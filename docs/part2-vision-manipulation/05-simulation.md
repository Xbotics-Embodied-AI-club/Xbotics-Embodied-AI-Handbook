## **3\.2 任务总览：本讲贯穿的两个任务**


### **建议结构**



1. 任务 A：机械臂 reach / pick\-place。

    - reach：末端到达目标点。

    - pick\-place：抓取物体并放到目标位置。

    - 观察点：末端误差、轨迹、接触、摩擦、抓取稳定性。

2. 任务 B：G1 standing / walking / turning。

    - standing：保持站立。

    - walking：按速度指令前进。

    - turning：按角速度指令转向。

    - disturbance recovery：受扰动后恢复。

    - 观察点：base 姿态、速度跟踪、步态、是否摔倒。

3. 两个任务的共同点：

    - 都需要机器人模型。

    - 都需要场景。

    - 都需要观测和动作。

    - 都需要成功判定。

    - 都会遇到 Sim2Real gap。

### **必写内容**



- 机械臂任务是操作线。

- G1 任务是运动线。

- 本讲不是训练完整策略，而是跑通、观察、记录和复盘。

## **3\.3 仿真任务拆解：从真实任务到可运行环境**


### **建议结构**



按照“七个问题”写：



1. 任务目标是什么？

    - 到达目标点、抓取物体、按速度行走、保持平衡。

2. 机器人模型是什么？

    - 关节、连杆、执行器、碰撞体、质量、惯量。

3. 场景和物体是什么？

    - 桌面、地面、目标物、障碍物、摩擦、质量。

4. 机器人能看到什么？

    - 关节状态、末端位姿、物体位置、相机、base 姿态、速度。

5. 机器人能输出什么动作？

    - 关节位置、关节速度、末端目标、策略 action、base velocity command。

6. 物理和控制参数是什么？

    - 接触、摩擦、控制频率、阻尼、延迟。

7. 成功和失败如何判断？

    - 末端误差、抓取成功、物体到位、速度跟踪、是否摔倒。

### **必写内容**



- 这七个问题是本讲主框架。

## **3\.4 平台选择：MuJoCo 与 Isaac Lab 分别解决什么问题**


### **建议结构**



1. 先说明平台选择原则。

    - 平台选择要服务任务，不要先入为主追求“更高级”的工具。

    - 入门阶段先看清任务结构，再看大规模训练和评测能力。

    - 本讲使用两个平台，是为了让学生看到两种不同层次的仿真问题。

2. 简介 MuJoCo。

    - 轻量，上手相对快。

    - 模型文件和物理参数更容易直接观察。

    - 适合机械臂、灵巧手、控制验证、小规模强化学习。

    - 本讲中承担“看懂机器人模型、关节、碰撞、摩擦和控制频率”的角色。

3. 简介 Isaac Lab。

    - 基于 Isaac Sim，环境更重。

    - 适合 GPU 并行仿真、传感器仿真、强化学习训练与评测。

    - 适合人形机器人、四足机器人、大规模 RL 和 Sim2Real 前验证。

    - 本讲中承担“看懂机器人学习环境、并行评测和 locomotion 任务接口”的角色。

4. 做 MuJoCo 与 Isaac Lab 对比。

    - 不写成谁更好。

    - 写成“什么时候优先用 MuJoCo，什么时候优先用 Isaac Lab”。

    - 对比要回到本讲两个任务：机械臂操作和 G1 locomotion。

### **必写内容**



- MuJoCo 适合帮助学生理解仿真任务的骨架：模型、关节、碰撞、物理参数、控制接口。

- Isaac Lab 适合帮助学生理解机器人学习环境：observation、action、reward、done、success metric、多环境并行。

- 平台选择服务任务，不是平台优劣排名。

- 本讲先用 MuJoCo 建立直觉，再用 Isaac Lab 扩展到机器人学习和人形机器人任务。

|运行成本|较低|更依赖 GPU 和 Isaac Sim|Isaac Lab 用于并行和复杂任务|
|模型理解|MJCF / XML 结构清楚|asset、articulation、scene 更工程化|MuJoCo 看模型骨架，Isaac Lab 看环境组织|

## **3\.5 仿真生态还有哪些平台**


### **建议结构**

1. 一句话过渡:机器人仿真赛道很拥挤,各家侧重点不同,了解全貌有助于以后按需选工具。

2. 按用途分类简介\(只给一句话定位 \+ 关键词标签,不展开安装教程\): 

    - **通用物理仿真/研究向**:PyBullet\(轻量、Python 友好、RL 常用\)、CoppeliaSim\(功能全、多接口\)、Drake\(控制理论与优化导向\)、Chrono\(多体动力学、颗粒/柔性体\)

    - **ROS 生态经典**:Gazebo/Ignition\(机器人学传统标配,ROS 集成度高\)

    - **教学/入门友好**:Webots\(界面友好,商业与开源双版本\)

    - **GPU 并行/下一代**:Genesis\(超高速并行仿真\+生成式能力\)、Newton\(NVIDIA 基于 Warp 的下一代可微分物理引擎\)、Brax 等 JAX 系\(大规模并行、可微分,RL 研究常用\)

    - **特定领域**:CARLA\(自动驾驶\)、AirSim\(无人机/自动驾驶\)、SAPIEN\(操作任务\)——呼应 3\.12 参考开源项目里已出现的 **ManiSkill、robosuite**,说明它们和机械臂操作任务的关系

    - **游戏引擎衍生**:Unity\+ML\-Agents、Unreal\+AirSim 插件\(视觉效果强,常用于感知/渲染仿真\)

3. 一句话选型逻辑收尾:"轻量学控制→MuJoCo/PyBullet;大规模并行训练→Isaac Lab/Genesis/Brax;真实感知仿真→Unreal/CARLA/AirSim;ROS 集成→Gazebo。"

4. 强调:平台多≠都要学,回到 3\.4 开头"任务驱动工具选择"的原则。

## **3\.6 MuJoCo 线：用机械臂任务看懂模型、控制和物理参数**



### **建议结构**



1. 为什么先用 MuJoCo。

    - 轻量。

    - 模型文件直观。

    - 适合看物理参数和控制效果。

2. 先看模型。

    - MJCF / XML。

    - body、joint、geom、site、actuator。

    - 说明每个字段在仿真任务中对应什么。

3. 再跑 reach。

    - 设置目标点。

    - 观察末端是否到达。

    - 记录末端误差和轨迹平滑性。

4. 再跑 pick\-place。

    - 加入物体。

    - 观察接触、抓取、放置。

    - 说明为什么 pick\-place 比 reach 更容易失败。

5. 最后改参数。

    - 改目标点。

    - 改物体质量。

    - 改摩擦系数。

    - 改控制频率。

    - 观察结果变化。

### **必写内容**



- MuJoCo 不只是“运行 viewer”，重点是看清任务结构。

- 参数修改要和失败现象绑定，而不是为了调参而调参。

- AI 辅助实操可融合在“读 MJCF”和“整理参数表”里，但学生必须验证。

## **3\.7 Isaac Lab 线：用机械臂任务看懂环境接口与并行评测**




### **建议结构**



1. 从 MuJoCo 过渡到 Isaac Lab。

    - MuJoCo 适合理解模型和物理。

    - Isaac Lab 适合理解训练、评测和并行环境。

2. 解释 Isaac Lab 任务组成。

    - scene。

    - asset。

    - articulation。

    - sensor。

    - environment。

3. 用机械臂 reach / pick\-place 对应五个接口。

    - observation：机器人和任务能看到什么。

    - action：控制器或策略输出什么。

    - reward：训练时鼓励什么。

    - done：任务何时结束。

    - success metric：评测时怎样算成功。

4. 解释多环境并行。

    - 同时跑多个初始状态。

    - 统计成功率。

    - 为强化学习做准备。

## **3\.8 G1 locomotion 线：用人形机器人任务理解运动仿真**



### **建议结构**



1. 先说明任务差异。

    - 机械臂：末端到哪里、物体是否抓住。

    - G1：身体是否稳定、速度是否跟上、是否摔倒。

2. 写 standing。

    - 目标是保持站立。

    - 观察 base 姿态、关节动作、是否抖动。

3. 写 walking。

    - 输入 base velocity command。

    - 观察实际速度、步态、脚底接触。

4. 写 turning。

    - 修改角速度指令。

    - 观察身体倾斜、转向稳定性。

5. 写 disturbance recovery。

    - 给扰动或观察失败案例。

    - 记录是否恢复、何时摔倒、哪里先失稳。

### **必写内容**



- base velocity command 是用户意图，不等于机器人一定能做到。

- locomotion 的成功判定要包含速度跟踪和平衡。

- 摔倒不是“Demo 失败”这么简单，要看是指令过大、接触问题、动作异常还是参数问题。

## **3\.9 Sim2Real 线：为什么仿真成功不等于真机成功**


### **建议结构**



1. 先给直观例子。

    - 仿真里能抓住，真机里物体滑掉。

    - 仿真里轨迹平滑，真机里有抖动或过冲。

    - 仿真里 G1 能走，真实地面上可能打滑或失衡。

2. 再分来源解释。

    - 接触模型差异。

    - 摩擦系数误差。

    - 质量、惯量、阻尼不准确。

    - 电机延迟和控制频率差异。

    - 传感器噪声和标定误差。

    - 光照、材质、相机参数差异。

3. 写有硬件对照实验。

    - SO101 真机 reach。

    - 仿真 reach。

    - 对比末端误差、轨迹、执行时间、停止位置。

### **必写内容**



- Sim2Real gap 要用任务现象解释，不要写成抽象名词。

- 真机安全注意事项只写必要内容：低速、小范围、有人看护、保留急停、不直接运行未经检查的 AI 生成真机代码。
