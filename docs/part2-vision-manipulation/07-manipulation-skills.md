## 7.2 核心知识点

1. **目标物体位姿 → 动作目标**：把空间输入变成预抓取 / 抓取 / 抬升 / 放置 / 退出位姿
2. **六维抓取候选**：与 GraspNet 兼容的 `G = {t, R, w, d, s}` 描述
3. **竖直抓取 vs 水平侧抓**：方块自上而下；瓶子侧向水平包夹
4. **生成阶段初筛**：夹爪宽度、桌面间隙、预抓取距离（不做完整规划）
5. **抓取—放置状态机**：进入条件、完成判据、超时与失败分支
6. **执行前校验**：可达性、逆运动学、路径碰撞
7. **分阶段成功检测**：抓取 / 抬升 / 放置，不能用“动作跑完”代替任务成功
8. **失败归因五类**：位姿 · 规划 · 控制 · 夹爪 · 放置检测
9. **分级恢复**：重感知 → 重生成 → 调参 → 换抓取点 → 安全退出
10. **任务日志与回流**：`events.jsonl` → 成功率 / 失败码 → 下一讲 episode 数据

## 7.4 方法框架

把本讲经验抽象为可复用的 **位姿驱动操作五步法**：

```text
目标物体位姿
  → 生成动作目标（预抓取/抓取/抬升/放置/退出）
  → 初筛 + 执行前校验
  → 状态机执行（接近→夹持→抬升→搬运→释放）
  → 分阶段检测 + 失败恢复 + 日志回流
```

**失败分析五类框架**（与课程统一口径）：视觉/位姿误差 · 动作/轨迹 · 时机（闭合过早过晚）· 目标位姿不合理 · 数据/日志覆盖不足。

## 7.4.1 框架展开：从目标位姿到操作技能


> **目标物体位姿回答“物体在哪里”，操作技能回答“机器人怎样安全、稳定地完成任务”。**

第 6 讲建立了从视觉观测到目标物体位姿的完整链路，使机器人能够确定物体在工作空间中的位置和朝向。第 7 讲进一步面向真实操作任务，讨论机械臂如何据此生成动作目标，完成抓取、搬运与放置，并在任务异常时定位原因、实施恢复。

从感知结果到任务完成，机器人还需要依次解决抓取位置选择、接近方向确定、动作位姿生成、运动执行、成功判定和失败处理等问题。这些环节共同构成位姿驱动操作的基本框架。

### 1.1 从“知道物体在哪里”到“完成操作任务”

目标物体位姿建立了物体与机器人之间的空间关系，是操作任务的起点。它能够说明物体位于何处、朝向如何，却不能直接给出机械臂末端的运动方式。真实抓取还需要确定夹爪从哪个方向接近、在何处闭合、抓起后沿什么路径搬运，以及在什么位置释放。

机械臂若直接向物体中心运动，可能出现末端路径穿过桌面、夹爪姿态与物体不匹配、接近速度过快或抓取点位于不稳定区域等问题。抓取完成后，系统还需要确认物体是否随夹爪抬升；放置完成后，则要判断物体是否进入目标区域并保持稳定。

因此，目标位姿必须经过动作目标生成和执行组织，转化为由预抓取、接近、夹持、抬升、搬运、释放和退出等阶段组成的操作流程。每个阶段均具有明确的进入条件、动作目标和完成判据；出现异常时，系统根据失败阶段重新感知、调整参数、重新生成动作目标或安全停止。

表 7-1 从感知结果到操作技能的能力转换

| **阶段**     | **需要回答的问题**               | **形成的结果**                     |
|--------------|----------------------------------|------------------------------------|
| 目标位姿     | 物体在哪里、朝向如何             | 操作任务的空间起点                 |
| 动作目标生成 | 夹爪从哪里接近、在哪里抓取和放置 | 预抓取、抓取、抬升、放置与退出位姿 |
| 状态机执行   | 各动作以何种顺序完成             | 可控的抓取—放置流程                |
| 结果检测     | 抓取和放置是否真正成功           | 抓取、抬升与放置状态               |
| 失败恢复     | 失败发生在哪里、下一步如何处理   | 重试、参数调整、安全退出与数据记录 |

位姿驱动操作的核心并不是把一个坐标直接发送给机械臂，而是把空间信息组织为可执行、可检测、可恢复的操作技能链。

### 1.2 贯穿场景：桌面物体抓取并放到指定区域

本讲以两个桌面操作任务贯穿动作目标生成、状态机执行、成功检测和失败恢复。两个任务共享相同的操作主线，但在物体几何特征、接近方式和放置约束方面具有不同要求。

本讲使用 SO-101 桌面机械臂作为硬件示例。机械臂基座固定在桌面一侧，二指夹爪作为末端执行器；目标物体与放置区域均位于同一工作台面。机器人基座坐标系用于统一描述物体位姿、夹爪位姿和运动目标。

**场景一：桌面方块从 A 区移动到 B 区**

桌面上放置一个规则方块，其初始位置位于 A 区，目标放置位置位于 B 区。机器人根据方块的空间位置和朝向，从上方建立预抓取位姿，沿竖直方向低速接近，闭合夹爪后将方块抬离桌面，随后移动至 B 区并释放。

该任务结构清晰、抓取方式稳定，适合建立位姿驱动抓取—放置的基础流程。主要观察内容包括抓取点是否接近方块中心、预抓取高度是否合理、接近过程中是否发生碰撞、方块是否随夹爪抬升，以及释放后是否稳定落入 B 区。

**场景二：竖直瓶子放入收纳盒**

桌面上放置一个竖直瓶子，目标区域为收纳盒内部。机器人需要根据瓶体的空间位置和轴向姿态确定夹持区域，采用侧向水平接近方式，完成抓取后将瓶子移动至收纳盒上方，再下降到适当高度释放。

瓶子具有较大的高度和明显的轴向特征。本讲采用侧向水平抓取：夹爪沿桌面水平方向接近瓶身，两指在瓶身中部形成对称接触。操作过程中需要重点处理接近高度、夹持位置和抬升稳定性。放置阶段还需考虑盒沿碰撞、释放高度和瓶体倾倒等问题。该任务用于检验基础操作流程面对姿态约束和容器放置时的适应能力。

表 7-2 两个贯穿任务的操作特点

| **对比项目** | **方块从 A 区移动到 B 区** | **瓶子放入收纳盒**                         |
|--------------|----------------------------|--------------------------------------------|
| 物体特征     | 形状规则，重心稳定         | 高度较大，轴向明显                         |
| 典型接近方式 | 自上而下                   | 侧向水平                                   |
| 夹爪姿态要求 | 相对固定                   | 沿水平方向接近，两指在瓶身中部形成对称接触 |
| 放置目标     | 平面区域                   | 容器内部                                   |
| 主要失败     | 抓偏、抓空、未进入 B 区    | 滑落、碰撞盒沿、释放后倾倒                 |
| 教学作用     | 建立最小抓取—放置闭环      | 展示姿态、夹持和容器放置约束               |

方块任务用于建立稳定、可复现的操作基线，瓶子任务则进一步引入抓取方向、夹持稳定性和容器放置约束。后续各节均以这两个任务为例，说明同一操作框架如何适应不同物体与任务条件。

## 7.4.2 从目标物体位姿生成动作目标

第 1 节明确了本讲的操作对象和任务主线。本节进一步回答一个直接影响执行结果的问题：目标物体的位姿已经确定后，机械臂应当以怎样的姿态接近物体，并在抓取、抬升、放置和退出阶段分别到达哪些位置。

动作目标生成不是把物体位姿原样发送给机械臂，而是把物体的空间状态、夹爪几何结构和任务要求结合起来，形成一组具有明确顺序的末端位姿。方块任务采用自上而下的竖直抓取；竖直瓶子任务采用从侧面接近的水平抓取。两种任务使用同一套生成逻辑，但抓取姿态、接近方向和放置约束不同。

| **本节方法主线：读取目标物体位姿 → 构造抓取候选 → 选定抓取方式 → 生成五个关键动作位姿 → 完成生成阶段初筛** |
|------------------------------------------------------------------------------------------------------------|

### 2.1 操作对象、机械臂与位姿输入

本讲使用 SO-101 桌面机械臂完成示例任务。机械臂基座固定在工作台一侧，二指夹爪安装在末端。由于基座与桌面的相对位置在实验中保持不变，桌面并不是机械臂的安装对象，而是操作空间中的固定工作平面。后续提到桌面高度，指的是桌面上表面在机器人基座坐标系中的高度，用于判断夹爪指尖、腕部和被抓物体是否可能与台面发生碰撞。

第 6 讲输出目标物体在机器人基座坐标系中的位姿。为在本节中描述该输入，先定义位置分量 x、y、z，分别表示物体参考点在机器人基座坐标系三个方向上的坐标；再定义四元数分量 q_x、q_y、q_z、q_w，用于表示物体的空间朝向。目标物体位姿记为 object_pose_base。

| object_pose_base = \[x, y, z, q_x, q_y, q_z, q_w\] |
|----------------------------------------------------|

这里的物体参考点由物体模型或位姿估计算法规定。对于规则方块，参考点通常位于几何中心；对于瓶子，参考点可以位于瓶身中心或模型坐标系原点。参考点并不等同于夹爪最终闭合的位置，二者之间还需要建立与物体几何形状相匹配的抓取关系。

### 2.2 用六维抓取候选描述夹爪与物体的关系

为了把物体位姿转化为夹爪目标，本讲采用与 GraspNet 六维抓取格式相兼容的描述方式。一个抓取候选首先由夹爪的位置和姿态确定，再补充夹爪宽度、进入深度以及候选评分等信息。这样的表示既可以用于规则生成，也可以直接接收抓取检测网络输出的候选。

在公式出现前，先定义本节使用的符号。用 t 表示夹爪坐标系原点在机器人基座坐标系中的三维位置；用 R 表示夹爪坐标系相对于机器人基座坐标系的三维旋转矩阵；用 w 表示夹爪两指之间的目标开口宽度；用 d 表示物体沿接近方向进入夹爪内部的深度；用 s 表示候选抓取的评分。若抓取候选来自场景中的多个物体，还可以附加物体编号。

| G = {t, R, w, d, s} |
|---------------------|

集合 G 表示一个任务化的抓取候选。其中，t 与 R 共同构成机械臂末端需要到达的六维位姿；w 用于设置夹爪张开程度；d 用于控制指尖与物体的相对包覆深度；s 用于在多个候选之间进行排序。GraspNet API 的完整数组还包含夹爪高度和物体编号，本讲在动作生成阶段重点使用与实际执行直接相关的位姿、宽度和深度信息。

![六维抓取候选中与任务执行直接相关的参数](../../assets/figures/lecture07/fig-07-2-6d-grasp-candidate.png)

图 7-2 六维抓取候选中与任务执行直接相关的参数

图中的 U 形框仅用于表达夹爪几何和抓取姿态。实际执行时，机械臂真实夹爪必须到达相同的位置和方向，并由两指与物体形成接触。可视化模型不能替代真实夹爪，也不能作为独立的执行对象。

### 2.3 根据任务确定抓取方式

抓取方式由物体几何特征、放置目标和周围空间共同决定。确定抓取方式时，需要同时回答三个问题：夹爪应夹住物体的哪个部位，夹爪两指应沿哪个方向分布，夹爪应从哪个方向接近物体。

#### 方块：自上而下的竖直抓取

方块的抓取参考点取在几何中心附近。夹爪位于方块正上方，接近方向竖直指向桌面，两指跨过方块相对的两个侧面。抓取位姿处，方块仍位于 A 区桌面上，夹爪下降并闭合；抬升位姿处，夹爪与方块共同位于 A 区正上方。该方式对物体朝向不敏感，适合作为基础实验。

#### 瓶子：从侧面接近的水平抓取

瓶子保持竖直放置，抓取参考点取在瓶身中部。夹爪沿桌面水平方向接近，两指在瓶身两侧形成对称接触。两指在空间中沿竖直方向展开，使夹爪能够包夹瓶身而不碰撞桌面。抓取位置过低会使指尖靠近桌面，过高则容易夹住瓶肩或瓶盖，因此需要依据瓶体直径和重心选择稳定夹持高度。

**表 7-4 两个贯穿任务的抓取方式**

| **任务**        | **抓取参考点**   | **夹爪姿态**                         | **接近方向** | **放置要求**                 |
|-----------------|------------------|--------------------------------------|--------------|------------------------------|
| 方块 A 区→B 区  | 方块几何中心附近 | 夹爪竖直向下，两指跨过方块两侧       | 自上而下     | 方块底面落在 B 区内          |
| 竖直瓶子→收纳盒 | 瓶身中部         | 夹爪水平包夹瓶身，两指沿竖直方向分布 | 水平侧向     | 瓶体通过盒口并在盒内稳定释放 |

### 2.4 生成五个关键动作位姿

抓取方式确定后，需要生成预抓取、抓取、抬升、放置和退出五个关键位姿。五个位姿描述的是机械臂末端在任务关键节点的目标状态，状态之间的连续轨迹由第 3 节的状态机与运动控制模块生成。

#### 预抓取位姿与抓取位姿

抓取位姿由选定抓取候选的位置 t 和姿态 R 确定，是夹爪闭合前应当到达的末端位姿。预抓取位姿位于抓取位姿的接近方向反侧，使机械臂先到达物体附近的安全位置，再沿较短的直线路径低速接近。

定义单位接近向量 a，用于表示夹爪从预抓取位置指向抓取位置的方向；定义预抓取距离 d_pre，用于表示两个位置之间的直线距离；定义抓取位置 p_g 和预抓取位置 p_pre。上述位置均在机器人基座坐标系中表达。

| p_pre = p_g − d_pre · a |
|-------------------------|

方块任务的接近向量竖直向下，预抓取位置位于方块正上方；瓶子任务的接近向量水平指向瓶身，预抓取位置位于瓶子侧面。预抓取与抓取阶段通常保持相同夹爪姿态，只改变位置，从而减少接近过程中的姿态变化。

#### 抬升位姿

抬升位姿用于使物体离开桌面并建立搬运安全间隙。定义抬升高度 h_lift，表示从抓取位置到抬升位置的竖直距离；定义 e_z 为机器人基座坐标系中竖直向上的单位向量；定义抬升位置 p_lift。

| p_lift = p_g + h_lift · e_z |
|-----------------------------|

抬升过程中保持夹爪闭合，并尽量维持抓取姿态不变。方块被抓取后应在 A 区正上方竖直抬起；瓶子采用水平夹持，但整体仍沿竖直方向抬升。抬升高度应使物体底部与桌面、容器边缘及其他障碍物之间保留足够间隙。

#### 放置位姿与退出位姿

放置位姿由目标区域确定。方块任务以 B 区中心附近作为水平位置参考，使方块底面接触桌面且整体位于 B 区内；瓶子任务以收纳盒开口内部的安全位置作为参考，使瓶体能够通过盒口并下降到释放高度。

放置位姿表示释放前的末端状态，因此夹爪仍应保持闭合并继续夹住物体。只有在末端到达放置位姿、物体获得桌面或容器支撑后，夹爪才打开。退出位姿位于放置区域上方或原接近路径的反方向，用于使张开的夹爪离开物体，并为后续成功检测留出无遮挡视野。

| **动作位姿** | **空间含义**                     | **夹爪状态**   | **任务中的关键要求**             |
|--------------|----------------------------------|----------------|----------------------------------|
| 预抓取位姿   | 位于抓取位置的接近方向反侧       | 张开           | 与物体保持安全距离，姿态已对准   |

### 2.5 生成阶段的候选初筛

动作位姿生成后，需要排除明显不适合进入运动规划的候选。这里的初筛只检查物体、夹爪和工作场景之间的几何关系，不求解机械臂关节角，也不判断完整轨迹是否可达。工作空间、逆运动学和路径碰撞由第 3 节执行前校验处理。

#### 夹爪尺寸与稳定接触

定义物体在夹持方向上的宽度 w_object，定义夹爪能够稳定夹持的最小宽度 w_min，定义夹爪最大开口宽度 w_max。三个量采用相同的长度单位。只有当物体宽度处于夹爪稳定夹持范围内时，当前抓取候选才具备执行条件。

| w_min ≤ w_object ≤ w_max |
|--------------------------|

除开口范围外，还应检查两指是否能够在物体两侧形成有效接触。方块应避免只夹到边角；瓶子应避开瓶盖、瓶肩斜面和过于柔软的标签区域。

#### 桌面与周围物体的几何间隙

机械臂虽然固定在桌面上，但夹爪、腕部和目标物体仍可能在接近或抬升过程中碰到桌面。因而需要已知桌面上表面在机器人基座坐标系中的高度，并检查夹爪最低点是否保留必要间隙。对于方块顶部抓取，重点检查指尖是否过度下探；对于瓶子水平抓取，重点检查下侧指尖和腕部是否接近台面。

#### 预抓取距离与放置空间

预抓取距离应足以容纳夹爪外形、定位误差和减速过程，同时不宜过大，以免低速接近路径过长。放置候选还需要检查目标区域是否能够容纳物体及夹爪：方块应完整落入 B 区；瓶子和夹爪应能通过收纳盒开口，且夹爪释放后具有可行的退出方向。

## 7.4.3 位姿驱动的抓取—放置状态机

第 2 节生成了预抓取、抓取、抬升、放置和退出等关键动作位姿。这些位姿只规定了机械臂在若干时刻应当到达的空间目标，还不能直接构成完整任务。机器人需要按照明确顺序调用这些目标，并在每一步结束后判断当前动作是否完成、下一状态是否允许进入，以及异常发生后应当重试还是停止。

状态机将连续的机器人操作划分为若干离散状态。每个状态只承担一项清晰职责，并包含输入条件、执行动作、完成条件和失败判断。由此，机械臂的抓取—放置过程不再是一段无法中断的动作序列，而成为可观察、可检查和可恢复的执行流程。

| **状态机的核心不是“按顺序播放动作”，而是“每完成一步都验证条件，再决定是否进入下一步”。** |
|------------------------------------------------------------------------------------------|

### 3.1 状态机整体流程

一次标准抓取—放置任务从接收目标物体位姿和放置目标开始。系统首先生成动作位姿，并完成可达性、逆运动学和路径碰撞校验；校验通过后，机械臂依次到达预抓取位姿、低速接近抓取位姿、闭合夹爪、验证抓取、抬升物体、搬运至放置区域、下降并释放物体。放置检测通过后，夹爪退出到安全位置，系统记录任务结果并结束本轮执行。

![位姿驱动的抓取—放置状态机](../../assets/figures/lecture07/fig-07-5-pick-place-state-machine.png)

图 7-5 位姿驱动抓取—放置状态机及失败诊断路径

图中的主流程表示正常执行路径。校验失败、夹持失败、抬升滑落或放置失败都会进入统一的失败处理状态。失败处理首先保存当前状态、传感器信息和动作记录，再根据失败类型选择重新感知、重新生成位姿、调整参数或更换抓取方式。达到最大重试次数、检测到碰撞风险或机器人状态异常时，系统不再继续尝试，而是打开夹爪、停止运动并回到安全位置。

从实现角度看，状态机可以划分为五个阶段模块：任务初始化、抓取执行、抓取验证、放置执行和结果记录。阶段模块用于组织较大的任务逻辑，模块内部再由若干原子状态完成具体动作。这样的分层结构既能避免状态数量过多造成连线混乱，也便于在程序中分别调试动作生成、执行控制、结果检测和异常恢复。

每次状态转移都应由明确事件触发。常见事件包括“末端到位”“夹爪闭合完成”“抓取检测通过”“抬升检测失败”“放置检测通过”和“执行超时”。状态机不应仅依靠固定等待时间推进，而应优先读取控制器反馈、夹爪状态和视觉检测结果；等待时间只作为传感器稳定和动作超时的辅助条件。

### 3.2 移动到预抓取位姿

预抓取位姿是机械臂进入物体附近之前的安全目标。该状态允许机械臂从当前姿态进行较大范围运动，但要求末端与物体、桌面和周围障碍物保持足够间隔。方块任务的预抓取位姿位于方块正上方；瓶子任务的预抓取位姿位于瓶身侧面，并与瓶体保持水平接近距离。

预抓取运动可以通过末端位姿控制、关节轨迹控制或运动规划实现。无论采用哪种接口，状态机只关心两个结果：目标能否安全到达，以及到达后的末端误差是否满足后续低速接近要求。到位后应重新读取机械臂末端的实际位姿，而不能仅依据控制指令已经发送来判断状态完成。

将末端位置误差记为 e_p，将允许的位置误差上限记为 ε_p；将末端姿态误差记为 e_R，将允许的姿态误差上限记为 ε_R。只有位置误差和姿态误差同时不超过各自上限时，预抓取状态才可以完成。

| e_p ≤ ε_p 且 e_R ≤ ε_R |
|------------------------|

其中，e_p 用于衡量实际末端位置与预抓取目标位置之间的距离；e_R 用于衡量实际末端朝向与目标朝向之间的差异。误差超过阈值时，系统可以继续等待控制器收敛、降低速度重新到位，或将该次执行记录为到位失败。

### 3.3 低速接近目标物体

机械臂到达预抓取位姿后，沿第 2 节确定的接近方向移动到抓取位姿。该段运动距离较短，但靠近物体和桌面，是整个抓取过程最容易发生接触冲击的阶段。因此，状态机应将低速接近设置为独立状态，并使用比大范围搬运更低的速度和加速度。

方块任务采用竖直向下接近，夹爪中心始终对准方块中心；瓶子任务采用水平方向接近，夹爪两指分别位于瓶身上下两侧，并在瓶身中部形成夹持。接近过程中可以使用短距离直线轨迹，也可以将总距离分成若干小步。小步执行便于在每一步后检查末端位置、机器人状态和物体是否发生移动。

接近状态的完成条件不是“运动时间结束”，而是末端实际到达抓取位姿，同时物体仍处于允许位置范围内。若视觉观察发现方块被推离 A 区中心、瓶子倾倒，或控制器报告碰撞和过载，状态机应立即停止接近并进入失败处理。

### 3.4 夹爪闭合与夹持控制

末端到达抓取位姿后，状态机进入夹爪闭合状态。夹爪在接近阶段应保持足够开口，使两指能够从物体两侧通过；到达抓取位姿后再闭合至目标宽度，并在短暂稳定时间内保持夹持。

目标开口应由物体在夹持方向上的尺寸和夹爪结构共同确定。方块竖直抓取时，两指从方块两侧夹紧；瓶子水平抓取时，两指在瓶身中部形成上下接触。夹爪闭合过早会在末端尚未对准时接触物体，容易将物体推开；闭合过晚则可能导致末端已经越过稳定抓取位置。

夹持力度或电机电流上限需要与物体材质匹配。刚性方块可以使用相对稳定的夹持参数；塑料瓶表面容易变形，夹持力过大可能压瘪瓶身，过小则会在抬升过程中滑落。对于无法直接设置夹持力的夹爪，可以通过闭合目标、速度限制和电流阈值间接控制。

| **夹爪指令发送完成并不等于抓取成功。闭合状态只负责形成夹持，抓取是否有效必须由下一状态单独检测。** |
|----------------------------------------------------------------------------------------------------|

### 3.5 抬升物体并进行抓取验证

夹爪闭合并保持稳定后，系统首先进行抓取检测。入门实验可以结合夹爪闭合宽度、驱动电流和视觉观测判断夹爪是否接触到物体。检测通过后，机械臂移动到抬升位姿，使物体脱离桌面。

抬升过程既是搬运准备，也是一次动态验证。机械臂应以受控速度沿竖直方向抬升，并在过程中持续观察物体。若物体保持在夹爪两指之间并随末端同步上升，则抓取验证通过；若物体仍留在桌面，说明夹爪抓空或未形成有效接触；若物体先被带起后又掉落，则记录为滑落失败。

方块任务中，抬升后的方块和夹爪应位于 A 区正上方；瓶子任务中，瓶身保持竖直，夹爪从侧面水平夹持瓶身中部。此时不应立即开始大范围搬运，而应保留短暂观察时间，确认物体姿态稳定、夹爪状态没有持续变化。

表 7-9 抬升阶段的抓取验证与状态转移

| **检测现象**                     | **状态判断**       | **后续动作**                   |
|----------------------------------|--------------------|--------------------------------|
| 夹爪闭合后完全合拢，物体仍在原处 | 抓空               | 返回重新感知或调整抓取点       |
| 物体随夹爪离开桌面，姿态稳定     | 抓取成功           | 进入搬运状态                   |
| 物体抬起后逐渐下滑               | 夹持不足           | 降低加速度或调整夹持参数后重试 |
| 抬升时物体旋转、倾斜明显         | 抓取点不稳定       | 更换抓取位置或姿态             |
| 机械臂出现过载或异常电流         | 存在碰撞或夹持风险 | 立即停止并安全退出             |

### 3.6 移动到放置区域、释放并退出

抓取验证通过后，机械臂将物体搬运到放置区域上方。搬运阶段应优先保持物体离开桌面和障碍物，并避免突然加速造成滑落。方块任务的目标是将方块移动到 B 区上方；瓶子任务则需要先将瓶子移动到收纳盒开口上方，并使瓶身与容器入口保持足够间隙。

机械臂到达放置区域上方后，沿安全方向下降到释放高度。方块放置时，方块底面与 B 区桌面接触，夹爪仍保持闭合；瓶子放置时，瓶底进入收纳盒并接触盒底或稳定支撑面，夹爪仍从侧面保持瓶身。确认物体已获得支撑后，夹爪再缓慢打开。

夹爪打开后应等待物体稳定。等待期间，系统检查物体是否滚动、倾倒、卡在夹爪中或被夹爪带离目标区域。随后，机械臂沿退出方向移动到退出位姿，为放置检测和下一次任务留出观察空间。

放置检测通过时，状态机记录任务成功；检测失败时，根据物体当前位置决定是否重新抓取、局部调整或终止任务。退出动作必须发生在释放完成之后，不能在夹爪仍夹持物体时直接离开放置区域。

### 3.7 执行前校验：可达性、逆运动学与路径碰撞

第 2 节的候选初筛主要排除抓取方向、夹爪宽度和几何位置明显不合理的方案。执行前校验则面向具体机械臂和当前环境，判断这些动作位姿能否被 SO-101 实际执行。该校验应在进入预抓取状态之前完成，并在目标物体重新定位或动作位姿发生变化后重新执行。

#### 可达性检查

可达性检查用于判断目标位置是否处于机械臂工作空间内。简单实现可以使用基座到目标位置的距离范围进行初步判断；更可靠的实现还需要考虑机械臂当前关节姿态、夹爪方向和关节限位。位置处于理论工作空间内，并不意味着指定姿态一定可达。

#### 逆运动学校验

逆运动学用于根据末端目标位姿求解机械臂各关节角度。每个关键动作位姿都需要至少一个满足关节限位的解。若抓取位姿有解而预抓取位姿无解，状态机仍不能开始执行，因为完整动作序列无法连贯完成。存在多个关节解时，应优先选择与当前关节状态接近、远离关节极限且便于后续动作衔接的解。

#### 路径碰撞检查

路径碰撞检查不仅检查目标位姿，还检查从当前状态到目标状态的整段轨迹。需要考虑夹爪和机械臂连杆是否碰到桌面、目标物体、收纳盒或机械臂自身。预抓取到抓取位姿通常采用短直线接近；搬运过程可以通过中间安全点抬高物体，再移动到放置区域，从而降低扫过桌面和容器边缘的风险。

表 7-10 执行前校验内容及失败处理

| **校验项目** | **检查对象**                       | **通过条件**                     | **失败后的处理**           |
|--------------|------------------------------------|----------------------------------|----------------------------|
| 可达性       | 预抓取、抓取、抬升、放置和退出位置 | 位于有效工作空间且不触及关节极限 | 调整位置偏移或更换抓取方向 |
| 逆运动学     | 每个关键末端位姿                   | 至少存在一个满足关节约束的解     | 重新生成姿态或增加中间位姿 |
| 路径碰撞     | 机械臂、夹爪、物体与环境           | 整段轨迹无桌面、容器和自碰撞     | 提高安全高度或重新规划路径 |
| 轨迹连续性   | 相邻状态的关节解与速度             | 关节变化连续且速度不突变         | 选择相邻关节解或降低速度   |

任何一项校验失败时，状态机都不应向机械臂发送运动指令，而应返回动作位姿生成阶段。系统可以调整预抓取距离、抓取姿态、抬升高度或搬运中间点后再次校验。只有完整序列通过检查，任务才进入预抓取状态。

### 3.8 状态机的软件实现方法

状态机的程序实现应将任务逻辑与底层设备接口分离。任务逻辑负责决定当前处于哪个状态、何时进入下一状态以及失败后采用何种恢复路径；设备接口负责发送机械臂和夹爪指令、读取末端位姿、获取夹爪状态并调用视觉检测。这样可以在不修改状态转移逻辑的情况下，将同一套任务迁移到真机或仿真环境。

#### 状态、上下文与执行结果

程序首先需要定义有限状态集合，例如接收任务、生成位姿、执行前校验、到达预抓取、低速接近、夹爪闭合、抓取检测、抬升验证、搬运、下降放置、释放、放置检测、退出记录、失败处理和安全退出。除当前状态外，还需要维护任务上下文。任务上下文用于保存目标物体位姿、五个动作位姿、当前重试次数、执行时间、最近一次失败原因以及传感器观测。

每个状态的执行函数返回统一结果。可将结果划分为运行中、成功、可恢复失败和不可恢复失败四类。运行中表示动作尚未完成，状态机保持当前状态；成功表示满足完成条件，可以转入下一状态；可恢复失败进入失败诊断并尝试重新感知或重新生成位姿；不可恢复失败直接进入安全退出。

表 7-11 状态执行函数的统一返回结果

| **返回结果**      | **含义**                                 | **状态机处理**                 |
|-------------------|------------------------------------------|--------------------------------|
| RUNNING           | 当前动作仍在执行，尚未满足结束条件       | 保持当前状态并继续读取反馈     |
| SUCCESS           | 当前状态完成条件已满足                   | 进入正常流程中的下一状态       |
| RETRYABLE_FAILURE | 失败原因可通过重新感知、调参或重规划处理 | 进入失败诊断，未超过上限时重试 |
| FATAL_FAILURE     | 出现急停、通信中断、持续过载或高风险碰撞 | 立即停止动作并进入安全退出     |

#### 周期执行与状态转移

状态机通常以固定控制周期运行。每个周期先读取机械臂、夹爪和视觉状态，再执行当前状态对应的检查与控制逻辑，最后根据返回结果决定是否转移。对于需要持续控制的状态，例如低速接近和抬升验证，执行函数应在多个周期内重复调用，而不是一次性发送全部动作后阻塞等待。

| result = execute_state(current_state, context) → current_state = transition(current_state, result, context) |

在实际程序中，主循环还应包含急停检查、通信状态检查和总任务超时。只要急停被触发、机械臂通信中断或检测到不可接受的碰撞风险，就应覆盖普通状态转移，直接进入安全退出。

#### 动作命令与完成条件解耦

每个状态可以分为进入、执行和退出三个阶段。进入阶段只执行一次，用于发送目标位姿、设置速度或记录开始时间；执行阶段在控制周期内反复读取反馈并判断完成条件；退出阶段用于停止当前控制器、保存状态结果并为下一状态准备数据。该结构可以避免在每个周期重复发送初始化命令，也便于实现超时和中断。

| 退出 on_exit   | 保存结果并清理当前状态资源       | 停止直线接近控制，记录实际轨迹 |

#### 超时、去抖与重试

机器人反馈可能出现短时波动，因此完成条件不宜只在单个周期满足一次就立即转移。可以要求误差、夹爪电流或视觉判据连续若干周期满足条件后再确认成功，这一过程称为去抖。去抖能够减少传感器噪声导致的错误状态转移。

每个状态还应设置独立超时。例如，预抓取运动长时间不到位、夹爪闭合超过允许时间或放置检测迟迟没有结果，都应被记录为对应状态的超时失败。重试时不能简单重复完全相同的动作，而应根据失败类型更新感知结果、调整抓取偏移、降低速度或更换抓取方向。

#### 真机与仿真的接口适配

在真机中，机械臂接口需要发送关节或末端目标，并读取编码器、末端估计、夹爪宽度、电流和控制器错误码；在仿真中，同样的状态机可以调用环境控制器并直接读取物体位姿、接触和碰撞信息。建议为两类环境定义一致的接口名称，例如 move_to_pose、move_linear、set_gripper、get_robot_state 和 detect_task_result。状态机只调用这些抽象接口，具体实现由真机适配器或仿真适配器提供。

## 7.4.4 抓取与放置成功检测

机械臂完成既定动作，只能说明控制指令已经执行，不能直接证明操作任务成功。抓取—放置任务必须依据夹爪反馈、物体运动和目标区域状态进行结果确认。检测过程应紧随状态机运行：夹爪闭合后判断是否形成有效夹持，抬升后判断物体是否随末端离开初始位置，释放后判断物体是否稳定进入目标区域。只有三类证据相互一致，任务状态才能被标记为成功。

成功检测采用“阶段判定”而非单一终点判定。这样既能避免把空抓、滑落或错误放置误记为成功，也能在失败发生后保留最早异常阶段，为第 5 节的原因定位和恢复决策提供依据。

### 4.1 抓取成功检测：确认夹爪形成有效夹持

抓取成功检测发生在夹爪闭合之后、机械臂大幅抬升之前。该阶段的目标是区分三种状态：夹爪未接触物体的空抓、夹爪接触但未形成稳定夹持，以及物体已被两指可靠约束。单一传感信号容易受到机构间隙、物体材质和控制误差影响，因此应优先采用两类以上证据联合判断。

夹爪闭合宽度是最容易获得的反馈。若夹爪在闭合后仍保留与物体尺寸相符的开口，说明两指之间可能存在物体；若夹爪接近机械极限位置，则更可能是空抓。然而，宽度只能说明夹爪之间存在阻挡，不能确认阻挡来自目标物体，也不能判断夹持是否稳定。

电机电流、关节力矩或末端力反馈能够反映夹爪闭合过程中的接触载荷。夹爪接触物体后，驱动负载通常出现上升并趋于稳定。对于不具备力传感器的入门平台，可读取夹爪电机电流或控制器返回的负载估计值。该信号应设置持续时间条件，避免把瞬时摩擦或机构卡滞误判为有效接触。

视觉检测用于确认目标物体仍位于夹爪附近，并判断其是否已经偏离原始位置。方块任务可检查红色方块是否位于夹爪两指之间；瓶子任务可检查瓶身中心是否与水平夹爪保持一致。入门实验可以采用“夹爪闭合宽度与抬升后视觉检测”组合：闭合宽度提供即时证据，后续抬升结果完成最终确认。

**表 7-13 抓取成功检测的主要证据**

| **检测证据**       | **可观测量**         | **能够说明的问题**                     | **局限与使用要求**                   |
|--------------------|----------------------|----------------------------------------|--------------------------------------|
| 夹爪闭合宽度       | 闭合后的两指间距     | 夹爪之间是否存在物体或阻挡             | 无法单独区分目标物体、碰撞与机构卡滞 |
| 电流、力矩或末端力 | 闭合阶段的负载变化   | 夹爪是否发生接触并形成夹持载荷         | 需要滤波、持续时间判断和空载基线     |
| 视觉位置关系       | 物体与夹爪的相对位置 | 目标物体是否位于两指之间               | 可能受遮挡、反光和视角影响           |
| 多源联合判断       | 宽度 + 负载 + 视觉   | 提高空抓、误碰和有效夹持之间的区分能力 | 各证据时间戳需与夹爪闭合状态对应     |

### 4.2 抬升检测：确认物体随夹爪离开初始支撑面

夹爪闭合后，状态机将机械臂移动到抬升位姿。抬升检测关注的不是末端是否到达指定高度，而是物体是否与夹爪同步运动并离开原有支撑面。该检测是确认抓取成功的关键环节，也用于识别夹持后立即滑落和搬运途中滑落。

检测开始前应保存物体在抓取前的初始位置，并记录抬升动作的开始时间。抬升过程中持续估计物体位置，比较其高度变化和水平位移。若机械臂末端已经上升，而物体仍停留在桌面或 A 区，则判定为抓取失败；若物体先随夹爪上升、随后重新落向桌面，则判定为滑落失败，并记录滑落发生的时间与机械臂状态。

对于方块任务，视觉系统应确认方块底面已与桌面分离，并在短时间内保持位于夹爪下方。对于瓶子任务，除高度变化外，还应检查瓶身与夹爪的相对姿态。瓶子被水平夹持后若出现明显下滑或旋转，即使尚未完全掉落，也应将其标记为夹持不稳定，并停止快速搬运。

抬升检测应设置稳定确认时间。物体在连续若干帧中满足离桌高度、相对位姿和运动一致性条件后，状态机才进入搬运阶段。这样能够降低视觉抖动和短暂遮挡造成的误判。

**表 7-14 抬升检测的状态判据**

| **观测现象**                       | **状态判定**   | **状态机处理**                         |
|------------------------------------|----------------|----------------------------------------|
| 末端上升，物体仍位于原位置         | 空抓或夹持失败 | 停止搬运，退出到安全位姿并进入失败处理 |
| 物体随夹爪上升并持续保持相对位置   | 抬升成功       | 进入搬运到放置区域状态                 |
| 物体先上升，随后高度下降或脱离夹爪 | 抬升滑落       | 立即停止水平搬运，记录滑落时刻与位置   |
| 物体持续倾斜、下滑但尚未掉落       | 夹持不稳定     | 降低速度，返回安全区域或重新抓取       |
| 视觉短时丢失但夹爪反馈稳定         | 检测不确定     | 保持低速或暂停，等待重新观测           |

### 4.3 放置成功检测：确认物体稳定进入目标区域

放置检测在夹爪打开、物体获得外部支撑并且机械臂退出后进行。机械臂退出能够减少夹爪遮挡，使视觉系统获得完整的目标区域图像。放置成功不仅要求物体出现在目标区域内，还要求物体已经脱离夹爪，并在规定时间内保持稳定。

方块任务的目标区域为桌面上的 B 区。检测时应判断方块在桌面上的投影是否落入 B 区边界，并为物体尺寸保留安全余量。若方块中心进入 B 区但部分区域明显越界，应根据任务要求判定为边界放置或失败，而不应简单采用中心点落区作为唯一标准。

瓶子任务的目标区域为收纳盒内部。检测内容包括瓶底是否进入盒内、瓶身是否被盒沿卡住、瓶子是否倾倒，以及夹爪退出后瓶子是否仍处于容器中。若任务要求瓶子保持竖直，还需要增加姿态判据；若任务只要求物体进入容器，则允许一定范围内的倾斜，但不能滚出或悬挂在盒沿。

放置检测应区分“释放完成”和“放置稳定”。夹爪打开仅表示释放命令已经执行，物体可能仍被夹爪带动、发生反弹或在斜面上继续滚动。系统应等待预设稳定时间，并比较多帧位置变化。物体位置变化小于允许范围后，才能将任务结果记录为成功。

| **任务**             | **区域条件**                  | **姿态与稳定性条件**                         | **典型失败**                   |
|----------------------|-------------------------------|----------------------------------------------|--------------------------------|
| 方块从 A 区放到 B 区 | 方块整体或规定比例位于 B 区内 | 方块落在桌面，连续多帧位置稳定               | 越界、弹出、仍被夹爪带走       |
| 瓶子放入收纳盒       | 瓶底和瓶身主体进入收纳盒内部  | 按任务要求保持竖直或允许范围内倾斜，停止滚动 | 碰撞盒沿、悬挂、倾倒、滚出容器 |

### 4.4 任务状态与操作日志记录

成功检测的每一次判断都应写入任务日志。日志既用于复现实验过程，也用于统计成功率、比较参数设置和建立后续训练数据。记录内容应覆盖任务输入、动作目标、执行反馈、检测证据和最终结果，避免只保存“成功”或“失败”两个标签。

任务级日志记录一次完整抓取—放置过程的编号、目标物体类别、起始区域、目标区域、开始时间、结束时间、重试次数和最终结果。状态级日志记录每个状态的进入时间、退出时间、控制目标、完成条件、超时信息和状态转移原因。高频轨迹数据则记录关节位置、关节速度、末端位姿、夹爪指令、夹爪宽度以及可用的电流或力反馈。

视觉数据应至少保存抓取前、夹爪闭合后、抬升确认、释放后和退出后的关键帧。发生失败时，还应保留失败前后的一段连续图像或视频，以便确定异常最早出现的时刻。所有数据使用统一任务编号和时间戳对齐，使状态机日志能够与图像、轨迹和控制命令相互对应。

**表 7-16 操作日志的推荐字段**

| **数据层级** | **主要记录内容**                                                  | **主要用途**               |
|--------------|-------------------------------------------------------------------|----------------------------|
| 任务级       | 任务编号、物体类别、起点与目标、开始/结束时间、重试次数、最终结果 | 统计整体成功率和任务耗时   |
| 位姿级       | 目标物体、预抓取、抓取、抬升、放置和退出位姿                      | 复现动作目标并分析空间误差 |
| 状态级       | 状态名称、进入/退出时间、完成条件、失败代码、转移原因             | 定位失败最早出现的状态     |
| 控制级       | 关节轨迹、末端轨迹、速度、夹爪命令、宽度、电流或力反馈            | 分析控制误差和夹持过程     |
| 视觉级       | 关键帧、深度图、检测框、物体位姿和任务视频                        | 验证抓取、滑落与放置结果   |

## 7.4.5 失败分析与恢复机制

失败处理的核心不是重复执行同一条动作，而是依据失败发生的阶段识别可能原因，再选择具有针对性的恢复策略。状态机已经记录每个状态的输入、完成条件和失败代码，因此可以沿任务时间顺序寻找最早出现异常的环节。后续状态中的异常往往是前一阶段问题的结果，若只根据最终现象处理，容易产生错误归因。

例如，物体在抬升时滑落，可能来自抓取点偏离重心、夹爪宽度设置不当或闭合时机过晚；放置后物体位于目标区外，也可能源于搬运过程中的夹持滑移，而不一定是放置位姿本身错误。因此，失败分析应结合状态日志、轨迹、夹爪反馈和视觉记录共同完成。

### 5.1 典型失败场景与成因

抓取—放置任务的失败可以分为感知与位姿、运动规划、接近控制、夹持、抬升搬运和放置检测六类。分类的目的不是给每次失败贴上唯一标签，而是缩小排查范围，并明确需要检查的数据。

**表 7-17 典型失败场景、直接表现与常见成因**

| **失败类别**     | **直接表现**                         | **常见成因**                               | **优先检查数据**                         |
|------------------|--------------------------------------|--------------------------------------------|------------------------------------------|
| 目标位姿偏差     | 夹爪整体抓偏或未对准物体             | 检测误差、坐标变换误差、目标移动           | 目标物体位姿、相机图像、坐标变换结果     |
| 抓取姿态错误     | 夹爪方向与物体不匹配                 | 抓取候选选择错误、物体主方向估计错误       | 抓取旋转、接近向量、夹爪开口方向         |
| 规划与可达性失败 | 逆运动学无解、轨迹无法生成或发生碰撞 | 目标超出工作空间、关节限位、障碍物约束     | 逆运动学结果、规划器错误码、碰撞对       |
| 接近阶段碰撞     | 夹爪提前碰到桌面或推开物体           | 预抓取距离不足、接近方向或速度不合理       | 接近轨迹、末端速度、碰撞或视觉记录       |
| 夹持失败         | 抓空、单指接触或物体被推开           | 闭合过早/过晚、开口设置错误、抓取点不稳定  | 夹爪宽度、电流、闭合时刻、关键帧         |
| 抬升滑落         | 物体离桌后下滑或掉落                 | 夹持力不足、抓取点偏离重心、加速度过大     | 夹爪反馈、物体相对位姿、末端加速度       |
| 放置失败         | 物体越界、倾倒、卡在盒沿或未释放     | 放置位姿偏差、释放高度错误、退出方向不合理 | 放置前后图像、夹爪打开状态、目标区域检测 |

### 5.2 依据状态时间线定位失败来源

失败定位应从最早异常状态开始，而不是从任务终止位置反向猜测。系统首先读取状态机日志，确定最后一个成功状态和第一个失败状态；随后调取该时间段的位姿、轨迹、夹爪反馈和图像数据，检查该状态的输入是否有效、动作是否按预期执行以及完成条件为何未满足。

预抓取前失败主要涉及目标物体位姿、抓取候选和执行前校验。若目标位姿在机械臂工作空间之外，或者逆运动学无解，应回到动作目标生成阶段，而不是继续调整接近速度。接近过程中失败则重点检查预抓取位姿、接近方向、速度和障碍物距离。

夹爪闭合后的失败需要区分空抓、推开和夹持不足。空抓通常表现为夹爪接近完全闭合且视觉中物体仍在原位；推开物体表现为闭合前后物体发生水平位移；夹持不足则可能在闭合时获得接触反馈，但抬升过程中出现持续下滑。

释放后的失败应先确认物体在搬运过程中是否发生滑移。若放置前物体相对于夹爪的位置已经改变，则应回溯到夹持或搬运阶段；若物体在放置前保持稳定，但释放后越界、倾倒或卡住，则重点检查放置位姿、释放高度和退出轨迹。

**表 7-18 按失败阶段组织的排查顺序**

| **第一个失败状态** | **优先排查对象**                               | **不应首先调整的项目** |
|--------------------|------------------------------------------------|------------------------|
| 执行前校验         | 目标物体位姿、抓取姿态、可达性、逆运动学和碰撞 | 夹爪闭合力度           |
| 移动到预抓取       | 目标位姿、轨迹规划、关节限位和控制超时         | 放置检测阈值           |
| 低速接近           | 预抓取距离、接近方向、速度和桌面/物体碰撞      | 抬升高度               |
| 夹爪闭合或抓取检测 | 抓取点、夹爪开口、闭合时机、接触反馈           | 放置位置               |
| 抬升验证           | 夹持稳定性、抓取点与重心关系、抬升速度         | 目标区域边界           |
| 放置或放置检测     | 放置位姿、释放高度、夹爪打开、物体稳定性       | 预抓取距离             |

### 5.3 恢复策略：重感知、重生成、参数调整与更换抓取点

恢复策略应改变导致失败的关键条件。若目标物体在碰撞或推挤后发生位移，首先重新采集图像并更新目标物体位姿；若感知结果稳定但抓取方向不合理，则重新生成抓取候选，改变接近方向、抓取偏移或夹爪姿态。

接近阶段发生碰撞时，可增加预抓取距离或提高预抓取安全高度，并降低接近速度。规划失败时，可重新选择机械臂姿态、增加搬运中间点或重新调用规划器。夹持失败时，应根据物体尺寸修正夹爪初始开口与闭合终点，调整闭合时机，并在必要时更换抓取点。

恢复动作应遵守安全顺序。系统先停止当前运动，保持或释放夹爪取决于物体状态；随后将机械臂移动到不会扩大碰撞风险的安全位姿，再执行重感知和动作目标更新。不得在目标物体位置已经变化后，直接沿原轨迹快速重试。

**表 7-19 失败原因与恢复策略的对应关系**

| **失败原因**           | **首选恢复策略**                 | **必要时采用的进一步调整**     |
|------------------------|----------------------------------|--------------------------------|
| 目标物体位姿失效       | 重新感知并更新目标位姿           | 检查坐标变换与相机遮挡         |
| 抓取姿态或抓取点不合理 | 重新生成抓取候选                 | 改变接近方向或更换抓取点       |
| 预抓取或接近碰撞       | 增加安全距离并降低接近速度       | 提高预抓取位姿或改变接近路径   |
| 逆运动学无解或规划失败 | 选择新的候选位姿并重新规划       | 增加中间点或改变机械臂初始姿态 |
| 夹持不足或抬升滑落     | 调整夹爪开口、闭合终点和抓取位置 | 降低抬升加速度，选择更稳定表面 |
| 放置越界或倾倒         | 修正放置位姿和释放高度           | 降低下降速度，调整退出方向     |

### 5.4 重试、降级与安全退出

重试机制必须设置上限，并记录每次重试相对于上一次发生了哪些改变。若系统在相同输入和参数下重复执行同一动作，通常只会重复同一类失败。重试次数、累计任务时间、碰撞风险和控制器状态共同决定任务是否继续。

第一次失败可采用低成本恢复：重新感知目标并按原抓取方式重新生成动作目标，用于排除偶发检测误差和短时控制波动。第二次失败应调整抓取偏移、预抓取距离、接近速度或夹爪参数。第三次失败应改变抓取方向或采用更保守的抓取方式。例如，方块任务可以回到中心顶部抓取；瓶子水平抓取连续失败时，可根据任务条件选择更稳定的瓶身位置，或者终止自动任务并请求人工处理。

出现不可恢复条件时，系统应立即安全退出，而不等待达到最大重试次数。不可恢复条件包括急停触发、通信中断、驱动器故障、持续碰撞、物体进入不可见或不可达区域，以及机械臂或夹爪状态无法可靠确认。安全退出时应停止运动，按照当前夹持状态选择保持或释放物体，将机械臂移动到允许的安全位姿，并保存完整日志。

**表 7-20 分级重试与退出策略**

| **处理级别** | **触发条件**                       | **系统动作**                               |
|--------------|------------------------------------|--------------------------------------------|
| 原策略重试   | 首次可恢复失败，环境和设备状态正常 | 重新感知，重新生成同类动作目标并再次校验   |
| 参数调整重试 | 同类失败再次出现                   | 调整抓取偏移、预抓取距离、速度或夹爪参数   |
| 策略降级     | 常规抓取连续失败，但仍存在安全候选 | 采用更保守的抓取方向、轨迹和速度           |
| 安全退出     | 达到最大重试次数或出现不可恢复风险 | 停止任务、回到安全位姿、保存日志并输出报警 |

### 5.5 失败样本记录与数据回流

失败样本应按照“任务输入—动作目标—执行过程—失败判定—恢复结果”的结构保存。基础数据包括彩色图像、深度图、目标物体位姿、抓取位姿、机械臂关节状态、末端轨迹、夹爪命令和反馈。对于滑落、碰撞和放置失败，还应保存失败前后的视频片段。

每个失败样本至少包含失败阶段、直接现象、推定原因、恢复动作和恢复结果五类标注。直接现象描述可以从传感器和图像中观察到的事实，例如“夹爪闭合后宽度接近零”“物体在抬升 0.6 秒后下落”；推定原因则表示经过分析得到的解释，例如“抓取点偏离重心”或“夹持力不足”。二者必须分开记录，避免将未经验证的推断当作原始事实。

数据回流首先服务于工程调试。统计不同失败类型的频率，可以发现影响成功率的主要环节；对比参数修改前后的结果，可以判断恢复策略是否有效。随着数据积累，成功和失败轨迹还可以整理为 episode 数据，用于模仿学习、策略训练、异常检测和抓取候选排序。进入学习阶段前，应检查时间同步、标签一致性和数据完整性，避免将错误日志直接用于模型训练。

**表 7-21 失败样本的数据结构与用途**

| **数据类别** | **建议内容**                                            | **用途**                       |
|--------------|---------------------------------------------------------|--------------------------------|
| 环境与感知   | 彩色图像、深度图、目标检测、目标物体位姿、场景版本      | 重现失败环境并检查感知误差     |
| 动作目标     | 预抓取、抓取、抬升、放置和退出位姿，规划结果            | 分析动作生成与规划问题         |
| 执行反馈     | 关节轨迹、末端轨迹、夹爪宽度、电流/力反馈、控制器错误码 | 定位控制、夹持和设备异常       |
| 失败标注     | 失败阶段、直接现象、推定原因、严重程度                  | 建立可检索的失败类型库         |
| 恢复记录     | 恢复策略、参数变化、重试次数和最终结果                  | 评估恢复策略并支持后续策略学习 |

经过成功检测、失败定位和恢复处理，抓取—放置任务形成了可验证、可追踪的执行闭环。第 6 节将在方块搬运和瓶子入盒两个任务中，将位姿生成、状态机执行、结果检测、失败恢复和日志记录整合为完整实验。

### 6.3 统一数据结构与任务参数

代码首先定义统一的数据结构。Pose 表示机器人基座坐标系中的末端或物体位姿；ActionTargets 保存一次任务需要执行的六个关键位姿；TaskConfig 保存任务参数；Observation 统一表示真机或仿真返回的末端、夹爪和物体状态。

TaskConfig 中的 approach_direction 表示从预抓取位姿指向抓取位姿的接近方向；grasp_offset 表示机械臂末端参考点相对于物体参考点的偏移；pre_grasp_distance 表示预抓取与抓取位姿之间的距离。gripper_open_width 和 gripper_close_width 分别表示接近前的张开宽度与抓取后的目标宽度。所有长度在本项目中统一使用米，速度参数为归一化课程参数，接入具体控制器时需要转换为平台实际单位。

```python
from dataclasses import dataclass
from typing import Any

@dataclass(frozen=True)
class Pose:
    """Position and quaternion in the robot base frame."""

    x: float
    y: float
    z: float
    qx: float = 0.0
    qy: float = 0.0
    qz: float = 0.0
    qw: float = 1.0

    def shifted(self, dx: float, dy: float, dz: float) -> "Pose":
        return Pose(
            self.x + dx,
            self.y + dy,
            self.z + dz,
            self.qx,
            self.qy,
            self.qz,
            self.qw,
        )

    def distance_to(self, other: "Pose") -> float:
        return sqrt(
            (self.x - other.x) ** 2
            + (self.y - other.y) ** 2
            + (self.z - other.z) ** 2
        )

    def to_dict(self) -> dict[str, float]:
        return asdict(self)


@dataclass(frozen=True)
class ActionTargets:
    pre_grasp: Pose
    grasp: Pose
    lift: Pose
    pre_place: Pose
    place: Pose
    retreat: Pose


@dataclass
class TaskConfig:
    name: str
    object_pose: Pose
    place_pose: Pose
    grasp_quaternion: tuple[float, float, float, float]

    pre_grasp_distance: float
    lift_height: float
    place_clearance: float
    retreat_height: float
    gripper_open_width: float
    gripper_close_width: float
    object_width: float
    fast_speed: float = 0.35
    slow_speed: float = 0.08
    position_tolerance: float = 0.01
    lift_threshold: float = 0.05
    place_xy_tolerance: float = 0.04
```

### 6.4 动作位姿生成代码

动作位姿生成函数先将接近方向归一化，再根据目标物体位姿、抓取偏移和抓取姿态得到抓取位姿。预抓取位姿沿接近方向反向偏移；抬升位姿在抓取位姿基础上提高；放置准备位姿和退出位姿位于目标区域上方。

代码将 place_pose 解释为物体期望到达的位置，因此生成机械臂放置位姿时仍需保留抓取偏移。这样，方块中心最终落在 B 区目标点，瓶身中心最终落在收纳盒内部，而不是把末端参考点误当成物体中心。

**代码清单 7-4 pose_generator.py：生成六个关键动作位姿**

```python
from __future__ import annotations

from math import sqrt

from .models import ActionTargets, Pose, TaskConfig


def _normalize(vector: tuple[float, float, float]) -> tuple[float, float, float]:
    length = sqrt(sum(value * value for value in vector))
    if length < 1e-9:
        raise ValueError("approach_direction must be non-zero")
    return tuple(value / length for value in vector)


def generate_targets(task: TaskConfig) -> ActionTargets:
    """Generate the six key poses from the object and place poses."""

    ax, ay, az = _normalize(task.approach_direction)
    ox, oy, oz = task.grasp_offset
    qx, qy, qz, qw = task.grasp_quaternion

    grasp = Pose(
        task.object_pose.x + ox,
        task.object_pose.y + oy,
        task.object_pose.z + oz,
        qx,
        qy,
        qz,
        qw,
    )
    pre_grasp = grasp.shifted(
        -ax * task.pre_grasp_distance,
        -ay * task.pre_grasp_distance,
        -az * task.pre_grasp_distance,
    )
    lift = grasp.shifted(0.0, 0.0, task.lift_height)

    place = Pose(
        task.place_pose.x + ox,
        task.place_pose.y + oy,
        task.place_pose.z + oz,
        qx,
        qy,
        qz,
        qw,
    )
    pre_place = place.shifted(0.0, 0.0, task.place_clearance)
    retreat = place.shifted(0.0, 0.0, task.retreat_height)

    return ActionTargets(
        pre_grasp=pre_grasp,
        grasp=grasp,
        lift=lift,
        pre_place=pre_place,
        place=place,
        retreat=retreat,
    )
```

### 6.5 统一后端与教学模拟实现

RobotBackend 定义状态机需要的最小能力：建立连接、重置任务、读取观测、移动末端、控制夹爪和停止运动。真机与仿真只要实现这些方法，便可以复用同一套状态机。

MockBackend 是可运行的教学模拟后端。它直接更新末端位姿，并在夹爪到达物体附近且执行闭合时建立“物体附着”关系；夹爪打开时释放物体。该后端不模拟真实动力学，其用途是检查状态机顺序、数据流、检测逻辑和日志格式。

```python
        raise NotImplementedError

    def set_gripper(

# backends/mock.py
from __future__ import annotations

from dataclasses import replace
from time import monotonic

from ..models import MotionResult, Observation, Pose, TaskConfig
from .base import RobotBackend


class MockBackend(RobotBackend):
    """A deterministic teaching backend with no external dependencies."""

    def __init__(self) -> None:
        self.connected = False
        self.task: TaskConfig | None = None
        self.eef_pose = Pose(0.20, 0.0, 0.30)
        self.object_pose = Pose(0.0, 0.0, 0.0)
        self.gripper_width = 0.08
        self.object_attached = False
        self.object_from_eef = (0.0, 0.0, 0.0)
        self.collision = False

    def connect(self) -> None:
        self.connected = True

    def disconnect(self) -> None:
        self.connected = False

    def reset_task(self, task: TaskConfig) -> None:
        self.task = task
        self.eef_pose = Pose(0.20, 0.0, 0.30)
        self.object_pose = task.object_pose
        self.gripper_width = task.gripper_open_width
        self.object_attached = False
        self.collision = False

    def get_observation(self) -> Observation:
        return Observation(
            timestamp=monotonic(),
            eef_pose=self.eef_pose,
            gripper_width=self.gripper_width,
            object_pose=self.object_pose,
            object_visible=True,
            object_attached=self.object_attached,
            collision=self.collision,
        )

    def move_pose(
        self,
        target: Pose,
        speed: float,
        timeout: float = 8.0,
    ) -> MotionResult:
        if not self.connected:
            return MotionResult(False, "backend is not connected")
        if speed <= 0.0 or timeout <= 0.0:
            return MotionResult(False, "speed and timeout must be positive")
        if self.collision:
            return MotionResult(False, "collision flag is active")

        self.eef_pose = target
        if self.object_attached:
            dx, dy, dz = self.object_from_eef
            self.object_pose = target.shifted(dx, dy, dz)
        return MotionResult(True)

    def set_gripper(
        self,
        width: float,
        force: float = 0.5,
        timeout: float = 3.0,
    ) -> MotionResult:
        if self.task is None:
            return MotionResult(False, "task has not been reset")
        if width < 0.0 or timeout <= 0.0:
            return MotionResult(False, "invalid gripper command")

        self.gripper_width = width
        closing = width <= self.task.gripper_close_width + 0.01
        opening = width >= self.task.gripper_open_width - 0.01

        if closing and not self.object_attached:
            if self.eef_pose.distance_to(self.object_pose) <= 0.11:
                self.object_attached = True
                self.object_from_eef = (
                    self.object_pose.x - self.eef_pose.x,
                    self.object_pose.y - self.eef_pose.y,
                    self.object_pose.z - self.eef_pose.z,
                )
        elif opening and self.object_attached:
            self.object_attached = False
            self.object_pose = replace(
                self.object_pose,
                z=self.task.place_pose.z,
            )

        return MotionResult(True)

    def stop(self) -> None:
        self.collision = False
```

### 6.6 成功检测与恢复参数调整

检测函数只读取统一 Observation，不依赖具体运行平台。抓取检测结合夹爪宽度、物体与末端距离以及仿真附着状态；抬升检测比较物体相对于初始位置的高度变化；放置检测确认物体已经脱离夹爪，并位于目标位置允许范围内。

恢复函数根据失败代码修改下一次任务参数。运动或碰撞失败时增加预抓取距离并降低接近速度；抓取或抬升失败时微调抓取偏移、夹爪闭合宽度和接近速度；放置失败时增加放置准备高度和退出高度。此处调整量是教学示例，真机实验应依据日志和安全范围逐步确定。

**代码清单 7-6 checker.py 与 recovery.py：成功检测和重试参数调整**

```python
# checker.py
from math import hypot

from .models import Observation, Pose, TaskConfig


def grasp_success(obs: Observation, task: TaskConfig) -> bool:
    if not obs.object_visible or obs.object_pose is None:
        return False
    width_is_plausible = (
        task.gripper_close_width - 0.015
        <= obs.gripper_width
        <= task.object_width + 0.03
    )
    object_is_near = obs.eef_pose.distance_to(obs.object_pose) <= 0.12
    return obs.object_attached or (width_is_plausible and object_is_near)


def lift_success(
    obs: Observation,
    initial_object_pose: Pose,
    task: TaskConfig,
) -> bool:
    if obs.object_pose is None:
        return False
    height_gain = obs.object_pose.z - initial_object_pose.z
    object_is_near = obs.eef_pose.distance_to(obs.object_pose) <= 0.14
    return height_gain >= task.lift_threshold and object_is_near


def place_success(obs: Observation, task: TaskConfig) -> bool:
    if obs.object_pose is None or obs.object_attached:
        return False
    xy_error = hypot(
        obs.object_pose.x - task.place_pose.x,
        obs.object_pose.y - task.place_pose.y,
    )
    return xy_error <= task.place_xy_tolerance


# recovery.py
from dataclasses import replace

from .models import FailureCode, TaskConfig


def adjust_task(
    task: TaskConfig,
    failure: FailureCode,
    retry_index: int,
) -> TaskConfig:
    """Return a modified task configuration for the next attempt."""

    if retry_index <= 0:
        return task

    if failure in {FailureCode.MOTION_FAILED, FailureCode.COLLISION}:
        return replace(
            task,
            pre_grasp_distance=task.pre_grasp_distance + 0.02,
            slow_speed=max(0.03, task.slow_speed * 0.8),
        )

    if failure in {FailureCode.GRASP_FAILED, FailureCode.LIFT_FAILED}:
        gx, gy, gz = task.grasp_offset
        return replace(
            task,
            grasp_offset=(gx, gy, gz + 0.005),
            gripper_close_width=max(0.0, task.gripper_close_width - 0.003),
            slow_speed=max(0.03, task.slow_speed * 0.85),
        )

    if failure is FailureCode.PLACE_FAILED:
        return replace(
            task,
            place_clearance=task.place_clearance + 0.02,
            retreat_height=task.retreat_height + 0.02,
        )

    return task
```

### 6.7 抓取—放置状态机的完整实现

状态机每进入一个状态，先写入状态日志，再调用后端执行动作或读取检测结果。任何一步失败都会生成 FailureCode 和原因文本，随后进入恢复或安全退出。一次尝试成功后，状态机写入 DONE；若达到最大重试次数仍未成功，则进入 SAFE_EXIT。

run_attempt() 负责执行一次完整尝试，run() 负责管理重试次数和参数更新。两层结构将“单次任务逻辑”和“跨尝试恢复逻辑”分离，便于单独测试和修改。

**代码清单 7-7 state_machine.py：完整状态机、失败分支与重试循环**

```python
from __future__ import annotations

from dataclasses import dataclass

from .backends.base import RobotBackend
from .checker import grasp_success, lift_success, place_success
from .models import FailureCode, State, TaskConfig
from .pose_generator import generate_targets
from .recovery import adjust_task
from .task_logger import TaskLogger


@dataclass(frozen=True)
class AttemptResult:
    success: bool
    failure: FailureCode
    reason: str


class PickPlaceStateMachine:
    def __init__(
        self,
        backend: RobotBackend,
        task: TaskConfig,
        logger: TaskLogger,
    ) -> None:
        self.backend = backend
        self.task = task
        self.logger = logger
        self.state = State.INIT

    def _enter(self, state: State, **extra: object) -> None:
        self.state = state
        self.logger.log(
            state,
            "enter",
            self.backend.get_observation(),
            **extra,
        )

    def _fail(self, code: FailureCode, reason: str) -> AttemptResult:
        self.logger.log(
            self.state,
            "failure",
            self.backend.get_observation(),
            code=code.name,
            reason=reason,
        )
        return AttemptResult(False, code, reason)

    def run_attempt(self) -> AttemptResult:
        targets = generate_targets(self.task)
        initial_object_pose = self.task.object_pose

        self._enter(State.INIT)
        result = self.backend.set_gripper(self.task.gripper_open_width)
        if not result.success:
            return self._fail(FailureCode.MOTION_FAILED, result.reason)

        self._enter(State.MOVE_PRE_GRASP)
        result = self.backend.move_pose(
            targets.pre_grasp,
            self.task.fast_speed,
        )
        if not result.success:
            return self._fail(FailureCode.MOTION_FAILED, result.reason)

        self._enter(State.APPROACH)
        result = self.backend.move_pose(targets.grasp, self.task.slow_speed)
        if not result.success:
            code = FailureCode.COLLISION if "collision" in result.reason else (
                FailureCode.MOTION_FAILED
            )
            return self._fail(code, result.reason)

        self._enter(State.CLOSE_GRIPPER)
        result = self.backend.set_gripper(self.task.gripper_close_width)
        if not result.success:
            return self._fail(FailureCode.GRASP_FAILED, result.reason)

        self._enter(State.VERIFY_GRASP)
        if not grasp_success(self.backend.get_observation(), self.task):
            return self._fail(FailureCode.GRASP_FAILED, "grasp check failed")

        self._enter(State.LIFT)
        result = self.backend.move_pose(targets.lift, self.task.slow_speed)
        if not result.success:
            return self._fail(FailureCode.LIFT_FAILED, result.reason)

        self._enter(State.VERIFY_LIFT)
        if not lift_success(
            self.backend.get_observation(),
            initial_object_pose,
            self.task,
        ):
            return self._fail(FailureCode.LIFT_FAILED, "lift check failed")

        self._enter(State.MOVE_PRE_PLACE)
        result = self.backend.move_pose(targets.pre_place, self.task.fast_speed)
        if not result.success:
            return self._fail(FailureCode.MOTION_FAILED, result.reason)

        self._enter(State.LOWER_PLACE)
        result = self.backend.move_pose(targets.place, self.task.slow_speed)
        if not result.success:
            return self._fail(FailureCode.PLACE_FAILED, result.reason)

        self._enter(State.OPEN_GRIPPER)
        result = self.backend.set_gripper(self.task.gripper_open_width)
        if not result.success:
            return self._fail(FailureCode.PLACE_FAILED, result.reason)

        self._enter(State.VERIFY_PLACE)
        if not place_success(self.backend.get_observation(), self.task):
            return self._fail(FailureCode.PLACE_FAILED, "place check failed")

        self._enter(State.RETREAT)
        result = self.backend.move_pose(targets.retreat, self.task.slow_speed)
        if not result.success:
            return self._fail(FailureCode.MOTION_FAILED, result.reason)

        self._enter(State.DONE)
        self.logger.log(
            State.DONE,
            "success",
            self.backend.get_observation(),
        )
        return AttemptResult(True, FailureCode.NONE, "")

    def run(self) -> bool:
        current_task = self.task
        for retry_index in range(current_task.max_retries + 1):
            self.task = current_task
            self.backend.reset_task(current_task)
            self.logger.log(
                State.INIT,
                "attempt_start",
                self.backend.get_observation(),
                retry_index=retry_index,
            )
            result = self.run_attempt()
            if result.success:
                return True

            self.backend.stop()
            if retry_index >= current_task.max_retries:
                self._enter(State.SAFE_EXIT, reason=result.reason)
                return False

            self._enter(State.RECOVER, failure=result.failure.name)
            current_task = adjust_task(
                current_task,
                result.failure,
                retry_index + 1,
            )
        return False
```

```python
from __future__ import annotations

import json
from dataclasses import asdict
from pathlib import Path
from time import time
from typing import Any

from .models import Observation, State


class TaskLogger:
    def __init__(self, output_dir: str | Path, task_name: str) -> None:
        stamp = time_ns_text()
        self.task_dir = Path(output_dir) / f"{stamp}_{task_name}"
        self.task_dir.mkdir(parents=True, exist_ok=False)
        self.events_path = self.task_dir / "events.jsonl"

    def log(
        self,
        state: State,
        event: str,
        observation: Observation | None = None,
        **extra: Any,
    ) -> None:
        record: dict[str, Any] = {
            "time": time(),
            "state": state.name,
            "event": event,
            **extra,
        }
        if observation is not None:
            record["observation"] = asdict(observation)
        with self.events_path.open("a", encoding="utf-8") as file:
            file.write(json.dumps(record, ensure_ascii=False) + "\n")


def time_ns_text() -> str:
    return str(int(time() * 1_000_000))
```

## 7.5 有硬件版 Demo

### SO-101 真机：从统一位姿到关节动作

SO-101 真机适配器接收一个已经配置和标定的机器人对象。该对象负责硬件连接、读取电机与相机观测以及发送关节目标。适配器另外注入三个与课程系统相关的函数：plan_pose() 将末端目标位姿转换为一系列关节动作；read_eef_pose() 根据关节状态计算实际末端位姿；detect_object() 从相机观测中获得目标物体位姿。

LeRobot 的机器人接口采用 connect()、get_observation() 和 send_action() 组织硬件读写。适配器将这些底层方法转换为状态机所需的 move_pose()、set_gripper() 和 get_observation()。运动规划可以由 MoveIt 2、课程提供的逆运动学与插值模块，或其他经过验证的规划器完成。

**代码清单 7-11 so101_adapter.py：SO-101 真机后端核心实现**

```python
from __future__ import annotations

from collections.abc import Callable, Mapping
from time import monotonic, sleep
from typing import Any

from ..models import MotionResult, Observation, Pose, TaskConfig
from .base import RobotBackend


class SO101Backend(RobotBackend):
    """Adapter around a connected LeRobot-style SO-101 robot object.

    The injected robot object must provide connect(), disconnect(),
    get_observation(), and send_action(). Pose planning and forward
    kinematics are injected because their implementation depends on the
    selected URDF, calibration, and motion-planning stack.
    """

    def __init__(
        self,
        robot: Any,
        plan_pose: Callable[[Pose, float], list[dict[str, float]]],
        read_eef_pose: Callable[[Mapping[str, Any]], Pose],
        detect_object: Callable[[Mapping[str, Any]], Pose | None],
        gripper_key: str = "gripper.pos",
    ) -> None:
        self.robot = robot
        self.plan_pose = plan_pose
        self.read_eef_pose = read_eef_pose
        self.detect_object = detect_object
        self.gripper_key = gripper_key
        self.task: TaskConfig | None = None

    def connect(self) -> None:
        self.robot.connect()

    def disconnect(self) -> None:
        self.robot.disconnect()

    def reset_task(self, task: TaskConfig) -> None:
        self.task = task

    def get_observation(self) -> Observation:
        raw = self.robot.get_observation()
        object_pose = self.detect_object(raw)
        return Observation(
            timestamp=monotonic(),
            eef_pose=self.read_eef_pose(raw),
            gripper_width=float(raw.get(self.gripper_key, 0.0)),
            object_pose=object_pose,
            object_visible=object_pose is not None,
            object_attached=False,
            collision=bool(raw.get("collision", False)),
            raw=dict(raw),
        )

    def move_pose(
        self,
        target: Pose,
        speed: float,
        timeout: float = 8.0,
    ) -> MotionResult:
        deadline = monotonic() + timeout
        try:
            joint_actions = self.plan_pose(target, speed)
        except Exception as exc:
            return MotionResult(False, f"planning failed: {exc}")

        for action in joint_actions:
            if monotonic() > deadline:
                self.stop()
                return MotionResult(False, "motion timeout")
            self.robot.send_action(action)
            sleep(0.02)
        return MotionResult(True)

    def set_gripper(
        self,
        width: float,
        force: float = 0.5,
        timeout: float = 3.0,
    ) -> MotionResult:
        del force, timeout
        try:
            self.robot.send_action({self.gripper_key: width})
        except Exception as exc:
            return MotionResult(False, f"gripper command failed: {exc}")
        return MotionResult(True)

    def stop(self) -> None:
        current = self.robot.get_observation()
        hold = {
            key: value
            for key, value in current.items()
            if key.endswith(".pos")
        }
        if hold:
            self.robot.send_action(hold)
```

## 7.7 实验步骤

### 完整实验清单

**1.** 检查任务区域。确认 SO-101 基座固定、桌面和收纳盒位置稳定，A 区与 B 区边界清晰；无硬件学生打开课程云平台的预装项目。

**2.** 运行教学模拟。依次执行 cube 和 bottle 任务，确认状态机能够到达 DONE，并检查 runs/ 下是否生成两个任务目录。

**3.** 检查动作目标。打印预抓取、抓取、抬升、放置准备、放置和退出位姿，并在可视化工具中确认方向和高度关系。

**4.** 运行方块无夹持试验。真机只执行预抓取、抬升和 B 区上方的空载位姿，确认逆运动学、轨迹和桌面间隙。

**5.** 启用方块抓取。将方块放入 A 区，低速运行完整状态机，观察夹爪是否在方块正上方接近、是否在 A 区上方抬升、是否在 B 区释放。

**6.** 执行方块参数对比。至少比较两种接近速度或两种预抓取距离，每组运行不少于 5 次，记录成功率、耗时和失败阶段。

**7.** 运行瓶子无夹持试验。检查水平接近方向、夹爪开口、瓶身夹持高度和收纳盒上方的放置准备位姿。

**8.** 启用瓶子抓取。夹爪从侧面水平接近瓶身中部，抬升时保持瓶体竖直，并在进入收纳盒前降低下降速度。

**9.** 触发并记录一次可恢复失败。可在仿真中改变接近偏移或夹爪宽度，观察状态机记录失败代码、修改参数并重新尝试。真机不得通过故意制造碰撞完成该步骤。

**10.** 执行放置检测。方块任务检查物体是否稳定位于 B 区；瓶子任务检查瓶体是否进入盒内、是否被盒沿卡住以及退出后是否滚出。

**11.** 生成实验汇总。运行日志分析脚本，输出 summary.csv，并将成功率、平均耗时、重试次数和失败类型整理为表格。

**12.** 完成失败复盘。选择一次失败样本，指出最早异常状态、直接证据、推定原因、恢复动作和下一轮验证方法。

**代码清单 7-13 analyze_runs.py：汇总任务日志**

```python
from __future__ import annotations

import csv
import json
from pathlib import Path


def summarize_task(task_dir: Path) -> dict[str, object]:
    events_path = task_dir / "events.jsonl"
    records = [
        json.loads(line)
        for line in events_path.read_text(encoding="utf-8").splitlines()
        if line.strip()
    ]
    success = any(record.get("event") == "success" for record in records)
    failures = [record for record in records if record.get("event") == "failure"]
    states = [record["state"] for record in records if record.get("event") == "enter"]
    return {
        "task_dir": task_dir.name,
        "success": success,
        "failure_count": len(failures),
        "last_failure": failures[-1].get("code", "") if failures else "",
        "state_count": len(states),
    }


def main() -> None:
    root = Path("runs")
    summaries = [summarize_task(path) for path in sorted(root.iterdir()) if path.is_dir()]
    output = root / "summary.csv"
    if not summaries:
        raise SystemExit("no task directories found under runs/")
    with output.open("w", newline="", encoding="utf-8-sig") as file:
        writer = csv.DictWriter(file, fieldnames=list(summaries[0]))
        writer.writeheader()
        writer.writerows(summaries)
    print(output)


if __name__ == "__main__":
    main()
```

## 本讲小结与通向下一讲

本讲以 SO-101 桌面机械臂的方块搬运和瓶子入盒任务为主线，建立了从目标物体位姿到动作执行结果的完整工程链路。目标物体位姿提供操作所需的空间依据，动作目标生成模块将其转化为机械臂末端需要依次到达的关键位姿，状态机组织各阶段的执行顺序，成功检测与失败恢复则使任务结果能够被验证、异常能够被定位。由此，机器人操作由单次运动指令扩展为可执行、可检测、可恢复、可记录的闭环系统。

### 7.1 位姿驱动操作主线回顾

第 6 讲输出目标物体在机器人基座坐标系中的位置与朝向。该结果描述了物体所处的空间状态，但并不直接等同于机械臂控制指令。机械臂还需要结合物体几何形状、夹爪结构、抓取方向和放置目标，确定末端执行器在任务各阶段的空间状态。

本讲将目标物体位姿依次转化为预抓取、抓取、抬升、放置准备、放置和退出位姿。预抓取位姿用于建立安全接近起点；抓取位姿规定夹爪闭合时的位置与方向；抬升位姿用于使物体脱离桌面并验证夹持稳定性；放置准备位姿为下降与释放预留安全空间；放置位姿确定物体最终到达的位置；退出位姿使夹爪在释放后离开目标区域。

两个贯穿任务采用了不同的抓取方式。方块任务使用自上而下的竖直抓取，夹爪从 A 区上方接近方块，并将其搬运至 B 区；瓶子任务保持瓶体竖直，夹爪从侧面水平接近瓶身中部，再将瓶子放入收纳盒。两个任务共享相同的操作框架，但在夹爪姿态、接近方向、夹持位置和放置约束上具有不同要求。

动作位姿只有按照确定顺序执行，才能构成完整任务。状态机将任务拆分为目标接收、动作生成、执行前校验、预抓取、低速接近、夹爪闭合、抓取检测、抬升验证、搬运、下降、释放、放置检测、退出和结果记录等状态。每个状态均具有明确的输入、执行动作、完成条件、超时条件和失败分支，从而避免后续动作在前一阶段尚未完成或已经异常时继续执行。

**表 7-32 位姿驱动操作的六个工程层级**

| **层级** | **需要回答的问题**                                 | **本讲形成的工程结果**               |
|----------|----------------------------------------------------|--------------------------------------|
| 空间输入 | 目标物体位于何处、朝向如何                         | 机器人基座坐标系下的目标物体位姿     |
| 动作目标 | 夹爪应从何处接近、在哪里闭合、如何抬升和放置       | 六个关键动作位姿及夹爪参数           |
| 执行组织 | 动作应按什么顺序执行、何时进入下一状态             | 带完成条件、超时和失败分支的状态机   |
| 结果确认 | 机械臂执行结束后，物体是否真正被抓起并放到目标区域 | 抓取、抬升和放置的分阶段检测         |
| 异常处理 | 失败最早发生在哪一阶段、下一次尝试需要修改什么     | 失败代码、参数调整、重试与安全退出   |
| 过程证据 | 任务过程能否被复现、比较和进一步利用               | 时间同步的状态、观测、动作与结果日志 |

| **核心认识** 目标物体位姿只回答“物体在哪里”。完整操作技能还必须回答“夹爪怎样接近”“动作按何种顺序执行”“任务是否真正成功”以及“失败后如何处理”。 |

### 7.2 抓取—放置—检测—恢复闭环梳理

抓取—放置任务的可靠性来自执行过程中的连续判断，而不是来自某一条运动指令。机械臂到达预抓取位姿后，需要确认末端误差处于允许范围；低速接近阶段需要监测运动是否完成以及是否出现碰撞或超时；夹爪闭合后，需要结合夹爪宽度、电流或力反馈判断是否形成接触；抬升后，需要通过物体位置变化确认物体已经离开桌面；释放后，还需要确认物体位于目标区域且未被夹爪带走。

单一检测信号通常不足以直接证明任务成功。夹爪未完全闭合可能表示夹住了物体，也可能由机构阻力或控制误差造成；视觉观察到物体离开原位置，可能表示抓取成功，也可能是接近阶段将物体推开。因此，课程中的基础实现采用夹爪状态与抬升后视觉结果联合判断，并将抓取、抬升和放置分别设置为独立检测阶段。

失败分析以最早出现异常的状态为起点。预抓取前失败主要检查目标物体位姿、动作目标和规划结果；接近阶段失败主要检查接近方向、速度和碰撞；夹爪闭合后失败主要检查开口宽度、闭合时机和抓取点；抬升或搬运阶段失败主要检查夹持稳定性；释放后失败则需要检查放置位姿、释放高度和目标区域检测。这样的阶段化定位能够把“任务没有完成”转化为可以验证的工程问题。

**图 7-12 从目标位姿到真实操作闭环的主线总结**

恢复策略应与失败原因相对应。目标位置发生变化时重新感知；候选抓取方向不合适时重新生成动作目标；接近路径过于激进时增加预抓取距离或降低速度；夹持不稳定时调整抓取点、夹爪宽度或夹持力度；规划失败时重新求解逆运动学、增加中间路径点或更换候选位姿。可恢复失败在限定次数内重新尝试，不可恢复失败、达到最大重试次数或触发安全条件时进入安全退出。

任务日志将闭环中的空间目标、状态转移、控制指令、检测结果、失败代码、重试次数和任务耗时保存下来。日志不仅用于计算成功率，还能够将动作结果与执行过程对应起来，使学生能够判断失败从何时开始、哪一项证据支持当前结论，以及下一轮实验需要修改哪个参数。

### 7.3 通向下一讲：从规则操作到任务回合数据

本讲完成的是规则驱动的位姿操作系统。动作位姿由明确的几何关系与任务参数生成，状态转移由人工设定的条件控制，失败恢复由预先定义的规则触发。该系统具有过程透明、便于调试和安全边界清晰等特点，也为后续学习方法提供了可比较的基线。

在机器人学习中，从任务开始到成功或失败终止的一次完整过程称为一个任务回合，英文为 episode。一个任务回合通常包含按时间顺序记录的环境观测、机器人动作、状态变化和最终结果。环境观测包括相机图像、目标物体位姿、关节位置、末端位姿和夹爪状态；机器人动作包括关节指令、末端目标和夹爪命令；最终结果包括成功标志、失败阶段、失败原因和终止方式。

本讲已经记录的状态机日志构成任务回合数据的基础，但面向学习算法时还需要进一步统一采样频率、时间戳、字段名称和数据类型，并保证图像、机器人状态与动作指令严格对齐。成功样本用于描述任务如何完成，失败样本则提供偏离正常过程的反例。两类数据都应保留，不能只记录最终成功的视频。

模仿学习是从人工示范或成功任务轨迹中学习动作策略的方法；端到端策略是将传感器观测直接映射为机器人动作的模型；视觉—语言—动作模型的英文名称为 Vision-Language-Action，简称 VLA，它将视觉观测、语言任务描述与机器人动作统一建模。无论采用哪一种方法，训练数据都需要明确任务起点、观测、动作、终止条件和结果标签。规则状态机可以提供安全的数据采集流程，也可以作为学习策略的对照方法和异常兜底机制。

|------------------------------|--------------------------------------------|--------------------------------------|
| 相机图像与目标物体位姿       | observation：视觉与任务环境观测            | 描述每个时刻机器人看到的环境状态     |
| 关节状态、末端位姿与夹爪状态 | robot_state：机器人本体状态                | 描述执行动作前后的机器人状态         |

| 状态机名称与状态转移时间     | phase 与 timestamp：任务阶段和时间戳       | 对齐观测、动作和任务阶段             |
| 抓取、抬升和放置检测结果     | success_signal：阶段成功信号               | 区分动作完成与物理任务完成           |
| 失败代码、原因与重试次数     | failure_label 与 retry：失败标签和恢复信息 | 支持失败归因、样本筛选和恢复策略学习 |
| 任务成功或安全退出           | terminal 与 outcome：终止标志和结果        | 确定一个任务回合的结束位置与最终标签 |

| **下节衔接** 下一讲将把真机或仿真中的成功与失败过程整理为标准任务回合，完成图像、机器人状态、动作和结果的时间同步与结构化存储，并为模仿学习、端到端策略和视觉—语言—动作模型实验准备数据。 |
