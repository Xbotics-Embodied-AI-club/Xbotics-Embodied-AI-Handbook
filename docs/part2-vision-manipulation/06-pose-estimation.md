# 第6讲 机器人感知与位姿估计：从像素到抓取位姿的完整链路

## 1 从"看得到"到"抓得到"：位姿估计在机器人操作中的定位

机器人操作任务中的视觉输出，不能直接等同于控制输入。目标检测给出的是图像区域，实例分割给出的是前景像素，点云恢复给出的是相机坐标系下的几何观测；而机械臂最终需要的是基座坐标系下、满足夹爪结构与运动学约束的抓取目标。位姿估计的功能，正是在这些不同表征之间建立可计算、可验证、可执行的转换关系。

可以先从一个最普通的桌面抓取场景说起：相机看到桌面上有一个杯子，检测器给出了一个框，分割模型也把杯身轮廓描了出来。到这一步，人很容易觉得“机器人已经看见杯子了”。但对机械臂来说，问题才刚刚开始：杯子离相机多远？杯口朝上还是倾斜？夹爪应该抓杯身、杯口，还是杯柄附近？这些问题都不在检测框里，也不在二维 mask 里。位姿估计正是在这里进入链路，把“图像里有一个目标”继续推进为“空间中有一个可操作的刚体对象”。

换句话说，本讲关心的不是单个视觉模型能否在图像上画出漂亮结果，而是机器人如何把一次观测转化为动作决策。这个过程可以分成三类表征：图像域的观测表征、三维空间中的物体状态表征，以及机器人控制器可消费的动作表征。位姿估计位于中间层，既承接前端视觉，又约束后端抓取。

图 6.1 可以看作本讲的主线：左侧是机器人获得的 RGB-D 观测，右侧是机械臂真实执行的抓取动作，中间则依次经过检测、分割、点云、位姿、抓取映射和坐标转换。每一步都在回答一个更具体的问题：先问“目标在哪个图像区域”，再问“这个区域对应哪些三维点”，再问“这些点组成的物体在空间里如何摆放”，最后才问“夹爪应该以什么姿态去接触它”。

### 1.1 背景与动机：为什么机器人不能只靠检测抓取

#### 1.1.1 检测框的本质：二维投影，信息严重缺失

目标检测与实例分割解决的是图像域中的语义归属问题；抓取控制解决的是三维空间中的接触与约束问题。二者的关键差异不是“精度高低”，而是**输出空间不同**：检测框属于二维投影表征，抓取位姿属于刚体位姿与动作表征。

这也是初学者最容易形成的误解：把“检测到了”误认为“可以抓了”。检测框只告诉我们物体在画面里的大致范围，它没有深度、没有旋转，也不知道夹爪从哪一侧接近更安全。对人来说，这些信息可以凭常识补全；对机器人来说，它们必须被显式计算出来。

| 表示层级 | 典型输出 | 表征空间 | 可支撑的下游任务 | 仍缺失的信息 |
|---|---|---|---|---|
| 检测框 bbox | $(x_{min},y_{min},x_{max},y_{max})$ | 图像平面 | 目标粗定位、ROI 裁剪 | 深度、姿态、接触区域 |
| 实例掩膜 mask | 目标前景像素集合 | 图像平面 | 前景分离、深度筛选 | 三维位置、物体朝向 |
| 三维中心 | $(x,y,z)$ | 相机 / 基座坐标系 | 粗定位、顶部接近 | 旋转姿态、夹爪对齐方式 |
| 物体位姿 object pose | $\,{}^{C}T_{O}$ 或 $\,{}^{B}T_{O}$ | $SE(3)$ | 描述所定义物体坐标系的位置与朝向 | 抓取点、开合宽度、避碰偏置 |
| 抓取位姿 grasp pose | $\,{}^{B}T_{G}$ | 机器人操作空间 | 给出夹爪 TCP 在抓取时刻的目标刚体变换 | 仍需开口宽度、接近/撤离、IK、碰撞与力控校验 |

若系统仅输出 bbox，抓取点可能落在背景、桌面或物体边缘；若仅输出 mask，目标虽然已与背景分离，但尚未进入米制三维空间；若仅输出三维中心，机械臂可以到达目标附近，却无法确定夹爪应如何旋转。即使获得 object pose，也仍需结合物体几何、夹爪结构和任务约束，进一步生成 grasp candidate。因此，位姿估计必须放在“感知表征逐步转化为操作表征”的链路中理解。

#### 1.1.2 从 2D 到 3D：维度跃迁带来的根本性挑战

从信息闭合的角度看，抓取任务至少要求系统回答四类问题：目标是否存在，目标在三维空间中的位置，目标相对于夹爪的朝向，以及夹爪能否沿某条无碰撞路径完成接触。检测框只回答第一类和一小部分第二类问题；mask 进一步改善前景分离，但仍停留在图像域；object pose 才开始描述物体的刚体状态；grasp candidate 则把物体状态与末端执行器结构、接触参数和任务约束联系起来。也就是说，位姿估计不是为了“多输出几个自由度”，而是为了补齐从视觉判断到物理执行之间缺失的空间约束。

从控制系统视角看，这一步也是变量空间的切换：像素坐标 $(u,v)$ 没有物理单位，深度点 $(X,Y,Z)$ 进入相机坐标系但缺少刚体朝向，6D 位姿 $T \in SE(3)$ 才同时包含位置和旋转。机器人抓取所需的不是“图像上哪里亮”，而是“某个刚体相对于机器人在哪里、如何摆放、能否被当前夹爪稳定接触”。这正是 2D 感知和 3D 操作之间最本质的差距。

#### 1.1.3 位姿估计何时是关键中间环节

对于位姿驱动抓取，一条最基本的变换链可写为：

$$
{}^{B}T_{G} = {}^{B}T_{C} \, {}^{C}T_{O} \, {}^{O}T_{G}
$$

其中，$\,{}^{C}T_{O}$ 表示物体坐标系相对于相机坐标系的 6D 位姿，$\,{}^{O}T_{G}$ 表示在物体坐标系中定义的抓取模板，$\,{}^{B}T_{C}$ 来自手眼标定，$\,{}^{B}T_{G}$ 则是提交给运动规划器的基座系抓取目标。由此可见，6D 位姿并不是链路终点，而是连接视觉几何与抓取动作的中间状态。

一个实用判断是：如果任务只要求“指向一个区域”，bbox 或 3D 中心可能已经足够；如果任务要求“沿某个方向接近、避开桌面、夹住局部结构”，位姿、抓取模板和坐标转换通常会成为更可靠的中间约束。但显式 object pose 并不是所有抓取系统的必经环节：直接 6-DoF 抓取检测、场景点云到抓取候选生成、端到端视觉运动策略，都可能绕过物体坐标系位姿，直接预测 grasp pose、抓取候选或动作。

**本节小结：** 检测框和实例掩膜让机器人“看见”目标，但它们仍然停留在图像投影层面，无法直接回答目标的深度、朝向、接触位置和执行坐标系问题。对于基于已知物体模型或抓取模板的位姿驱动抓取，6D object pose 是常用且可验证的中间表示；对于直接抓取检测或端到端策略，系统也可以直接预测 grasp pose、抓取候选或动作。理解这一点之后，6D 位姿就不再是“多预测几个自由度”的必然环节，而是一种在可解释性、几何约束和工程调试上很有价值的中间表征。

### 1.2 机器人感知的三层目标：识别、定位与定姿

机器人操作中的视觉感知可归纳为三个递进目标：**识别（Recognition）—定位（Localization）—定姿（Pose Estimation）**。三者分别回答“是什么”“在哪里”“朝向如何”，共同构成从语义理解到几何恢复再到刚体状态估计的基本链条。

这三个问题可以按机器人逐步接近动作执行的顺序理解。识别阶段确定目标身份：场景里哪个是杯子，哪个是盒子。定位阶段开始测量空间位置：目标在相机前方多少米、相对机器人基座处于什么位置。定姿阶段则进入操作细节：杯子是否倾斜、盒子的长边朝向哪里、夹爪开合方向是否应与物体长轴对齐。只有走完这三步，视觉结果才逐渐接近控制系统能够使用的形式。

#### 1.2.1 第一层：识别（Recognition）——解决"是什么"的问题

识别层负责确定任务目标和语义类别，是整条链路的入口。它通常输出类别、检测框或初始 mask，帮助系统从复杂场景中选出需要继续处理的对象。

在机器人抓取中，识别并不只是给图像打标签，而是决定后续几何计算应该围绕哪个目标展开。桌面上可能同时存在杯子、盒子、工具和杂物，如果系统没有先确认任务对象，后续的点云提取和位姿估计就可能处理到错误物体。对于“拿起红色杯子”这类任务，识别层还要结合类别、颜色、位置或语言指令，在多个候选目标之间完成选择。

识别结果通常不直接进入控制器，而是作为空间裁剪和语义过滤的依据。检测框可以限制分割模型的搜索范围，类别信息可以决定是否调用某个 CAD 模型或抓取模板，置信度则可以作为是否继续执行的门槛。若识别阶段漏检，整条链路无法启动；若误检，把背景或相邻物体当成目标，后续几何算法即使计算得很精确，也只是在精确地处理错误对象。

#### 1.2.2 第二层：定位（Localization）——解决"大致在哪里"的问题

定位层把二维候选区域与深度观测结合起来，恢复目标在三维空间中的位置。它不一定要求完整旋转姿态，但至少要给出可用于接近的空间坐标或目标点云。

这一层完成的是从图像平面到物理空间的关键过渡。检测框和 mask 只说明目标投影在哪些像素上，定位层需要利用深度图、相机内参和前景掩膜，把这些像素反投影成相机坐标系下的三维点。此时系统开始获得米制尺度的信息，例如物体中心离相机多远、位于桌面左侧还是右侧、是否在机械臂可达范围内。

定位结果可以有不同粒度。最简单的是一个 3D 中心点，适合顶部抓取、点击、靠近观察等对姿态要求较低的动作；更完整的是目标点云，它保留了物体局部形状和表面分布，可作为后续 6D 位姿估计、主轴提取或抓取候选生成的输入。定位误差通常会表现为抓空、偏抓或接近路径偏离目标，因此真机调试时要重点检查深度尺度、相机内参、mask 是否混入背景点，以及手眼标定是否带来系统偏移。

#### 1.2.3 第三层：定姿（Pose Estimation）——解决"朝哪个方向"的问题

定姿层进一步恢复物体坐标系的朝向，使夹爪能够根据物体长轴、局部平面、孔洞或把手等几何结构调整自身姿态。对侧向抓取、插拔、装配等任务而言，这一层往往决定操作能否稳定完成。

与定位只关心“到哪里”不同，定姿关心的是物体坐标系相对于相机或机器人坐标系如何旋转。对于规则盒子，夹爪可能需要与长边对齐；对于杯子，杯柄方向会影响可抓区域；对于插拔和装配任务，几度的姿态偏差就可能导致顶撞或无法插入。因此，6D 位姿中的旋转部分并不是附加信息，而是把视觉几何转化为可执行接触动作的核心约束。

定姿方法通常会利用 RGB 纹理、点云几何、关键点、CAD 模型或学习得到的特征来估计刚体变换。工程上还要处理对称物体带来的多解问题：圆柱体绕自身轴旋转可能在视觉上等价，但夹爪、标签朝向或任务约束未必等价。定姿失败时，机器人往往不是够不到目标，而是以错误角度接近目标，表现为夹爪斜撞、夹偏、碰到桌面或无法沿预期方向插入。因而，定姿层是从“空间定位”走向“动作对齐”的关键一步。

| 层级 | 核心问题 | 主要输入 | 主要输出 | 典型方法 | 对抓取的作用 |
|---|---|---|---|---|---|
| 识别 | 目标是什么 | RGB 图像 | 类别、bbox、mask | YOLO、Mask R-CNN、SAM | 确定操作对象与感兴趣区域 |
| 定位 | 目标在哪里 | mask + depth | 3D 中心、目标点云 | 反投影、聚类、滤波 | 提供空间位置与几何载体 |
| 定姿 | 目标朝向如何 | RGB-D、点云、CAD / 先验模型 | 6D object pose | PnP、ICP、模板匹配、位姿回归 | 支撑夹爪姿态对齐与抓取模板映射 |

这三个层级在工程实现中并不一定严格分步。例如，部分 6D 位姿网络会同时输出平移和旋转，部分抓取检测网络会绕过显式 object pose 直接输出 grasp pose。但在系统分析和调试中，将三者区分仍然重要：定位误差主要影响“能否到达目标附近”，定姿误差主要影响“夹爪能否以正确方向接触物体”。前者通常表现为抓空或偏位，后者更容易表现为夹偏、顶撞或滑脱。

这种区分在真机调试中尤其重要。若机器人每次都偏向同一侧，问题往往在深度尺度、手眼外参或 TCP 偏置；若机器人位置基本正确但夹爪总是斜着撞向物体，问题更可能来自旋转估计、物体对称性处理或抓取模板定义。把“识别、定位、定姿”拆开分析，可以避免把所有失败都笼统归因于“模型不准”。

**本节小结：** 识别、定位和定姿分别回答“是什么”“在哪里”和“朝向如何”，三者不是并列的孤立任务，而是一条逐步逼近操作执行的感知阶梯。识别层决定系统应该处理哪个对象，定位层把目标从像素区域推进到米制三维空间，定姿层则进一步恢复物体坐标系，使夹爪可以按正确方向接触目标。工程调试中，把这三层拆开分析非常重要：漏检、深度偏移和姿态翻转会导致完全不同的失败表现。后续的点云提取、6D 位姿估计和抓取生成，正是在这三层信息逐渐闭合的基础上展开。

### 1.3 两条技术路线：模块化感知 vs 端到端感知

按照是否显式构造中间表征，机器人抓取系统可分为两类：**模块化感知**与**端到端感知**。前者将检测、分割、点云、位姿、抓取规划拆成可检查的模块；后者尝试由原始观测直接生成抓取动作或动作评分。

如果把抓取系统看成一条生产线，模块化方法会在每个工位留下可检查的半成品：bbox、mask、点云、位姿矩阵、抓取候选。端到端方法则更像一个整体策略网络，输入图像和状态，直接给出动作。前者调试成本低、链路更长；后者形式简洁、数据要求更高。两者没有绝对优劣，关键取决于任务是否需要可解释、可验证和可逐步排错。

#### 1.3.1 模块化感知：经典的分层流水线架构

模块化路线强调显式中间结果。每一步输出都可以被保存、可视化和单独评估，因此特别适合教学实验、工业部署和需要追责排错的真实机器人系统。

#### 1.3.2 端到端感知：直接映射的数据驱动范式

端到端路线试图减少人工设计的中间步骤，让模型直接从图像、点云或状态输入中预测动作。它的优势是形式统一、可吸收大规模数据；难点在于数据成本、泛化边界和失败解释。

| 比较维度 | 模块化感知 | 端到端感知 |
|---|---|---|
| 基本范式 | 检测 → 分割 → 点云 → 6D 位姿 → 抓取 | 图像 / 点云 → 抓取动作或动作分布 |
| 中间表征 | 显式，可视化和单步验证方便 | 隐式，依赖网络内部特征 |
| 误差诊断 | 可定位到检测、深度、配准、标定等环节 | 失败归因困难 |
| 数据需求 | 可复用检测、分割、CAD、点云等分任务数据 | 依赖大量示教、仿真或真实抓取数据 |
| 几何约束 | 易嵌入坐标变换、ICP、碰撞检查 | 需通过网络结构或训练数据隐式学习 |
| 典型场景 | 工业抓取、教学实验、可靠性优先系统 | 开放类别操作、策略学习、研究探索 |

#### 1.3.3 深度对比与综合权衡

本讲采用模块化路线作为主线。原因并不是端到端路线不重要，而是模块化路线更适合建立清晰的机器人感知知识结构：每一级表征都有明确的数据类型、坐标系和误差来源，便于将视觉算法与运动规划、手眼标定和真机调试连接起来。

实际系统中，两条路线也常常是混合的。例如，前端可以使用开放词汇检测和通用分割模型获得目标 mask，后端仍然使用点云滤波、ICP、手眼标定和运动规划保证几何一致性；也可以用学习方法生成多个抓取候选，再用 IK 与碰撞检测筛掉不可执行的结果。这样的混合架构既利用了深度模型的泛化能力，又保留了机器人系统中必要的几何校验。

**本节小结：** 模块化路线把检测、分割、点云、位姿和抓取拆成可观察的中间环节，优势是数据类型清晰、误差来源可追踪、单模块验证方便；端到端路线则试图用数据直接学习从观测到动作的整体映射，优势是接口简洁、表达能力强、适合开放场景策略学习。两条路线的差别，本质上是可靠性、可解释性、数据成本和泛化能力之间的工程权衡。真实机器人系统通常不会极端地选择其中一边，而是在前端吸收大模型的开放能力，在后端保留点云几何、手眼标定、IK 和碰撞检测等硬约束。这样的折中也解释了本讲为什么以模块化链路为主线，同时保留对学习式方法的讨论。

### 1.4 本讲核心内容与学习路径

本讲后续内容按照“二维感知 → 三维点云 → 6D 位姿 → 抓取执行”的顺序展开。核心问题不是单个算法如何刷高指标，而是前一阶段输出如何成为后一阶段的输入约束。

因此，阅读本讲时可以始终抓住一条线：机器人不是为了“看懂图像”而看图像，而是为了最后能安全地动手。第 3 节关注如何把二维前景变成干净点云；第 4 节关注如何从点云和图像中恢复物体姿态；第 5 节关注如何把物体姿态进一步翻译成夹爪动作。这样看，后续每个技术模块就不是孤立知识点，而是同一条抓取链路上的连续环节。

#### 1.4.1 本讲定位：服务机器人场景下的全链路视角

本讲不把位姿估计孤立为一个视觉算法，而是把它放在机器人操作闭环中讨论。这样处理的好处是，读者可以同时看到模型输出、坐标变换、抓取模板和执行校验之间的依赖关系。

#### 1.4.2 从输入到执行：七步闭环学习主线

## 2 机器人感知任务体系与标准抓取流水线

### 2\.1 机器人感知任务分类图谱

机器人视觉感知是一个庞大的任务集合，不同任务对应不同的输出形式、技术路线与应用场景。从最基础的图像分类到复杂的多传感器融合感知，各任务之间既有独立的适用范围，又存在明确的依赖与递进关系。建立清晰的分类体系，有助于精准定位位姿估计在整个领域中的位置，理解各任务之间的衔接逻辑，也为后续章节中流水线设计、算法选型与系统调试提供概念基础。

![image\.png](../../assets/figures/lecture06/image%202_1.png)

#### 2\.1\.1 按任务目标划分：语义、几何与属性三大类



按照任务的核心输出目标，机器人感知可分为语义类、几何类、属性类三大分支。三者从"看懂是什么"到"量清在哪里"再到"知道怎么用"逐级深化，构成了从环境理解到物理操作的完整认知链路。

1. 语义类任务：核心解决"是什么"的问题，输出语义标签与区域信息。

语义感知是机器人进入场景后的第一步认知，其目标是将原始像素映射为有意义的概念标签。根据输出粒度的不同，语义类任务可进一步细分为四个层次。图像分类是最基础的语义任务，它判断整张图像的主体类别，适用于场景级粗分类，如判断当前相机视野中是否包含待抓取物体。目标检测在分类的基础上叠加了定位能力，输出图像中每个目标的类别与矩形边界框，兼顾语义理解与粗定位，是当前工业机器人抓取系统中使用最广泛的语义模块。实例分割将输出粒度推进到像素级别，为每个独立物体生成精确的轮廓掩膜，从而实现目标与背景的精确分离，是连接语义感知与几何计算的关键桥梁。语义分割则关注场景中不同类别的区域划分，如桌面、地面、墙壁、传送带等，用于机器人对整体环境的语义理解与导航决策。

2. 几何类任务：核心解决"在哪里、朝哪"的问题，输出空间几何信息。

几何感知是机器人从"看见"走向"操作"的关键跃迁。语义感知告诉机器人场景中有哪些物体，而几何感知则告诉机器人这些物体在三维空间中的精确位置与姿态。按照输出信息的完整度，几何类任务可划分为四个层级。3D 中心点估计输出物体的三维质心坐标，是最低粒度的几何输出，常用于粗略的目标定位与抓取点引导。6D 物体位姿估计输出物体在相机坐标系下的完整三维位置与旋转姿态，包含 3 个平移自由度和 3 个旋转自由度，是抓取操作的核心中间表示，也是绝大多数位姿驱动抓取系统的关键环节。抓取位姿估计在物体位姿的基础上进一步结合夹爪模型与抓取策略，直接输出夹爪的可执行位姿，是几何感知链条的最终操作目标。深度估计则从单张 RGB 图像预测场景的稠密深度图，为单目视觉系统提供从二维到三维的映射能力，是缺乏主动深度传感器时的替代方案。

3. 属性与 Affordance 类任务：核心解决"能怎么用"的问题，输出物体的操作属性。

语义感知告诉机器人"这是什么"，几何感知告诉机器人"它在哪里"，但机器人要完成实际抓取操作，还需要知道"它能怎么用"。属性与 Affordance 类任务正是为此而生。物理属性估计关注物体的尺寸、重量、材质、重心分布等固有物理特性，这些信息直接影响抓取策略的选择——例如，易碎物体需要轻柔夹持，重心偏移的物体需要调整夹取位置。Affordance 感知直接面向可操作性，判断物体的可操作区域与可执行动作，如杯柄适合提拉、瓶盖适合旋转、按钮适合按压，这种"功能导向"的感知方式使机器人能够理解物体与操作动作之间的映射关系。力觉触觉感知则通过接触传感器在抓取过程中实时感知交互状态，如滑移检测、接触力反馈等，用于抓取过程中的闭环修正与自适应调整，是连接感知与执行的关键反馈通道。

三类任务在机器人操作系统中各司其职：语义类任务构建场景认知，几何类任务提供空间坐标，属性类任务指导操作策略。三者协同工作，共同支撑起机器人在复杂环境中的自主操作能力。

#### 2\.1\.2 按输入模态划分：从单目到多传感器融合

输入模态决定了感知系统的信息上限。不同的传感器配置带来不同的信息丰富度、系统复杂度和适用场景，按照传感器配置的递进关系，可将感知系统分为四个层级。

![image\.png](../../assets/figures/lecture06/image%202_2.png)

1. 单 RGB 模态：仅依靠彩色相机输入，硬件成本最低，但缺乏直接的几何深度信息。

单 RGB 模态是视觉感知的最简配置，仅使用一台彩色相机获取场景的二维纹理信息。其最大优势在于硬件成本低、系统部署简单、数据采集方便。然而，由于缺乏直接的深度测量，三维信息完全依赖算法从单张或连续多帧 RGB 图像中推理得到，如通过单目深度估计网络预测深度图，或通过运动恢复结构从多视图重建三维点云。这种依赖算法推理的几何获取方式精度有限，对纹理稀疏、光照变化、反射表面等场景的鲁棒性较差。单 RGB 模态适用于对深度精度要求不高、场景结构简单且纹理丰富的抓取任务，或在深度传感器无法使用的特殊场景中作为替代方案。

2. RGB\-D 模态：彩色图像与深度图同步输入，同时提供语义纹理与几何距离信息。

RGB\-D 模态是当前机器人抓取感知的主流标准配置。深度相机通过结构光、飞行时间或双目立体视觉等原理，在获取彩色图像的同时同步输出像素对齐的深度图，使每个像素点同时具备颜色信息与距离信息。这种配置从根本上解决了单目视觉缺乏直接深度测量的核心瓶颈，使得三维点云的获取变得快捷可靠。RGB\-D 模态的典型传感器包括 Intel RealSense 系列、Microsoft Kinect 系列、Orbbec 系列等，它们体积小巧、成本适中、精度满足多数抓取场景需求，已成为学术研究与工业部署中的事实标准。RGB\-D 模态的局限性在于：深度传感器存在测量范围限制，对透明物体、反光表面、黑色吸光物体等特殊材质的深度测量效果不佳，且强光环境下红外结构光容易受到干扰。

3. 多相机模态：多台相机从不同视角协同观测，减少遮挡盲区，提升位姿估计精度。

单台 RGB\-D 相机虽然能提供完整的三维信息，但受限于单一视角，不可避免地存在遮挡盲区——物体被遮挡的部分无法被观测到，导致点云数据不完整，进而影响位姿估计的精度与鲁棒性。多相机模态通过部署两台或更多相机从不同角度协同观测，有效弥补了单视角的遮挡缺陷。多相机系统需要解决的关键技术问题包括：多相机之间的外参标定（将不同相机的坐标系统一到同一参考系下）、多视角数据的融合策略（如何将不同视角的点云和图像信息有效融合）、以及计算资源的协同分配。多相机模态显著提升了位姿估计的精度上限，尤其适用于精密操作和复杂装配场景，但系统复杂度和硬件成本也随之增加。

4. 多传感器融合：融合视觉、激光雷达、力觉、IMU 等多种传感器信息。

多传感器融合是感知系统的最高配置形态，通过融合多种异质传感器的信息，弥补单一传感器模式的固有缺陷，实现优势互补。典型的融合配置包括：视觉传感器提供丰富的语义纹理信息，激光雷达提供大范围高精度的三维几何信息，惯性测量单元提供运动状态与加速度信息，力觉传感器提供接触交互信息。多传感器融合的关键技术在于异质数据的时间同步与空间对齐、不同置信度信息的融合策略、以及融合后的状态估计与不确定性量化。这种配置适用于动态、非结构化、光照条件复杂的真实场景，如户外移动操作、人机协作、灾难救援等，是高阶人形机器人与移动操作机器人的发展方向。

本节小结：机器人感知可从任务目标与输入模态两个维度建立分类体系。从任务目标看，语义、几何、属性三类任务逐级深化，分别回答"是什么""在哪里""怎么用"三个核心问题，共同支撑机器人的操作能力。从输入模态看，从单 RGB 到多传感器融合的逐步升级，不断提升感知系统的信息上限与环境适应性。位姿估计与抓取位姿生成作为几何类任务的核心环节，是连接语义感知与物理操作的关键桥梁，也是后续章节深入讨论的主题。

### 2\.2 位姿驱动抓取的完整流水线

位姿驱动是当前工业与服务机器人抓取领域最成熟、落地最广泛的技术范式。它以 6D 物体位姿为核心中间表示，将物体在三维空间中的精确位置与姿态作为后续操作的依据，串联起从图像输入到机械臂执行的完整流程。理解这条流水线的每个环节及其依赖关系，是工程实践中进行系统设计、算法选型与故障排查的核心基础。

#### 2\.2\.1 标准 8 步流程：从图像采集到机械臂执行

完整的位姿驱动抓取包含 8 个串行环节，前序环节的输出是后序环节的输入，形成严格的依赖链路。任一环节的失效都会阻断后续流程，因此理解每个环节的输入输出与功能边界至关重要。

![image\.png](../../assets/figures/lecture06/image%202_3.png)

1. RGB\-D 图像采集

通过深度相机同步获取时间对齐、像素对齐的彩色图像与深度图，是整个感知系统的数据源头。彩色图像提供丰富的纹理与语义信息，深度图提供每个像素对应的空间距离信息。采集环节的关键技术指标包括：图像分辨率与帧率、深度测量范围与精度、彩色与深度图像之间的像素对齐精度、以及数据传输的实时性。采集质量直接决定了后续所有环节的性能上限——如果深度图存在大范围空洞或噪点，后续的点云提取与位姿估计将难以获得可靠结果。实践中，采集环节需要根据场景特点选择合适的相机型号与参数配置，如曝光时间、增益、白平衡等，并确保传感器处于稳定的工作状态。

2. 目标检测

在 RGB 图像中运行目标检测器，输出目标物体的类别、边界框与置信度。目标检测的作用是快速缩小后续处理的空间范围，将感知注意力从整幅图像聚焦到目标物体所在的局部区域。当前主流的检测器包括 YOLO 系列、Faster R\-CNN、DETR 等，在工业场景中通常以 YOLO 系列部署最为广泛，因其在检测速度与精度之间取得了良好的平衡。检测环节需要关注的关键指标包括：检测召回率（是否漏检了目标物体）和检测精度（是否出现了误检或边界框偏移），两者都会对后续流程产生直接影响。

3. 实例分割

基于检测框或文本提示生成像素级实例掩膜，精确分离目标物体与背景像素。实例分割的输出是一张与 RGB 图像同尺寸的二值掩膜，其中目标物体对应的像素值为 1，背景像素值为 0。这一环节的核心价值在于消除背景噪声对后续几何计算的干扰——如果未做精确分割，背景点云混入目标点云，将导致位姿估计出现系统性偏移。当前可用的实例分割方法包括基于深度学习的经典方法（如 Mask R\-CNN）和基于视觉基础模型的方法（如 SAM），后者通过文本提示或点在提示实现零样本分割，在开放类别场景中具有显著优势。

4. 目标点云提取

用实例掩膜过滤深度图，通过像素反投影生成目标物体的三维点云，并完成滤波、去噪、降采样等预处理。具体而言，对于掩膜内每个像素，利用相机内参将其二维像素坐标与深度值反投影为相机坐标系下的三维点坐标，从而得到目标物体的局部点云。提取后的点云通常需要经过一系列预处理操作：统计滤波去除离群噪声点、体素降采样减少点云密度以降低计算开销、法向量估计为后续配准提供几何特征。点云质量的好坏直接决定了位姿估计的成败——空洞过多、噪声过大或点云过于稀疏都会导致位姿估计收敛失败或输出错误结果。

5. 6D 位姿估计

基于目标点云与 RGB 特征，结合物体先验模型，计算物体在相机坐标系下的完整 6D 位姿矩阵。6D 位姿包含 3 个平移参数（x, y, z）和 3 个旋转参数（通常用旋转矩阵或四元数表示），构成一个 4×4 的齐次变换矩阵。当前主流的 6D 位姿估计方法可分为三类：基于对应点匹配的方法（如 PnP 求解）、基于点云配准的方法（如 ICP 迭代最近点算法）、以及基于端到端深度学习的方法（如 PoseCNN、GDR\-Net 等）。实际工程中，通常采用"粗估计 \+ 精配准"的两阶段策略：先用深度学习网络获得初始位姿，再用 ICP 进行精细化迭代配准，兼顾速度与精度。

6. 抓取位姿生成

结合物体位姿、几何尺寸与抓取策略，计算夹爪的接近方向、开合尺度、安全偏移与姿态匹配关系，生成可执行的抓取位姿与预抓取位姿。抓取位姿生成并非简单的位姿复制，而是需要考虑多个约束条件：夹爪的几何尺寸与运动学限制、物体的局部几何特征（如抓取表面是否平坦、是否存在可夹持的凸起结构）、物体与周围环境的碰撞可能性、以及抓取策略的选择（如顶抓、侧抓、两指夹持、吸盘吸取等）。预抓取位姿是夹爪在接近物体之前的准备位置，通常位于物体正前方一定偏移距离处，确保接近路径的安全性与可执行性。

7. 基座坐标转换

通过手眼标定得到的外参矩阵，将相机坐标系下的抓取位姿转换为机器人基座标系下的位姿，完成视觉空间到机器人空间的映射。手眼标定是连接感知系统与执行系统的关键环节，通常分为"眼在手上"和"眼在手外"两种配置，分别对应不同的标定方法与计算流程。标定结果的精度直接影响抓取位姿在机器人空间中的准确性——一个微小的标定误差将在远距离处被放大为可观的位姿偏移。基座坐标转换的本质是一个刚体变换，即通过左乘一个 4×4 的齐次变换矩阵将相机坐标系下的位姿变换到基座坐标系。

8. 机械臂执行

运动规划器基于目标抓取位姿生成无碰撞运动轨迹，驱动机械臂完成接近、抓取、抬升的完整动作。运动规划需要考虑机械臂的正逆运动学、关节限位、自碰撞避免、环境碰撞避免、以及运动轨迹的光滑性与速度连续性。常用的运动规划算法包括 RRT 系列（快速随机搜索树）、CHOMP（协变哈密顿优化运动规划）、STOMP（随机轨迹优化运动规划）等。执行阶段还包括力控与柔顺控制策略，在夹爪接触物体时通过力觉反馈进行自适应调整，以防止夹持力过大损坏物体或夹持力过小导致滑落。

#### 2\.2\.2 各环节失效的误差传导效应

位姿驱动抓取流水线的核心特征是严格的串行依赖关系，误差具有逐级传导与放大的特性。理解各环节失效的典型表现与误差传导规律，是工程调试时快速定位故障根源的核心基础。

1\.检测漏检与误检是流水线中最致命的失效模式。如果目标检测器未能检测到场景中的目标物体，后续所有环节将无法正确启动，抓取直接失败。如果检测器误将背景物体识别为目标，流水线将定位到错误目标，产生"抓取成功但拿错了物体"的隐蔽故障。检测环节的误差通常来自训练数据分布与部署场景的差异、极端光照条件、严重遮挡等情况。

2\.分割轮廓偏差的影响具有传导性。实例分割输出的掩膜如果存在边界偏差——过大则混入背景像素，过小则截断目标物体的边缘部分——都会导致后续提取的目标点云不完整或包含噪声。这种偏差会进一步传导到位姿估计环节：背景点云的混入会使位姿出现系统性偏移，而目标点云被截断则可能使位姿估计在局部最优中收敛失败。

3\.点云质量差是工程实践中最为常见的故障来源之一。深度传感器在透明、反光、吸光等特殊材质表面会产生显著的空洞与噪点，导致目标点云稀疏、残缺或包含大量离群点。点云质量差会直接导致位姿估计环节的收敛失败——ICP 算法在点云过于稀疏时无法找到正确的对应关系，深度学习方法的位姿输出也会因输入信息不足而出现较大偏差。

4\.位姿估计偏差对抓取结果的影响最为直接。平移误差会使夹爪抓取位置偏离物体中心，导致夹偏或抓空；旋转误差则会使夹爪姿态与物体表面不匹配，导致夹爪与物体边缘碰撞、物体被推离原位或夹持不稳。位姿估计的精度要求与物体尺寸和夹爪类型密切相关：小型物体对平移误差更敏感，细长物体对旋转误差更敏感。

5\.标定误差具有全局性影响特征。不同于其他环节的随机误差或局部误差，手眼标定误差会在整个工作空间中产生系统性的均匀偏移——所有抓取结果都出现固定方向和固定大小的位姿偏差。这种系统性误差在流水线调试中具有独特的诊断价值：如果机器人抓取物体时总是偏向同一方向，应当优先排查标定参数而非其他环节的算法性能。

理解上述误差传导规律，有助于在实操中建立系统化的故障排查思路：首先确认标定参数是否正确，再检查点云采集质量，然后依次验证检测、分割、位姿估计各环节的输出，最后定位到具体失效环节。

本节小结：位姿驱动抓取包含 8 步标准流水线，从数据采集到机械臂执行形成完整的前馈依赖链路。各环节的误差具有逐级传导放大的特性，前端感知数据的质量决定了系统的性能上限，标定误差则会带来系统性的全局偏差。在工程实践中，理解误差传导规律比掌握单个算法的原理更为重要，因为它是快速定位故障根源、系统性优化系统性能的核心能力。

### 2\.3 核心概念辨析：bbox /mask/center point /object pose /grasp pose

初学者在入门机器人视觉抓取时，最容易混淆不同层级的感知输出概念。这些概念虽然都描述物体在空间中的某种"位置"，但它们在定义形式、维度信息、用途场景和精度要求上存在本质差异。清晰区分五类核心输出的定义与内涵，是建立正确认知体系的前提。

#### 2\.3\.1 五类感知输出的定义与维度对比

五类感知输出按照信息粒度从低到高排列，逐级逼近机器人操作所需的完整空间描述。

边界框（Bounding Box, bbox） 是最粗略的感知输出形式，在二维图像平面上用一个带方向的矩形框标记目标物体的位置。其数学表示为 \(x, y, w, h\)，其中 \(x, y\) 为矩形框左上角或中心点的像素坐标，w 和 h 分别为框的宽度和高度。边界框仅提供二维平面上的粗略定位，不包含任何三维深度信息，也不包含物体的精确轮廓和旋转姿态。它适合作为后续精处理的空间范围引导，但无法直接用于机器人操作。

掩膜（Mask） 是像素级别的语义输出，在图像平面上为每个像素分配一个二进制标签，指示该像素是否属于目标物体。相比于边界框，掩膜提供了物体的精确轮廓，能够区分物体与背景的边界，从而消除背景像素对后续几何计算的干扰。掩膜仍然是在二维图像平面上的描述，不包含三维空间信息，但其像素级精度使其成为连接二维感知与三维几何计算的关键桥梁。

中心点（Center Point） 是三维空间中的最低粒度几何输出，通常表示为物体质心在相机坐标系下的三维坐标 \(x, y, z\)。中心点提供了物体在三维空间中的位置信息，但完全不包含物体的旋转姿态和尺寸信息。对于对称物体或球形物体，中心点可能足以引导抓取，但对于大多数非对称物体，仅凭中心点无法确定夹爪的接近方向与夹持姿态。

物体位姿（Object Pose） 是完整的 6D 空间描述，包含物体在相机坐标系下的三维位置 \(x, y, z\) 和三维旋转姿态 \(rx, ry, rz\)，通常以 4×4 齐次变换矩阵表示。物体位姿提供了物体在空间中的完整刚体变换信息，是连接视觉感知与机器人操作的核心中间表示。从物体位姿出发，可以计算出物体上任意一点在空间中的位置，也可以确定物体的朝向和对称性。

抓取位姿（Grasp Pose） 是机器人的最终操作目标，表示夹爪在机器人基座标系下的可执行位姿。与物体位姿不同，抓取位姿不仅包含空间位置与姿态，还隐含了夹爪的开合状态、接近方向、安全偏移等操作信息。抓取位姿是直接发送给机器人运动规划器的指令，其坐标系通常以机器人基座为参考，而非相机坐标系。从物体位姿到抓取位姿的转换，需要经过基座坐标变换和抓取策略计算两个关键步骤。

#### 2\.3\.2 用途场景与精度要求差异

不同输出对应不同的任务阶段，对精度的要求差异显著，越靠近执行端精度要求越高。

边界框主要用于目标检测与粗定位阶段，其精度要求相对宽松。在典型的抓取场景中，只要边界框完整包围目标物体且能够正确引导后续的分割与点云提取，即可满足要求。边界框的精度通常以交并比（IoU）衡量，在抓取场景中 IoU 达到 0\.7 以上即可接受，因为边界框本身并不直接参与几何计算，其误差会在后续环节中被进一步修正。

掩膜的精度要求高于边界框，因为掩膜直接决定了目标点云的质量。掩膜如果过小，会截断物体边缘，导致点云不完整；如果过大，会混入背景像素，导致位姿估计出现系统性偏移。掩膜精度通常以边界 F1 分数或平均 IoU 衡量，在抓取场景中要求掩膜边界误差不超过数个像素。对于细小部件或精密操作场景，掩膜精度要求更高，需要亚像素级别的分割精度。

中心点的精度要求取决于物体尺寸与夹爪类型。对于大型物体（如箱子、盒子），中心点误差在厘米级别仍可接受，因为夹爪的容错空间较大。对于小型物体（如螺丝、电子元件），中心点误差需要控制在毫米级别，否则夹爪可能完全错过目标。中心点精度通常以绝对位置误差（APE）衡量。

物体位姿的精度要求与抓取任务类型密切相关。对于普通抓取任务，平移误差在物体尺寸的 10% 以内、旋转误差在 10° 以内通常可以接受，因为夹爪的柔顺机构与力控反馈可以补偿一定程度的位姿偏差。对于精密装配任务，如插拔连接器、拧螺丝，位姿误差要求达到亚毫米级和 1° 以内。物体位姿精度通常以平移误差（cm/mm）和旋转误差（°）分别衡量，也可以使用 ADD（平均距离度量）或 ADD\-S（对称物体平均距离度量）等综合指标评估。

抓取位姿作为最终的可执行指令，其精度要求最为严格。抓取位姿的误差直接决定了抓取能否成功，而不像前端感知误差那样可以通过后续环节补偿。在基座坐标转换中，标定误差会与位姿估计误差叠加，因此抓取位姿的实际精度要求通常比物体位姿高出 1\-2 个数量级。抓取位姿的精度评估没有统一的度量标准，最终以抓取成功率这一物理指标作为评判依据。

核心结论：检测和分割都是中间手段，生成可执行的 grasp pose 才是机器人感知的最终目标。所有前端感知算法的性能优劣，最终都要以抓取成功率这一物理指标作为评判标准，而不是以各自输出层面的精度指标作为独立评价依据。

本节小结：bbox、mask、center point、object pose、grasp pose 五类输出按信息粒度逐级提升，分别对应不同的任务阶段与精度要求。从二维到三维、从粗定位到精操作，每一类输出都在流水线中承担着不可替代的角色。感知的终点不是物体识别，也不是位姿估计，而是生成机械臂可直接执行的抓取位姿。所有前端算法的价值，最终都要通过抓取成功率来验证——这是贯穿整个机器人感知系统的核心评价逻辑。

### 2\.4 不同硬件平台的感知需求差异

不同形态的机器人硬件，在自由度、安装方式、操作场景与工作空间上存在显著差异，对感知系统的需求侧重点也各不相同。不存在放之四海而皆准的感知方案，必须结合具体硬件特性与目标应用场景进行针对性设计。本节以四种典型机器人平台为例，分析其感知需求差异与选型思路。

#### 2\.4\.1 SO101 桌面机械臂：固定视角下的精准定位

SO101 类小型桌面机械臂通常为 6 自由度固定基座配置，搭配单台固定深度相机，面向桌面分拣、简单抓取等轻量级工业与教育场景。

核心需求：该类平台的核心场景是单目标、固定视角下的高重复抓取，因此首要诉求是高重复定位精度与运行稳定性，而非感知的泛化能力。由于相机与机械臂基座的相对位置固定不变，手眼标定可一次性完成并在长期使用中保持有效。

技术特点：场景结构化程度高，工作空间有限，物体种类相对固定，光照条件可控。这些特点使得感知系统可以采用简化设计——不需要复杂的动态重标定，不需要多视角融合，也不需要强泛化能力。感知系统的主要挑战在于如何在有限算力条件下实现稳定可靠的实时检测与位姿估计。

选型建议：优先采用模块化流水线架构，使用 YOLOv8 等轻量级检测器完成目标检测，使用基于深度学习的位姿估计网络（如 GDR\-Net）进行粗估计，再通过 ICP 算法进行精配准。这种组合在固定场景下能够兼顾速度与精度，且各模块可独立替换与优化。对于算力受限的嵌入式平台，可进一步精简流水线，如直接使用基于模板匹配的位姿估计方法，放弃深度学习的灵活性以换取更高的运行效率。

#### 2\.4\.2 xLeRobot 移动操作：多坐标系与动态场景适配

xLeRobot 类移动操作机器人由移动底盘与机械臂组成，相机分布在头部（眼在手外）与腕部（眼在手上），面向动态室内环境的移动抓取任务。

核心需求：该类平台面临的核心挑战是多坐标系之间的统一与动态场景下的目标跟踪。移动底盘的运动使相机视角不断变化，机器人在导航过程中需要同时处理全局场景理解与局部精细操作，对感知系统提出了更高的集成度要求。

技术特点：需要同时维护眼在手外与眼在手上两套标定关系。头部相机负责大范围场景感知与目标搜索，腕部相机负责近距离精细观测与抓取引导。底盘运动带来的视角变化要求感知系统具备目标跟踪与重识别能力，避免因视角变化导致的目标丢失。此外，底盘在运动过程中的振动与晃动也需要通过滤波算法进行补偿，以保证感知输出的稳定性。

选型建议：采用"全局粗定位 \+ 局部精定位"的两级感知架构。全局层级使用头部相机进行场景级目标检测，输出目标在全局地图中的粗略位置；局部层级在机器人接近目标后切换至腕部相机，进行精细的位姿估计与抓取位姿生成。这种架构兼顾了搜索效率与抓取精度，是移动操作场景中主流的工程方案。在视觉基础模型成熟后，可引入开放词汇检测与分割模型，增强对未知物体的泛化能力。

#### 2\.4\.3 Imeta\-Y1 科研机械臂：精密操作的高位姿精度要求

Imeta\-Y1 类高精度科研机械臂面向精密插拔、微装配、电子元件焊接等复杂操作任务，对位姿精度要求极高，通常需要亚毫米级的定位精度与亚度级的旋转精度。

核心需求：精密操作的核心诉求是极致的 6D 位姿精度与鲁棒性。这类任务中，物体通常尺寸较小、结构复杂，对位姿误差的容忍度极低——一个微小的旋转角度偏差就可能导致插拔失败或零件损坏。因此，感知系统需要能够在各种干扰条件下稳定输出高精度位姿。

技术特点：精密操作场景对感知系统的要求体现在多个维度。首先，需要高分辨率深度传感器或高精度结构光扫描仪，以获取足够精细的目标点云。其次，需要多视角融合以消除单视角的遮挡盲区，通过多相机阵列从不同角度同时观测目标，融合得到完整的三维信息。此外，小部件的精细分割也是关键挑战——物体尺寸小、边缘模糊，通用的实例分割模型难以达到所需精度，通常需要针对特定物体进行精细调优或使用高分辨率定制模型。

选型建议：采用多相机阵列结合高精度 ICP 配准的方案。多相机阵列提供多视角观测数据，通过点云融合得到完整的高密度目标点云；高精度 ICP 配准基于物体 CAD 模型进行迭代优化，实现亚毫米级的位姿精度。同时，配合力控末端执行器，在接触过程中通过力觉反馈进行接触式位姿补偿，进一步弥补视觉感知的残余误差。

#### 2\.4\.4 Unitree G1 人形机器人：全身感知与多视角协同

Unitree G1 类人形机器人具备全身自由度，多相机分布在头部、手部、躯干等位置，面向非结构化家庭与服务场景，是当前对感知系统要求最为全面的机器人平台。

![image\.png](../../assets/figures/lecture06/image%202_5.png)

核心需求：人形机器人的感知需求具有多层次、多模态、高实时的特点。首先是全身感知空间的统一——头部相机、手部相机、躯干传感器各自有独立的坐标系，需要统一到机器人本体坐标系下。其次是多视角的快速切换与协同——机器人在执行任务过程中需要根据当前动作状态动态切换主视角，如行走时以头部相机为主，抓取时以手部相机为主。再次是目标与双手的相对位姿匹配——双手操作任务中，需要同时感知左右手与被操作物体之间的相对位置关系。最后是开放类别泛化能力——家庭场景中的物体种类繁多且不可预知，感知系统必须具备零样本或少样本的泛化能力。

技术特点：人形机器人的感知场景高度非结构化，物体类别多变，光照条件复杂，遮挡严重。这些特点使得传统的固定类别、固定场景的感知方案难以胜任。视觉基础模型（如 CLIP、SAM、DINOv2 等）的引入为开放类别感知提供了新的技术路径，使机器人能够在不需要特定训练的情况下识别和操作未知物体。

选型建议：采用模块化与端到端混合架构。基础通用任务（如物体检测、场景分割、目标搜索）使用开放词汇的视觉基础模型，利用其在海量数据上预训练的泛化能力；精密操作任务（如精细抓取、装配）则切换回基于几何精配准的传统方法，利用 CAD 模型或高精度点云配准获取亚毫米级精度。这种混合架构在人形机器人的感知系统中兼具泛化性与精度，是当前技术条件下的最优权衡。

本节小结：不同硬件平台的感知需求差异显著，不存在通用的"万能感知方案"。桌面机械臂追求固定场景下的稳定精度与重复定位能力，移动操作机器人侧重多坐标系统一与动态场景适配，科研机械臂要求极致的位姿精度与鲁棒性，人形机器人则更看重泛化能力与全身协同感知。感知方案的设计必须结合硬件特性与目标场景进行针对性选型，在精度、泛化性、实时性、系统复杂度之间寻求最优权衡。

## 3 视觉感知前端：目标检测分割与点云提取

视觉感知前端的任务，是将原始 RGB-D 观测转化为可供 6D 位姿估计使用的目标点云表示。这个过程不是简单的图像裁剪，而是一个从二维语义约束到三维几何恢复的表征转换过程：检测建立候选区域，分割约束前景像素，深度图提供尺度，内参模型完成反投影，点云滤波则将原始观测整理为稳定的几何输入。

可以把这一节理解为机器人“把一张图像观测转化为一簇空间点”的过程。起初，机器人只有一张 RGB 图和一张深度图，里面既有目标物体，也有桌面、背景和其他干扰物。检测器先把处理范围集中到目标附近，分割模型再提取目标前景，深度图提供每个前景像素到相机的距离，最后反投影和滤波把这些像素变成三维空间中的目标点云。这个过程稳定以后，后面的位姿估计才有可靠的几何输入。

从系统角度看，第 3 节输出的不是“好看的分割图”，而是后续位姿估计可以使用的 `target point cloud`。因此，前端质量应以点云纯净度、完整性、尺度一致性和实时性来评价，而不仅是检测 mAP 或分割 IoU。

### 3.1 输入模态：RGB-D 数据与多相机配置

#### 3.1.1 RGB 相机：语义纹理的提供者

RGB-D 观测同时包含语义纹理与几何测距信息。RGB 图像适合完成类别识别、边缘提取和实例分割；深度图为每个有效像素提供距离观测；相机内参 $K$ 则定义了像素坐标到相机坐标的几何映射。对机器人而言，这三者必须作为一个整体理解：RGB 决定“哪些像素属于目标”，Depth 决定“这些像素离相机多远”，内参决定“这些像素如何回到三维空间”。

![图6.2 RGB-D 相机示意：彩色相机提供纹理与语义线索，深度模组提供距离观测，二者对齐后构成点云恢复的输入基础](../../assets/figures/lecture06/图6.2.jpg){width=70%}

图 6.2 展示的是一个典型 RGB-D 相机的硬件形态。对机器人抓取而言，RGB 与 Depth 的关系不是“谁替代谁”，而是互补：RGB 更擅长区分类别和边界，Depth 更擅长提供距离和尺度。只有二者完成时间同步、像素对齐和内参标定，后续的“mask 筛深度”和“深度反投影”才有意义。否则，即使分割结果看起来很准，也可能因为 RGB 与深度没有对齐，把错误位置的深度值拿来生成点云。

实际部署时，需要优先确认三个基础条件：第一，RGB 与 Depth 是否已经注册到同一像素坐标系；第二，深度值是否有明确单位，例如 16-bit 深度图常以毫米存储，而 Open3D 等库通常以米为几何单位；第三，相机内参是否与当前分辨率一致。很多看似“位姿估计不稳定”的问题，最后都能追溯到这三项基础配置。

| 输入项 | 提供的信息 | 典型用途 | 主要误差来源 |
|---|---|---|---|
| RGB 图像 | 颜色、纹理、边缘、语义线索 | 检测、分割、目标识别 | 光照变化、遮挡、反光、运动模糊 |
| Depth 图像 | 像素级距离观测 | 反投影、点云恢复、3D 定位 | 深度空洞、飞点、量程误差、材质相关噪声 |
| 相机内参 $K$ | $f_x,f_y,c_x,c_y$ | 像素到相机三维坐标转换 | 标定误差、畸变补偿不足、尺度配置错误 |
| 手眼外参 | 相机与机器人坐标系关系 | 相机系到基座系转换 | 外参漂移、矩阵方向混淆、采样姿态不足 |

#### 3.1.2 深度相机：三维几何的感知核心

深度相机本身也有不同技术路线。双目立体视觉依赖左右图像的视差，适合纹理丰富、光照可控或户外场景；结构光通过投射编码图案获得深度，近距离精度较高，但容易受强光和反光表面影响；ToF 相机通过测量光飞行时间估计距离，覆盖范围较大，但在边缘、反光和多径反射场景中仍会产生系统性噪声。选型时不应只看分辨率，还要同时考虑工作距离、目标材质、安装方式和允许的标定复杂度。

| 深度技术 | 基本原理 | 优势 | 局限 | 抓取场景中的典型用法 |
|---|---|---|---|---|
| 双目 / 主动双目 | 由视差恢复深度 | 结构简单，部分方案适合较远距离 | 弱纹理区域匹配困难 | 移动机器人、较大工作空间观测 |
| 结构光 | 投射已知图案并分析形变 | 近距离精度高，适合桌面场景 | 强光、反光和透明材质敏感 | 桌面分拣、近距离物体建模 |
| ToF | 测量光传播时间或相位差 | 量程较大，响应快 | 边缘、多径和反光噪声明显 | 中距离感知、全局粗定位 |

#### 3.1.3 多相机配置：从单一视角到系统级视觉

常见相机拓扑可分为三类。Eye-to-Hand 相机固定在工作空间外，视野稳定，适合桌面分拣和工位监控；Eye-in-Hand 相机安装在末端执行器附近，近距离精度高，适合精细对位和二次复检；多相机协同则通过顶视、头部、腕部等视角互补，缓解遮挡并扩展可观测空间。拓扑选择会直接影响后续手眼标定形式和抓取闭环策略。

#### 3.1.4 关键参数：选型的量化依据

相机选型最终要落到可量化指标上：工作距离决定深度有效范围，分辨率和视场角决定目标在图像中的像素占比，帧率影响闭环响应，标定稳定性决定点云尺度和坐标转换是否可信。若这些底层条件不足，后续模型精度很难弥补硬件观测质量的缺口。

**本节小结：** RGB-D 输入为抓取感知提供了语义与几何两类互补信息：RGB 帮助系统识别目标类别、纹理和边界，Depth 给出尺度、距离和局部几何，内参和外参则把这些像素观测放回真实空间。相机拓扑、工作距离、分辨率、深度噪声和标定稳定性并不是外围配置，而是直接决定点云质量和坐标转换可靠性的基础条件。多相机配置可以减少遮挡、扩大视野，但也会引入同步、外参维护和数据融合成本。只有输入侧足够可信，后续检测、分割、点云提取和位姿估计才有稳定发挥的可能。

### 3.2 目标检测：从边界框到目标粗定位

#### 3.2.1 核心作用：缩小搜索空间，为后续处理"划重点"

目标检测的作用，是在整幅图像中建立受约束的候选区域，减少后续分割、深度关联和点云处理的搜索空间。检测结果并不直接给出抓取点，而是提供语义先验和区域先验。

在实际系统中，检测通常是整条链路的第一道候选生成环节。没有检测框，后续分割模型可能要面对整幅图像；没有类别和置信度，任务层也很难判断当前目标是否就是用户想抓的对象。检测的价值不在于一步到位解决抓取，而在于把问题从“整张图里有什么”缩小为“这个局部区域里如何恢复目标几何”。

#### 3.2.2 输出形式：边界框、类别与置信度

| 输出项 | 含义 | 在后续链路中的作用 |
|---|---|---|
| `class` | 目标类别 | 关联任务约束与抓取策略库 |
| `bbox` | 二维候选框 | 限定分割与深度关联范围 |
| `score` | 检测置信度 | 过滤误检、排序候选目标 |

#### 3.2.3 YOLO 系列：实时检测的工业标准

闭集检测器的代表是 YOLO 系列。它的优势是推理快、部署成熟，适合固定类别和实时性要求高的场景。对桌面机械臂来说，如果任务只涉及少量已知物体，训练一个轻量 YOLO 或 YOLO-seg 模型往往比直接使用大型通用模型更稳定。原因很直接：闭集任务的类别边界清晰，标注成本可控，模型输出也更容易和后端抓取策略库绑定。

#### 3.2.4 Grounded-SAM：开放词汇检测的新范式

开放词汇检测器解决的是另一类问题：任务目标不一定来自固定类别表，而可能来自语言指令，例如“拿起那个蓝色瓶子”。Grounding DINO 与 SAM 组合后，可以先根据文本找到候选目标，再由分割模型给出前景 mask，适合服务机器人和开放环境。它的优势是泛化，代价是链路更长、延迟更高，而且文本提示的歧义会传递到后续 mask 和点云。

| 方法类别 | 代表实现 | 特点 | 适用场景 |
|---|---|---|---|
| 闭集检测 | YOLO 系列、Faster R-CNN | 类别集合固定，部署成熟 | 已知类别、边缘设备、工业分拣 |
| 开放词汇检测 | Grounding DINO、Grounded-SAM | 文本提示驱动，类别开放 | 家庭服务、语言交互、未知物体搜索 |
| 检测跟踪组合 | detector + tracker | 帧间稳定，减少跳变 | 视频流、移动平台、动态目标 |

#### 3.2.5 核心局限：二维信息不足以支撑抓取

检测阈值不应只根据 mAP 设定。阈值过低会引入误检，导致背景深度进入点云；阈值过高会漏掉目标，使整条感知链无法启动。对于抓取系统，检测器的输出应和后续点云质量一起评估。

在工程实现中，检测结果通常还要经过任务层过滤。例如，同一帧图像中检测到多个杯子时，系统需要根据语言指令、距离、可达性或抓取优先级选择其中一个；当检测框连续多帧跳动时，应引入跟踪或时序平滑，避免后续点云在帧间抖动。检测器不是独立终点，而是整个抓取链路的候选生成器。

**本节小结：** 目标检测是抓取感知链路中的第一道候选生成环节，它把全图搜索问题缩小到目标相关区域，也为任务层提供类别和置信度线索。闭集 YOLO 适合已知类别、实时性要求高的场景，开放词汇检测则适合服务机器人面对长尾物体和语言指令的任务。无论采用哪类检测器，检测结果本身都仍只是二维入口，不能直接给出深度、姿态或可执行接触点。要让这个入口真正服务抓取，还必须继续经过实例分割、深度关联、点云处理和坐标转换。

### 3.3 实例分割：从像素级掩码到目标区域提取

#### 3.3.1 核心作用：从"矩形框"到"精确轮廓"

若直接用 bbox 裁剪深度图，矩形区域通常会同时包含目标、桌面和邻近物体。这些非目标像素在反投影后会变成背景点云，污染质心估计、法向量估计和点云配准。因此，实例分割在本链路中的功能，是为三维恢复提供目标级前景约束。

这里可以把 bbox 和 mask 的差别理解得更直观一些：bbox 在图像上给出一个“搜索范围”，mask 则进一步给出目标前景像素集合。对于人眼来说，框里混入少量桌面并不影响理解；但对点云算法来说，桌面点和物体点没有语义标签，一旦一起进入配准或主轴估计，就会被当成同一个几何对象处理。很多抓取偏差并不是位姿算法本身的问题，而是从这一步开始，目标点云已经被背景点污染了。

| 表示形式 | 保留对象 | 背景混入风险 | 对三维恢复的影响 |
|---|---|---|---|
| 整幅图像 | 场景全部像素 | 最高 | 反投影得到完整场景点云 |
| bbox 裁剪 | 矩形区域像素 | 中等 | 桌面、邻物易混入目标点云 |
| mask 筛选 | 目标前景像素 | 最低 | 更利于恢复目标专属点云 |

#### 3.3.2 经典实例分割模型：Mask R-CNN 与 YOLACT

![图6.3 Mask R-CNN 的两阶段实例分割结构：先生成候选区域，再并行完成分类、框回归和 mask 预测](../../assets/figures/lecture06/图6.3.jpg){width=60%}

Mask R-CNN 代表了经典两阶段实例分割范式 [1]。它的思路可以拆成两步看：第一步先让 Region Proposal Network（RPN）在特征图上找出一批可能包含目标的候选区域；第二步对每个候选区域做更精细的判断，包括类别分类、边界框修正和像素级 mask 预测。图 6.3 中的 `mask branch` 就是 Mask R-CNN 相比 Faster R-CNN 增加的关键分支，它让模型不只知道“这里有一个目标”，还能知道“目标在这个框里的哪些像素上”。

这种两阶段结构的优势是稳。候选区域先把问题缩小，再在局部区域内做细分割；RoIAlign 等对齐机制减少了特征量化误差，因此边界质量通常较好，适合小零件分拣、工件装配前定位、桌面物体点云提取等对轮廓敏感的场景。它的代价是链路较长，推理速度和部署复杂度不如单阶段方法。对于教学和离线实验，Mask R-CNN 很适合用来解释“检测框为什么不够、mask 为什么有价值”；对于实时抓取，则需要结合算力和帧率要求权衡。

![图6.4 YOLACT 类单阶段实例分割思路：网络同时预测原型 mask 与实例系数，再通过线性组合生成具体实例掩膜](../../assets/figures/lecture06/图6.4.jpg){width=90%}

YOLACT 则走了另一条路线：不再先生成候选区域再逐个精修，而是在一次前向传播中同时预测两类东西：一组全图共享的 prototype masks，以及每个检测实例对应的 mask coefficients [2]。最终每个实例的 mask 由这些 prototype 按系数组合得到。图 6.4 右侧的 “Prototypes mask 与 mask coefficients 线性组合” 展示的就是这个过程。它把“每个实例单独做精细分割”的问题，改写成“全图原型 + 实例系数”的组合问题。

这类方法的关键取舍是用“可组合的原型”换取速度。它不需要对每个 RoI 单独运行复杂的 mask 分支，因此更适合视频流和边缘设备。但也因为 mask 是由若干原型组合出来的，在边界特别复杂、小物体密集或严重遮挡时，分割质量可能不如两阶段方法稳定。对机器人抓取来说，如果场景是传送带、桌面分拣或固定类别物体，YOLACT 类方法可以提供较高帧率；如果任务要求精密插拔或小零件位姿估计，则需要重点验证 mask 边缘误差是否会放大为点云误差。

| 维度 | Mask R-CNN | YOLACT |
|---|---|---|
| 基本范式 | 两阶段，先候选区域再局部分割 | 单阶段，原型 mask 与实例系数组合 |
| 主要优势 | 边界质量较稳，便于解释和离线评估 | 推理链路短，适合实时或视频流 |
| 主要风险 | 速度和部署成本较高 | 复杂边界、小物体和遮挡场景下需谨慎验证 |
| 抓取前端定位 | 高质量 mask 生成器 | 实时目标前景筛选器 |

#### 3.3.3 通用分割基础模型：SAM / SAM2

![图6.5 SAM2 的视频分割结构：通过图像编码、提示编码、记忆注意力和记忆库维持跨帧目标一致性](../../assets/figures/lecture06/图6.5.jpg){width=85%}

SAM2 的价值不只在于“能分割”，更在于它把分割从单张图像扩展到了视频序列 [3]。图 6.5 中的 memory attention 和 memory bank 可以理解为模型的短期记忆：第一帧由点、框或 mask 提示确定目标以后，后续帧不必每次从零开始找目标，而是参考过去帧中的目标表示继续跟踪。对于机器人来说，这一点很重要，因为机械臂一旦开始运动，视角、遮挡和光照都会变化。如果每一帧的 mask 都独立预测，目标前景可能抖动；如果能利用时序记忆，点云和位姿估计会更稳定。

在抓取系统中，SAM2 更适合作为“交互式目标锁定 + 时序前景保持”的工具，而不是替代几何模块。第一次提示可以来自人工点击、语言检测框或任务规划器；后续帧则依赖记忆机制维持同一目标身份。这样做的直接收益是降低 mask 在连续帧中的跳变，从而减少点云质心和位姿估计的抖动。

![图6.6 文本提示、视觉提示与时序跟踪结合的通用分割流程，可用于开放词汇目标定位与连续帧前景保持](../../assets/figures/lecture06/图6.6.jpg){width=85%}

图 6.6 展示的流程进一步把语言提示、视觉提示和时序跟踪结合起来。用户可以说“抓那个红色杯子”，开放词汇检测器先根据文本找到候选目标，分割模型再生成 mask，跟踪模块负责在后续帧维持目标一致性。对于服务机器人和移动操作平台，这种能力比固定类别检测更接近真实需求：家庭、办公室、仓储环境中的物体种类很难提前穷尽，机器人必须能根据语言描述临时确定目标。

不过，SAM 系列和 Grounded-SAM 类方法不能被理解为完整抓取前端。它们输出的仍然是二维 mask，并不直接解决深度空洞、透明物体、手眼标定或夹爪碰撞问题。更准确的定位是：它们把开放类别目标从图像中分离出来，为后续 RGB-D 几何恢复提供更强的前景约束。要让它真正服务抓取，还需要继续接上深度筛选、反投影、点云滤波和坐标转换。

#### 3.3.4 核心局限：仍为 2D 感知，需与深度图配合

实例分割误差通常以三种方式向下游传播：边界漏分会低估物体尺寸；背景混入会偏移点云质心和主方向；遮挡粘连会把多个物体错误合并，使位姿估计建立在错误几何对象上。

**本节小结：** 实例分割把粗糙的 bbox 进一步收缩为目标前景像素，是二维视觉进入三维点云之前的关键筛选步骤。对机器人而言，mask 的价值不只是让图像结果更精细，而是决定哪些深度像素会被带入三维空间；一旦背景、桌面或邻物混入，后续质心估计、主轴估计和点云配准都会受到影响。Mask R-CNN、YOLACT、SAM/SAM2 等方法各有适用边界，选型时要同时考虑实时性、开放类别能力、边缘精度和与深度图的对齐质量。因此，实例分割虽然仍停留在 2D 层面，却直接决定了下一步目标点云是否“干净”、位姿估计是否有可靠输入。

### 3.4 点云生成与滤波：从深度图到三维目标点云

目标点云生成是从图像域进入欧氏空间的关键步骤。给定实例 mask、深度图和相机内参，系统先筛选目标前景深度，再将有效像素反投影到相机坐标系，最后通过滤波和降采样形成位姿估计所需的几何输入。

到这里，机器人完成了从“看见一块前景区域”到“量出一簇空间点”的转换。这一步看似只是公式计算，但它决定了后续所有几何算法的输入基础是否可靠。深度尺度错了，点云会整体变大或变小；mask 边缘错了，点云会混入桌面；滤波参数过强，目标局部结构会被抹掉。位姿估计如果建立在这样的点云上，再复杂的模型也很难稳定输出正确结果。

#### 3.4.1 像素反投影：从深度图到三维点云的核心公式

设相机内参矩阵为：

$$
K = \begin{bmatrix}
 f_x & 0 & c_x \\
 0 & f_y & c_y \\
 0 & 0 & 1
\end{bmatrix}
$$

对于深度像素 $(u,v,d)$，若深度图原始值需要通过尺度因子 $s$ 转换为米制深度，则先令：

$$
Z = \frac{d}{s}
$$

其在相机坐标系下的三维点 $\mathbf{p}_c=(X,Y,Z)^T$ 为：

$$
X = \frac{(u-c_x)Z}{f_x}, \qquad
Y = \frac{(v-c_y)Z}{f_y}, \qquad
Z = \frac{d}{s}
$$

该公式恢复的是**相机坐标系下的观测点**，不是机器人基座坐标系下的控制目标。因此，第 3 节输出仍属于视觉几何表征，后续必须经过手眼外参和抓取映射才能用于执行。

反投影公式还隐含两个容易被忽略的前提。第一，深度值 $d$ 必须与 RGB 或 mask 所在像素对齐；若 RGB 与 Depth 分辨率不同或外参未对齐，mask 中的前景像素可能会取到背景深度。第二，深度单位必须明确：许多 RGB-D 相机输出 16-bit 深度图，数值单位可能是毫米，也可能需要乘以 `depth_scale` 才能转为米。单位错误不会让程序报错，但会让点云尺度整体错误，后续位姿估计和手眼转换都会被污染。

#### 3.4.2 点云预处理：从"原始点云"到"干净点云"

| 处理步骤 | 目的 | 典型参数 | 输出结果 |
|---|---|---|---|
| 前景筛选 | 去除非目标深度 | `mask > 0` | 目标深度图 |
| 反投影 | 像素恢复为三维点 | `K, depth_scale` | 原始目标点云 |
| 直通滤波 | 裁剪工作空间外点 | `z_min, z_max` | 有效空间范围点云 |
| 统计滤波 | 剔除离群飞点 | `nb_neighbors, std_ratio` | 更平滑稳定的点云 |
| 体素降采样 | 控制点数与计算量 | `voxel_size` | 适合配准的稀疏点云 |
| 导出存储 | 供位姿估计模块调用 | `.pcd / .ply` | 标准化目标点云文件 |

![图6.7 目标点云预处理过程中的可视化结果：从原始点云到统计滤波、体素降采样后的目标几何表示](../../assets/figures/lecture06/图6.7.jpg){width=90%}

图 6.7 中使用的是经典 Stanford Bunny 点云 / 网格模型，来源于 Stanford 3D Scanning Repository [5]。它是计算机图形学、三维重建、点云处理和 Open3D / PCL 教学中非常常见的基准模型，并不是 OpenCV 专属案例；本讲使用它只是为了直观展示点云滤波、降采样和离群点去除的效果。

点云预处理的目标不是“尽可能保留所有点”，而是在保留主要几何结构的前提下去除噪声并降低计算量。过弱的滤波会使 ICP 或位姿回归受到离群点干扰；过强的滤波则会破坏边缘、孔洞、把手等对姿态判断有价值的局部结构。Open3D 中常用的体素降采样和统计离群点滤波，正好对应这两个目标：前者控制点数，后者根据邻域距离剔除孤立点 [4]。

三类滤波可以按功能区分。直通滤波用于删除工作空间之外的点，例如桌面以下、相机量程之外或机器人不可达区域；统计离群点滤波根据每个点到邻近点的平均距离剔除孤立飞点，适合处理深度边缘和反光噪声；体素降采样把空间划分成固定大小的立方体网格，每个体素保留一个代表点，用来降低点数并提高配准速度。常见经验是先保证目标点云语义纯净，再做适度去噪，最后按下游算法实时性选择体素大小。

| 操作 | 解决的问题 | 参数含义 | 调参倾向 |
|---|---|---|---|
| 直通滤波 | 删除明显不可能属于目标的空间区域 | `z_min, z_max` 或 XYZ 范围 | 宁可略宽，不要截断目标 |
| 统计滤波 | 删除孤立飞点和边缘离群点 | `nb_neighbors, std_ratio` | 点云稀疏时放宽阈值 |
| 体素降采样 | 控制点数、提升配准速度 | `voxel_size` | 精密抓取取小，实时任务取大 |

参数调节时要先判断下游需求。如果下一步是 ICP 精配准，应保留足够的边缘、平面和局部结构；如果下一步只是计算 3D 中心或粗略包围盒，可以使用更强的降采样来换取速度。对真实机器人来说，滤波参数不是越强越好，而是要服务位姿估计和抓取规划所需的几何信息量。

#### 3.4.3 目标点云提取与误差修正路径

| 现象 | 优先检查项 | 处理建议 |
|---|---|---|
| 点云整体倾斜或尺度异常 | 内参、深度尺度 | 核对 `f_x, f_y, c_x, c_y` 与 `depth_scale` |
| 边缘大量飞点 | 深度边界、反光区域、mask 边界 | 先修正分割，再调整统计滤波参数 |
| 目标被截断 | `z_min / z_max` 过窄、mask 漏分 | 放宽空间阈值或改善前景提取 |
| 点数过多导致配准缓慢 | 点云过密 | 增大 `voxel_size`，但避免过度降采样 |
| 多物体粘连 | 分割失败或遮挡严重 | 重做实例分割，必要时做连通域拆分 |

这些现象分别对应不同层级的假设失配。尺度异常通常源于相机参数或深度单位错误；飞点和空洞对应测距噪声与边界不连续；粘连则说明二维前景约束失败。调试时应先定位表征层级，再调整对应模块。

![图6.9 反投影阶段的统计输出：目标前景深度被转换为相机坐标系下的三维点云](../../assets/figures/lecture06/图6.9.jpg){width=70%}

课堂讨论可以围绕三个问题展开：为什么反投影必须依赖相机内参；为什么深度空洞常出现在物体边缘、反光面和透明材质上；为什么体素降采样需要在“计算效率”和“几何细节保留”之间折中。

**本节小结：** 点云生成完成了从二维像素到三维几何的关键跃迁：mask 负责选出目标前景，深度与内参负责反投影，滤波与降采样负责把原始观测整理成可计算的目标点云。这里最重要的不是某个函数调用，而是每一步都留下可检查的中间结果：masked depth、raw point cloud、passthrough point cloud 和 clean point cloud。直通滤波、统计滤波和体素降采样分别解决空间裁剪、离群点抑制和计算规模控制问题，但参数过强也可能削掉真实几何细节。这样一来，位姿估计前端的错误就不再是模糊的“模型不准”，而可以被定位到 mask、深度尺度、内参、外参或滤波参数等具体环节。

### 3.5 常用开源工具与模型选型

#### 3.5.1 检测分割工具

| 任务条件 | 可选工具 | 选择理由 |
|---|---|---|
| 类别集合封闭、实时性要求高 | YOLO / YOLO-seg | 部署成熟、边缘设备友好，但需要目标数据验证漏检和误检 |
| 目标来自语言指令或长尾类别 | Grounding DINO + SAM / Grounded-SAM | 支持文本提示，适配开放类别物体，但延迟、提示歧义和后处理成本更高 |
| 需要高质量实例 mask 或交互提示 | Mask R-CNN、SAM / SAM2 | 分割质量和提示形式较灵活，但不能直接保证三维位姿或抓取成功率 |

#### 3.5.2 点云处理工具

| 任务 | 推荐工具 | 选择理由 |
|---|---|---|
| 点云处理 | Open3D | 提供滤波、配准、可视化等完整工具链 |
| 真机 RGB-D 数据采集 | RealSense SDK 或相机厂商 SDK | 便于获得对齐 RGB、Depth 与内参 |

#### 3.5.3 选型建议：三维度决策框架

选型时不应使用“固定类别就用 YOLO、开放词汇就用 Grounded-SAM、精度优先就用 SAM”这类无条件口诀。更可靠的决策表应同时检查：类别是否封闭，是否需要实例 mask，是否有深度图 / CAD / 相机内参，时延预算和算力是否允许，模型许可与维护成本是否可接受，以及目标数据上的检测、分割和任务成功率是否达标。对于教学实验，`YOLO / Grounding DINO → SAM → Open3D` 是一条容易观察中间结果的链路；对于工业部署，则应根据目标类别、节拍、算力、失败代价和维护能力做更保守的组合。

**本节小结：** 第 3 节的核心输出不是 bbox，也不是 mask，而是经过前景约束、深度反投影与几何整形后形成的目标点云表征。检测与分割负责回答“处理哪个目标”，深度和内参负责把目标送入三维空间，滤波和工具链则负责让这份点云足够干净、足够轻量、足够可调试。开源工具的选择应围绕链路需求展开：检测分割看类别开放性和实时性，点云处理看几何算子和可视化能力，整体系统还要考虑部署复杂度。接下来，第 4 节将在这份点云或 RGB-D 观测基础上讨论 6D 位姿估计，第 5 节则进一步把位姿结果转化为夹爪可以执行的抓取目标。

## 4 6D 物体位姿估计：原理与主流技术方案

### 4\.1 什么是 6D 位姿：平移与旋转的数学表示

6D 位姿（6 Degree\-of\-Freedom Pose）是描述刚体在三维空间中完整状态的标准表示，包含 3 个平移自由度与 3 个旋转自由度，是连接视觉感知与机器人操作的核心中间量。清晰理解其数学表示，是掌握位姿估计算法的基础。

在机器人抓取场景中，当我们说"估计物体的 6D 位姿"时，本质上是要求解一个刚体变换，它将物体从自身的模型坐标系映射到当前观测到的相机坐标系中。这个变换由平移和旋转两部分组成，分别对应物体在空间中的"位置"和"朝向"。

### 图 4\-1 6D 位姿自由度示意图

展示相机坐标系下物体的 3 个平移自由度与 3 个旋转自由度，符合机器人视觉的标准坐标系约定

![image\.png](../../assets/figures/lecture06/image%204_1.png)

#### 4\.1\.1 平移自由度：物体三维空间位置的量化描述

平移描述物体坐标系原点在参考坐标系（通常为相机坐标系或机器人基座坐标系）中的三维空间位置，用三维列向量表示：$\boldsymbol{t} = \begin{bmatrix} x \ y \ z \end{bmatrix}$ 

单位通常为米（m）或毫米（mm）。在机器人视觉的标准相机坐标系（OpenCV 约定）下：

- x 对应物体在成像平面内的水平位置，向右为正方向；

- y 对应物体在成像平面内的垂直位置，向下为正方向；

- z 对应物体沿相机光轴的深度距离，向前为正方向。

平移分量决定了物体"在空间哪里"，是机械臂能够到达目标区域的基础前提。在工程中，平移量通常通过像素反投影结合深度图初步获得——给定物体某个像素点在图像上的坐标 \(u, v\) 及其对应的深度值 d，通过相机内参矩阵 K 即可反投影出该点在相机坐标系下的三维坐标,这一过程是连接二维图像与三维空间的关键桥梁，也是后续所有几何计算的起点。平移误差会直接导致抓取位置出现左右或前后偏差，在工程中通常要求平移精度达到毫米级别。

#### 4\.1\.2 旋转自由度：三种主流旋转表示方法对比

旋转描述物体坐标系相对于参考坐标系的空间朝向，共有 3 个独立自由度。工程中常用三种表示方式，各有优劣与适用场景。

#### 1\. 欧拉角

- 表示方法：通过三次绕坐标轴的旋转角度描述刚体朝向，工业界最常用 ZYX 外旋顺规，即依次绕参考系 Z 轴旋转 yaw、绕 Y 轴旋转 pitch、绕 X 轴旋转 roll，对应偏航、俯仰、翻滚三个角度。

- 优势：直观易懂，三个角度具有明确的物理意义，便于人类理解与现场调试。

- 劣势：存在万向锁（Gimbal Lock）问题 —— 当 pitch 角为 ±90° 时，第一次旋转的 Z 轴与第三次旋转的 X 轴重合，系统损失一个旋转自由度，导致数值奇异；此外欧拉角插值不连续，求导复杂，不适合作为算法的直接优化目标。

#### 2\. 四元数

- 表示方法：用四维单位向量描述旋转，形式为： $\boldsymbol{q} = [w, x, y, z]^T, \quad \text{满足约束} \quad w^2 + x^2 + y^2 + z^2 = 1$ 其中w为实部，$x,y,z$为虚部，编码了旋转轴与旋转角度信息。

- 优势：无万向锁奇异问题；计算高效（旋转复合仅需四元数乘法）；插值平滑（SLERP 球面线性插值）；存储空间小，是算法优化与机器人控制系统的首选表示。

- 劣势：直观性差，不便于人工直接解读与调试。

- 工程地位：是机器人控制系统与位姿估计算法中最常用的旋转内部表示形式。

#### 3\. 旋转矩阵

- 表示方法：用 3×3 的正交矩阵$\boldsymbol{R}$描述旋转，矩阵的三个列向量分别对应物体坐标系 X、Y、Z 轴在参考坐标系下的单位方向向量： $\boldsymbol{R} = \begin{bmatrix} \boldsymbol{r}_1 & \boldsymbol{r}_2 & \boldsymbol{r}_3 \end{bmatrix} \in SO(3)$ 满足正交性约束：$\boldsymbol{R}^T \boldsymbol{R} = \boldsymbol{I}$，且行列式$\det(\boldsymbol{R})=1$（保证右手系旋转变换）。

- 优势：数学性质严谨，可直接用于三维点的坐标变换，是几何推导与坐标计算的标准形式。

- 劣势：参数冗余（9 个参数描述 3 个自由度），存在强约束，不适合直接作为神经网络的回归目标，训练中难以保证正交性。

#### 4\.1\.3 齐次变换矩阵：位姿的统一工程表达形式

工程实践中，通常将旋转矩阵与平移向量整合为 4×4 的齐次变换矩阵$\boldsymbol{T} \in SE(3)$，作为位姿的标准输出与系统间交换格式：

$\boldsymbol{T} = \begin{bmatrix} \boldsymbol{R} & \boldsymbol{t} \ \boldsymbol{0}^T & 1 \end{bmatrix}$ 

其中左上角 3×3 为旋转矩阵，右上角 3×1 为平移向量，最后一行用于齐次坐标补全。

该矩阵可直接完成不同坐标系之间的点坐标变换：对于任意一点在物体坐标系下的齐次坐标$\boldsymbol{p}_{obj} = [x, y, z, 1]^T$，其在相机坐标系下的坐标为：

$\boldsymbol{p}_{cam} = \boldsymbol{T}_{cam \leftarrow obj} \cdot \boldsymbol{p}_{obj}$

齐次变换矩阵的核心工程价值在于：

1. 级联变换便捷：多级坐标系的串联变换可通过矩阵乘法直接实现，如$\boldsymbol{T}_{base \leftarrow obj} = \boldsymbol{T}_{base \leftarrow cam} \cdot \boldsymbol{T}_{cam \leftarrow obj}$，是手眼标定、坐标转换链路的标准数据结构；

2. 逆变换易求：变换矩阵的逆可通过旋转矩阵转置快速计算，无需复杂的矩阵求逆运算： $\boldsymbol{T}^{-1} = \begin{bmatrix} \boldsymbol{R}^T & -\boldsymbol{R}^T \boldsymbol{t} \ \boldsymbol{0}^T & 1 \end{bmatrix}$ 

本节小结：6D 位姿由 3 个平移自由度与 3 个旋转自由度组成，分别描述物体的空间位置与朝向。旋转有欧拉角、四元数、旋转矩阵三种主流表示方式，其中四元数适合算法计算与控制，旋转矩阵适合几何推导与坐标变换，欧拉角适合人工调试。齐次变换矩阵是工程中位姿的统一表达形式，支持级联坐标变换，是全链路数据交互的标准格式。

### 4\.2 位姿估计的三类技术路线

6D 位姿估计经过数十年发展，形成了三类技术路线清晰、适用场景各异的方法体系：传统几何法、模板匹配法与深度学习法。三者并非简单的迭代替代关系，而是在不同场景、不同硬件条件下各有最优解，工程落地中常采用混合架构取长补短。

#### 4\.2\.1 传统几何法：基于点云配准的 ICP 系列

传统几何法是位姿估计的经典技术路径，核心依赖刚体变换的几何约束，无需数据训练，可解释性强。

#### 核心思想

将观测得到的目标点云与物体的 CAD 模型点云进行迭代配准，寻找使两组点云最优对齐的刚体变换矩阵（旋转 \+ 平移）。代表算法为ICP（Iterative Closest Point，迭代最近点）及其众多变体，包括点到点 ICP、点到平面 ICP、截断 ICP 等。

#### 算法流程（点到点 ICP）

1. 输入初始化：给定初始位姿估计、观测目标点云$\mathcal{P} = \{ \boldsymbol{p}_i \}_{i=1}^N$、模型参考点云$\mathcal{Q} = \{ \boldsymbol{q}_j \}_{j=1}^M$；

2. 对应点匹配：为每个观测点$\boldsymbol{p}_i$在模型点云中寻找欧氏距离最近的对应点$\boldsymbol{q}_j$，形成对应点对；

3. 最优变换求解：构造最小二乘目标函数，求解使所有对应点距离平方和最小的刚体变换$\{ \boldsymbol{R}, \boldsymbol{t} \}$： $E(\boldsymbol{R}, \boldsymbol{t}) = \frac{1}{N} \sum_{i=1}^{N} \left\| \boldsymbol{p}_i - (\boldsymbol{R} \boldsymbol{q}_{c(i)} + \boldsymbol{t}) \right\|^2$ 其中$c(i)$为第i个观测点对应的模型点索引。该问题可通过 SVD（奇异值分解）求得闭式解： 

    - 计算两组点云的质心：\\\(\\bar\{\\boldsymbol\{p\}\} = \\frac\{1\}\{N\}\\sum\\boldsymbol\{p\}\_i\\\)，\\\(\\bar\{\\boldsymbol\{q\}\} = \\frac\{1\}\{N\}\\sum\\boldsymbol\{q\}\_\{c\(i\)\}\\\)

    - 计算协方差矩阵：\\\(\\boldsymbol\{H\} = \\sum \(\\boldsymbol\{p\}\_i \- \\bar\{\\boldsymbol\{p\}\}\)\(\\boldsymbol\{q\}\_\{c\(i\)\} \- \\bar\{\\boldsymbol\{q\}\}\)^T\\\)

    - SVD 分解：\\\(\\boldsymbol\{H\} = \\boldsymbol\{U\} \\boldsymbol\{\\Sigma\} \\boldsymbol\{V\}^T\\\)

    - 最优旋转：\\\(\\boldsymbol\{R\} = \\boldsymbol\{U\} \\boldsymbol\{V\}^T\\\)（若行列式为负则修正反射歧义）

    - 最优平移：\\\(\\boldsymbol\{t\} = \\bar\{\\boldsymbol\{p\}\} \- \\boldsymbol\{R\} \\bar\{\\boldsymbol\{q\}\}\\\)

4. 迭代收敛：用求解得到的变换更新观测点云，重复步骤 2\-3，直到误差变化小于阈值或达到最大迭代次数。

#### 算法变体与优化

- 点到平面 ICP：目标函数改为最小化观测点到模型点切平面的距离，收敛速度显著快于点到点版本，是工程中最常用的变体；

- 截断 ICP（Truncated ICP）：对距离过大的对应点进行截断，提升对离群点与遮挡的鲁棒性。

#### 优势与局限

- 优势：精度极高，收敛后可达亚毫米级；无需训练，纯几何驱动，可解释性强；有成熟的开源实现（如 PCL、Open3D）。

- 劣势：对初始位姿要求高，初始偏差过大易陷入局部最优；对严重遮挡、大量离群点敏感；无纹理、高度对称物体易匹配错误。

- 适用场景：已知物体精确三维模型、初始位姿偏差较小的工业场景，常用作深度学习粗估计后的位姿精化环节。

#### 4\.2\.2 模板匹配法：基于三维模型的姿态对齐

模板匹配法是工业场景中应用较早的实时位姿估计方案，核心是预先生成姿态模板库，在线通过特征匹配快速检索位姿。

#### 核心思想

离线阶段预先渲染物体在不同视角、不同姿态下的二维 / 三维特征模板，构建完整的模板库；在线阶段将输入图像 / 点云与模板库进行特征匹配，找到相似度最高的模板，其对应的姿态即为估计结果。代表方案为经典LINEMOD算法及其深度学习增强变体。

#### 算法流程

1. 离线建库：对物体 CAD 模型进行全视角采样（通常按 5°\-10° 步长采样方位角与俯仰角），渲染生成大量视角图像；提取每幅图像的梯度方向、深度法线等鲁棒特征，与对应姿态绑定存入模板库；

2. 在线匹配：对输入场景图像提取相同特征，通过滑动窗口与模板库进行快速卷积匹配，输出相似度最高的模板对应的 6D 位姿；

3. 后处理：对匹配结果进行非极大值抑制，去除重复检测，输出最终位姿。

#### 优势与局限

- 优势：推理速度极快，适合高实时性场景；对低纹理、无纹理金属 / 塑料物体友好；对硬件算力要求低，可在嵌入式平台部署。

- 劣势：姿态精度有限，通常仅作为粗估计；模板库存储空间随视角粒度指数增长；新物体需要重新建库，零样本泛化能力差。

- 适用场景：结构化工业分拣场景、固定物体模型、对实时性要求高但精度要求适中的任务。

#### 4\.2\.3 深度学习法：从两阶段方案到端到端范式



深度学习方法利用神经网络从大规模数据中学习位姿特征，凭借强泛化性与端到端能力成为当前研究主流，根据架构设计可分为两阶段与端到端两大类。

#### 1\. 两阶段方案

- 核心逻辑：第一阶段完成目标检测与实例分割，裁剪出目标区域；第二阶段单独输入位姿回归网络，输出 6D 位姿。

- 典型代表：SAM\-6D，以 SAM 大模型的零样本分割结果为基础，后续接轻量级位姿回归头。

- 技术特点：任务解耦清晰，便于分模块调试与优化；分割精度直接决定位姿估计的上限；可复用成熟的检测分割模型，降低开发成本。

#### 2\. 端到端方案

端到端方案可进一步分为直接回归型与检测驱动型两类：

- 直接回归型：网络输入原始 RGB\-D 图像，直接输出完整的旋转与平移参数。代表为 FoundationPose，通过隐式几何重构与可微优化实现强泛化性。 

    - 优势：零样本泛化能力强，对遮挡、截断场景鲁棒，可适配未知类别物体；

    - 劣势：模型参数量大，推理速度慢，训练数据与算力需求高。

- 检测驱动型：基于 YOLO 等目标检测架构扩展，单次前向传播同步预测类别、检测框与物体 3D 包围盒角点的 2D 投影，再通过PnP（Perspective\-n\-Point）几何算法求解 6D 位姿。代表为 YOLO\-6D。 

    - 核心原理：PnP 算法已知物体 3D 关键点的模型坐标与对应的 2D 像素投影，结合相机内参即可闭式求解相机到物体的位姿，是连接 2D 检测与 3D 位姿的经典几何桥梁。

    - 优势：推理速度极快，模型轻量化，支持实时部署；工程落地成熟，便于与现有检测系统集成；

    - 劣势：泛化能力有限，依赖已知物体 3D 模型，严重遮挡与对称场景下精度下降明显。

三类技术路线对比：

本节小结 6D 位姿估计形成了三类成熟的技术路线：传统几何法精度最高但依赖初始值，模板匹配法速度最快但泛化性差，深度学习法泛化性强但算力需求高。工程实践中常采用 “深度学习粗估计 \+ ICP 精配准” 的混合方案，兼顾速度、泛化性与精度，是当前落地最广泛的组合模式。

### 4\.3 典型开源方案对比：FoundationPose / SAM\-6D / YOLO\-6D

FoundationPose、SAM\-6D 与 YOLO\-6D 是当前工程与科研领域最具代表性的三类开源位姿估计方案，分别对应端到端通用型、两阶段融合型、检测驱动实时型三条技术路径，适配不同的场景需求。

#### 4\.3\.2 不同场景下的选型决策建议

位姿估计方案不存在绝对的优劣，选型的核心是匹配场景需求，在精度、速度、泛化性、部署成本之间寻求最优权衡。

1. 工业结构化场景：固定物体、追求实时性 优先选择 YOLO\-6D \+ ICP 精化 的方案：前端用 YOLO\-6D 快速输出粗位姿，后端用 ICP 基于 CAD 模型做几何精配准，兼顾实时性与高精度，是工业分拣、装配场景的最优解。该方案部署成熟、调试简单，且能充分利用工业场景物体固定、光照可控的特点。

2. 服务机器人场景：物体类别多变、追求泛化性 优先选择 SAM\-6D 方案：依托 SAM 的零样本分割能力，适配家庭、办公等开放场景下的多种常见物体，无需针对每个物体单独训练，平衡泛化性与推理速度。配合点云预处理与简单几何约束，可满足多数服务抓取任务的精度要求。

3. 科研前沿场景：未知物体、追求通用能力 优先选择 FoundationPose 方案：其强零样本泛化能力适合探索未知物体操作、通用抓取等前沿方向，是当前通用位姿估计的标杆方案。该方案无需物体 CAD 模型，在遮挡、截断场景下仍能输出稳定位姿，适合基础研究与非结构化场景探索。

选型核心原则：优先匹配场景需求，不盲目追求 SOTA。在满足任务要求的前提下，优先选择部署简单、维护成本低、调试方便的方案；混合架构往往能通过模块组合取得比单一方案更优的工程性价比。

本节小结：三类主流开源方案各有定位：YOLO\-6D 胜在速度与轻量化，适合工业实时场景；SAM\-6D 胜在开放泛化，适合服务机器人场景；FoundationPose 胜在通用能力，适合科研前沿探索。选型需结合场景的物体种类、精度要求、硬件条件综合判断，“粗估计 \+ 精配准” 的混合架构是工程落地的主流思路。

### 4\.4 位姿估计的精度评价指标

位姿估计的性能需要量化指标进行客观评估，不同指标从不同维度衡量精度。掌握评价指标是算法选型、效果评测与故障排查的基础。

#### 4\.4\.1 ADD 与 ADD\-S：位姿精度的核心综合指标

ADD 与 ADD\-S 是位姿估计领域最通用的综合评价指标，从点云整体对齐程度衡量位姿偏差，也是 LineMOD、YCB\-Video 等主流数据集的标准评测指标。

### 图 4\-5 ADD 与 ADD\-S 评价指标原理对比

![image\.png](../../assets/figures/lecture06/image%204_5.png)

#### 1\. ADD（Average Distance）指标

- 计算方式：将物体模型上的所有采样点，分别通过估计位姿与真值位姿进行变换，计算两组变换后点集中对应点的欧氏距离，取所有点距离的平均值： $\text{ADD} = \frac{1}{M} \sum_{i=1}^{M} \left\| \boldsymbol{T}_{est} \cdot \boldsymbol{x}_i - \boldsymbol{T}_{gt} \cdot \boldsymbol{x}_i \right\|_2$ 其中M为物体模型的采样点数，$\boldsymbol{x}_i$为物体坐标系下的第i个模型点，$\boldsymbol{T}_{est}$为估计位姿，$\boldsymbol{T}_{gt}$为真值位姿。

- 物理含义：衡量估计位姿与真值位姿之间的整体空间偏差，距离越小表示位姿精度越高。

- 合格阈值：通常以物体直径的 10%作为合格判定阈值，若 ADD 小于该阈值则判定为本次位姿估计正确。

#### 2\. ADD\-S 指标

- 提出背景：ADD 指标对于对称物体存在评估歧义 —— 对称物体旋转后点的一一对应关系不唯一，即使位姿正确，直接按索引计算也会得到较大距离，导致误判为错误。

- 计算方式：对于每个估计位姿变换后的点，不再匹配固定索引的对应点，而是在真值变换后的模型点云中寻找最近的点，再计算所有最小距离的平均值： $\text{ADD-S} = \frac{1}{M} \sum_{i=1}^{M} \min_{j=1..M} \left\| \boldsymbol{T}_{est} \cdot \boldsymbol{x}_i - \boldsymbol{T}_{gt} \cdot \boldsymbol{x}_j \right\|_2$ 

- 适用场景：专门用于旋转对称物体的位姿精度评估，是位姿估计数据集的标准补充指标。对于非对称物体，ADD\-S 与 ADD 的计算结果基本一致。

#### 3\. AUC（Area Under Curve）

- 计算方式：以误差阈值为横轴、位姿准确率为纵轴，绘制不同误差阈值下的准确率曲线，计算曲线下的面积。

- 优势：比单一阈值更全面地反映算法在不同精度要求下的整体性能，避免单一阈值的偶然性，是学术论文中最常用的综合对比指标。通常取 0 到物体直径 10% 的误差范围计算 AUC，取值范围为 0 到 1，数值越高位姿性能越好。

#### 4\.4\.2 分项误差指标：平移误差与旋转误差

综合指标便于整体性能对比，但在工程调试与故障排查时，需要分项指标定位误差来源，区分是位置偏差还是朝向偏差。

#### 1\. 平移误差

- 计算方式：估计位姿的平移向量与真值平移向量之间的欧氏距离，单位通常为毫米（mm）： $\text{Translation Error} = \left\| \boldsymbol{t}_{est} - \boldsymbol{t}_{gt} \right\|_2$ 

- 工程意义：直接反映物体位置估计的准确程度，对应抓取操作的左右、上下、前后偏差。

- 典型合格标准：桌面级抓取场景通常要求平移误差小于 5mm；精密装配场景要求亚毫米级。

- 误差溯源：平移误差过大通常源于深度图质量差、相机内参不准或手眼标定存在系统偏差。

#### 2\. 旋转误差

- 计算方式：估计旋转与真值旋转之间的测地线角度差，单位为度（°）。可通过旋转矩阵的迹快速计算： $\theta = \arccos\left( \frac{\text{tr}(\boldsymbol{R}_{est}^T \boldsymbol{R}_{gt}) - 1}{2} \right)$ 其中$\text{tr}(\cdot)$为矩阵的迹，即主对角线元素之和。

- 工程意义：反映物体朝向估计的准确程度，旋转偏差会在长臂展处被放大，是抓取姿态错误、夹爪碰撞物体的主要诱因。

- 典型合格标准：桌面抓取场景通常要求旋转误差小于 5°；精密装配场景要求小于 1°。

- 误差溯源：旋转误差过大通常源于点云特征不足、物体对称歧义或严重遮挡导致的朝向模糊。

工程调试经验：分项误差可以帮助快速定位问题根源 —— 若平移误差大而旋转误差正常，优先排查深度质量与标定；若旋转误差大而平移正常，优先排查点云完整性、物体对称性与位姿优化算法。

本节小结：位姿估计的核心评价指标包括综合指标与分项指标两类。ADD/ADD\-S 与 AUC 是综合评估位姿精度的标准指标，用于算法整体性能对比与学术排名；平移误差与旋转误差分项指标则用于误差溯源与工程调试。实际评测中需结合使用，既看整体准确率，也分析分项误差的分布规律，才能全面评估算法的工程可用性。

## 5 抓取位姿生成：从物体位姿到机器人可执行目标

第 4 节得到的 `object pose` 描述物体在空间中的刚体状态；机器人控制系统真正需要的，是末端执行器在机器人基座坐标系下的可执行目标。因此，抓取位姿生成不是在物体中心“放一个点”，而是将物体状态、夹爪几何、任务约束和坐标变换统一到同一个操作表征中。

如果说第 4 节解决的是“物体摆在哪里”，第 5 节解决的就是“末端执行器应如何接近并约束物体”。这两个问题看起来相近，实际差别很大。一个盒子的物体坐标原点由 CAD 或数据集约定，并不必然是几何中心或质心；即便它恰好位于中心，夹爪也不一定要去中心点。一个杯子的坐标系可以朝向杯口，但夹爪可能更适合从杯身侧面接近；一个工具的姿态估计很准确，也不代表机械臂一定能以那个方向绕过桌面和邻近物体。抓取候选生成就是把这些操作层面的因素逐一补上。

可以将该层理解为如下映射：

$$
({}^{C}T_{O},\; \mathcal{P}_{O},\; \mathcal{G},\; \mathcal{C})
\longrightarrow
\mathcal{Q}_G=\{\,{}^{B}T_{G},\; w_g,\; \mathbf{a},\; \text{pre-grasp},\; \text{score},\ldots\}
$$

其中，$\,{}^{C}T_{O}$ 是相机系下的物体位姿，$\mathcal{P}_{O}$ 是目标点云或几何模型，$\mathcal{G}$ 表示夹爪结构参数，$\mathcal{C}$ 表示环境、任务和可达性约束；输出 $\mathcal{Q}_G$ 是抓取候选集合。严格说，`grasp pose` 指夹爪 TCP 在抓取时刻的 $SE(3)$ 目标 $\,{}^{B}T_G$；夹爪开合宽度、接近方向、预抓取位姿、接触点和质量分数是抓取候选的附加参数。这个映射看起来像一个简单的坐标变换，实际上包含了任务层、几何层和运动学层的共同约束。

### 5.1 为什么 object pose 不等于 grasp pose

`object pose` 和 `grasp pose` 描述的是两个不同对象。前者描述物体坐标系相对于参考坐标系的刚体变换；后者描述夹爪工具中心点（TCP）相对于机器人基座坐标系的目标变换。二者相关，但不等价。

工程上可以把 `object pose` 看作“感知模块的状态估计”，把 `grasp pose` 看作“规划模块的动作候选”。前者尽量客观地描述物体，后者必须带有任务意图：是搬起、递送、倒水、插入，还是只把物体推到一侧。任务不同，即使同一个物体位姿也会对应不同抓取方式。

#### 5.1.1 抓取点选择：物体中心不等于最佳接触点

一个直观例子是螺丝刀：object pose 可以告诉我们螺丝刀的长轴方向和空间位置，但抓取时通常不会去夹刀尖，也不会盲目夹几何中心，而要选择靠近手柄、受力稳定且不影响后续使用的位置。再比如杯子，杯子的物体坐标系可能定义在杯身中心，但抓取策略可能选择从侧面夹杯身，也可能选择抓杯柄附近。也就是说，object pose 是对“物”的描述，grasp pose 是对“手”的描述，中间必须经过抓取策略映射。

| 概念 | 描述对象 | 典型形式 | 回答的问题 | 尚未包含的信息 |
|---|---|---|---|---|
| object pose | 物体坐标系 | $\,{}^{C}T_{O}$ / $\,{}^{B}T_{O}$ | 物体在哪里、朝向如何 | 抓取点、接近方向、夹爪开口、避碰偏置 |
| grasp pose | 夹爪 TCP 坐标系 | $\,{}^{B}T_{G}$ | 夹爪在抓取时刻应到哪里、如何对齐 | 仍需开合宽度、接近 / 撤离、IK、碰撞、力控和执行校验 |
| grasp candidate | 一次完整抓取尝试 | `{pose, width, approach, pregrasp, score, contacts...}` | 描述抓取动作参数集合 | 仍需排序、筛选和执行闭环 |

| 转换阶段 | 输入 | 输出 | 关键约束 |
|---|---|---|---|
| 状态估计 | RGB-D、mask、目标点云 | object pose | 几何一致性、对称性、置信度 |
| 抓取生成 | object pose、点云、夹爪模型 | grasp candidates | 接触稳定性、开合宽度、接近方向 |
| 坐标转换 | 相机外参、当前末端位姿 | base-frame grasp pose | 矩阵方向、单位、TCP 偏置 |
| 执行筛选 | grasp pose、环境模型 | 可执行轨迹 | IK、关节限位、碰撞、速度约束 |

#### 5.1.2 接近方向：物体朝向不等于夹爪进入方向

即使物体姿态估计正确，夹爪也不一定沿物体坐标轴直接接近。接近方向要同时考虑桌面、邻物、夹爪形状和任务意图：顶部抓取更关心桌面法线，侧向抓取更关心局部表面法线，插拔任务则可能要求沿孔轴或工具轴运动。

#### 5.1.3 夹爪开合尺度：物体尺寸不等于夹爪开口宽度

夹爪开口宽度来自被夹持局部的几何尺度，而不是物体整体尺寸。对杯子、工具、带把手物体等非均匀目标而言，物体 bbox 尺寸只能提供粗略上界，真正可用的开合尺度需要结合局部点云、抓取模板或学习模型估计。

#### 5.1.4 安全余量：物体表面不等于夹爪目标位置

抓取位姿还必须包含安全偏移和预抓取姿态。机械臂通常先到达目标外侧的 pre-grasp，再沿接近方向低速进入 grasp 位姿，以减少标定误差、深度噪声和规划误差带来的碰撞风险。

若在物体坐标系下预定义抓取模板 $\,{}^{O}T_{G}$，Eye-to-Hand 情形下可写为：

$$
{}^{B}T_{G} = {}^{B}T_{C} \, {}^{C}T_{O} \, {}^{O}T_{G}
$$

Eye-in-Hand 情形下，由于相机随末端运动，还需引入当前末端位姿：

$$
{}^{B}T_{G} = {}^{B}T_{E} \, {}^{E}T_{C} \, {}^{C}T_{O} \, {}^{O}T_{G}
$$

这两个公式说明：从 object pose 到 grasp pose 的转换，本质上是从**物体状态表征**到**动作构型表征**的映射。该映射同时受物体几何、夹爪结构、环境约束和坐标链路方向的共同影响。

**本节小结：** object pose 描述物体坐标系的刚体状态，grasp pose 描述夹爪 TCP 的目标刚体变换；完整抓取候选还应包含开合宽度、接近方向、预抓取位姿、评分和接触约束等附加参数。一个物体位姿可以对应多个抓取候选，不同候选又会受到夹爪结构、任务意图、周围障碍物和可达性约束的筛选。位姿估计提供的是操作所需的重要中间量，而不是机械臂可以直接执行的最终指令。真正的抓取生成，需要把物体状态、夹爪几何、运动规划和安全策略放在同一条链路中共同考虑。

### 5.2 抓取候选的核心要素：抓取点、接近方向、开合尺度、安全偏移与姿态匹配

一个可执行抓取候选通常包含抓取点、接近方向、姿态对齐、开合宽度和安全偏移等要素。它们共同决定夹爪如何接近目标、在哪个位置形成接触、以何种方向闭合，以及如何在执行前预留安全缓冲。MoveIt 等运动规划框架中的 `grasp_pose`、`pre_grasp_approach`、`post_grasp_retreat`、`pre_grasp_posture` 和 `grasp_posture`，本质上就是把 `pose` 与这些附加动作参数结构化成可提交给规划器的接口字段 [6][7]。

可以按一次真实抓取来理解这些参数：夹爪先要知道目标点在哪里，这是抓取点；接着要知道从哪个方向靠近，这是接近方向；靠近时手指该怎么转，这是姿态对齐；手指张多大，这是开合宽度；最后，不能直接高速冲到接触点，而要先停在目标外侧一个安全位置，这就是安全偏移和预抓取位姿。少掉这些附加参数，单独的 `grasp_pose` 只是一个空间刚体变换，抓取很容易从“可执行动作”退化成“空间里一个孤立的目标姿态”。

#### 5.2.1 抓取点（Grasp Point）：夹爪中心到哪里

抓取点是夹爪 TCP 或两指中心在接触时刻应该到达的位置。它可以来自物体质心、点云包围盒中心、局部平面中心、CAD 模型关键点，也可以来自学习模型预测的接触区域。抓取点并不一定等于物体几何中心：拿杯子时，抓取点可能在杯身侧壁；拿盒子时，抓取点可能接近上表面中心；拿带柄工具时，抓取点常常落在把手或细长轴上。

工程上应区分三类点：目标中心点、接触中心点和 TCP 目标点。目标中心点只表示物体大致在哪里；接触中心点表示夹爪希望夹住哪个局部结构；TCP 目标点还要考虑夹爪几何偏置。若把这三者混为一谈，就会出现“视觉上对准了物体中心，但夹爪指尖实际碰到边缘”的问题。

抓取点的常见检查方式包括：看点是否落在目标点云内部或可接触表面附近；看该点到桌面、邻物和遮挡物的距离是否足够；看以该点为中心的夹爪模型是否能容纳目标局部宽度。对于点云稀疏或遮挡严重的目标，不建议只用单帧质心直接抓取，应结合包围盒、局部法线或多候选排序做保护。

#### 5.2.2 接近方向（Approach Direction）：夹爪从哪个方向来

接近方向决定末端执行器进入目标附近的路径。它通常由桌面法线、物体侧面法线、物体主轴、局部表面法线或任务约束确定，是避碰和姿态规划中最敏感的参数之一。对桌面顶部抓取而言，接近方向常取世界系或基座系的竖直向下；对侧向抓取而言，接近方向通常沿物体侧面法线或夹爪闭合平面的法向进入；对插拔、挂取、按压等任务，接近方向还必须服从孔轴、把手方向或接触面的功能约束。

接近方向不是随便选一条看起来最短的路径。它至少要同时满足三类条件：第一，沿该方向移动时夹爪不会先碰桌面、相机支架、邻近物体或机器人本体；第二，方向要与夹爪闭合后的受力方向匹配，避免把物体推走而不是夹住；第三，pre-grasp 到 grasp 的最后一小段应尽量短、直、低速，便于把视觉误差限制在接触前的局部区域。

一个实用检查是把接近方向画成箭头，并从 pre-grasp 点到 grasp 点连成线段。如果这条线穿过桌面、穿过物体主体之外的遮挡物，或者与夹爪手指开合方向混淆，就说明候选还不能执行。许多抓取失败并不是抓取点错了，而是接近方向把夹爪带到了一个必然碰撞的位置。

#### 5.2.3 开合尺度（Gripper Opening Width）：夹爪张多大

开合尺度决定夹爪闭合前的初始宽度。它需要覆盖被夹持局部的几何尺寸，并加入安全余量；过小会导致手指在到达抓取点前提前碰撞目标，过大则会增加碰到邻物、桌沿或容器壁的风险。对两指夹爪而言，开合尺度通常与夹爪闭合方向上的局部宽度相关，而不是简单等于整个物体的最大宽度。

可以用下面的关系理解：

$$
w_g = d_{\text{local}} + \Delta_{\text{safe}}
$$

其中 $d_{\text{local}}$ 是抓取局部在夹爪开合方向上的尺寸，$\Delta_{\text{safe}}$ 是给定位误差、点云噪声和夹爪重复定位误差预留的余量。这个余量不能无限增大，因为夹爪张得越开，进入狭窄空间时越容易碰撞邻物；也不能太小，因为真实深度、标定和物体摆放都会有误差。

开合尺度还必须受夹爪硬件限制约束。报告中应说明夹爪最小闭合宽度、最大开口宽度和本次候选使用的宽度。如果候选宽度超过夹爪行程，即使位姿完全正确也无法执行；如果宽度接近极限，闭合力和接触稳定性也可能下降。

#### 5.2.4 安全偏移（Safety Offset）：夹爪停在哪儿

安全偏移用于构造 pre-grasp，使夹爪在真正接触前先停在目标外侧。它把长距离运动规划和短距离接触动作分开，是降低执行风险的基本设计。没有 pre-grasp 的抓取，相当于让规划器直接把 TCP 送到接触位姿；一旦深度、标定或路径略有误差，就可能在高速接近阶段撞到物体或桌面。

安全偏移通常沿接近方向反向设置：

$$
\mathbf{p}_{\text{pre}} = \mathbf{p}_{g} - d_{\text{safe}}\mathbf{a}
$$

其中 $\mathbf{p}_{g}$ 是抓取点，$\mathbf{a}$ 是从 pre-grasp 指向 grasp 的单位接近方向，$d_{\text{safe}}$ 是预留距离。这个距离要大于预期定位误差和夹爪外形厚度带来的缓冲需求，但也不能过大；过大会让最后一段直线接近跨越更多障碍物，反而增加碰撞风险。

实际系统中，pre-grasp 还承担一个调试功能：机械臂可以先运动到 pre-grasp，暂停或低速观察，确认夹爪、目标和桌面的相对位置，再执行最后的 approach。对教学实验，即使没有真机，也应在可视化中画出 pre-grasp 点和 grasp 点，让读者看到“安全停靠点”和“实际接触点”的区别。

#### 5.2.5 姿态匹配（Orientation Alignment）：夹爪方向与物体姿态对齐

姿态匹配决定夹爪开合方向、接近方向和 TCP 坐标系之间的关系。规则物体可以依赖主轴或抓取模板，复杂物体则常需要学习模型生成多个候选，再由几何与运动学约束筛选。

一个夹爪姿态通常可以由三根互相正交的轴构造：接近轴、开合轴和手掌法向轴。接近轴决定夹爪从哪里进入，开合轴决定两根手指从哪两个方向夹住物体，第三根轴由右手系约束确定。仅有接近方向还不够，因为夹爪可以绕接近方向旋转；这个绕轴旋转角会决定手指是否对准物体长轴、短轴、把手、孔洞或可接触平面。

对盒子、书本、工具柄等有明显主轴的物体，夹爪开合方向通常要与局部宽度方向对齐，而不是与物体最长方向对齐。对圆柱、杯子这类存在旋转对称的物体，多个姿态可能在几何上等价，但会因为把手、遮挡或邻物而在执行上不同。对插拔和装配任务，姿态匹配比抓取点更敏感，因为几度旋转误差就可能导致插入失败或侧向卡死。

调试姿态匹配时，应同时画出物体坐标系和夹爪 TCP 坐标系，并说明每根轴的物理含义。若只显示一个 4×4 矩阵，读者很难判断夹爪到底是从上方来、从侧面来，还是绕接近方向转错了 90 度。工程报告中最好明确写出：哪根轴是 approach，哪根轴是 finger closing direction，哪根轴是 palm normal。

| 要素 | 物理含义 | 典型确定方式 | 误差后果 |
|---|---|---|---|
| 抓取点 $\mathbf{p}_{g}$ | 夹爪中心到达的位置 | 质心、局部平面中心、关键点、抓取模板 | 夹空、夹边、接触不稳定 |
| 接近方向 $\mathbf{a}$ | 夹爪进入目标的方向 | 桌面法线、表面法线、物体主轴、任务约束 | 提前碰撞、接近受阻 |
| 姿态矩阵 $R_g$ | 夹爪局部坐标系与目标几何的对齐关系 | 由接近方向、开合方向和 TCP 定义构造 | 手指不贴合、姿态偏转 |
| 开合宽度 $w_g$ | 闭合前夹爪张开尺度 | 被夹持部位局部尺寸 + 安全余量 | 无法闭合或压碰邻物 |
| 安全偏移 $d_{safe}$ | 预抓取点到抓取点的距离 | 沿接近方向反向偏移 | 高速接近时撞物、路径过短 |

#### 5.2.6 总结：五个要素的协同关系

从接口角度看，一个抓取候选通常不是只保存 `pose`，而是一组随动作阶段展开的参数：

| 字段 | 对应含义 | 常见用途 |
|---|---|---|
| `grasp_pose` | 末端执行器尝试抓取时的目标位姿 | 作为 IK 和路径规划目标 |
| `pre_grasp_approach` | 抓取前的接近方向和距离 | 控制末端从安全位置进入目标 |
| `post_grasp_retreat` | 抓取后的撤离方向和距离 | 抬升或退出障碍区域 |
| `pre_grasp_posture` | 接近前夹爪姿态 | 通常对应张开状态 |
| `grasp_posture` | 抓取时夹爪姿态或闭合动作 | 控制闭合位置与接触力 |
| `grasp_quality` | 候选抓取评分 | 多候选排序与筛选 |

在代码中，建议把候选保存成结构化对象，而不是只保存一个矩阵。例如：

```json
{
  "grasp_point": [0.12, -0.04, 0.63],
  "approach_direction": [0.0, 0.0, -1.0],
  "closing_direction": [1.0, 0.0, 0.0],
  "gripper_width": 0.065,
  "pre_grasp_distance": 0.08,
  "grasp_pose": "4x4 matrix in base frame",
  "score": 0.82,
  "validity_checks": {
    "within_workspace": true,
    "width_in_range": true,
    "ik_solved": true,
    "collision_free": false
  }
}
```

这个结构的好处是失败时能快速归因：`width_in_range=false` 说明候选超出夹爪行程；`ik_solved=false` 说明空间位姿不可达；`collision_free=false` 说明几何候选存在但路径不可执行。相比只输出 `T_base_grasp`，这种表示更接近真实规划器和抓取模块需要消费的数据。

在实现上，抓取候选可以来自三种来源。第一种是模板法：对已知物体预先定义若干 $\,{}^{O}T_{G}$，运行时用 object pose 将模板变换到机器人坐标系；第二种是几何法：从点云中估计主轴、法线、局部宽度和可接触区域，再构造夹爪坐标系；第三种是学习法：由网络直接预测抓取候选、抓取质量分数和夹爪宽度。无论候选如何产生，最后都需要回到同一套执行参数：抓取点、接近方向、开合宽度、预抓取偏移和可达性校验。

| 生成方式 | 输入依赖 | 优势 | 风险 |
|---|---|---|---|
| 抓取模板 | CAD / 物体坐标系 / 物体位姿 | 可解释、重复性好 | 依赖已知物体和准确位姿 |
| 点云几何 | 目标点云、法线、包围盒、主轴 | 不强依赖类别，适合规则物体 | 对遮挡和噪声敏感 |
| 学习预测 | RGB-D / 点云 / 示教数据 | 可处理复杂形状和多候选 | 需要数据，候选仍需几何校验 |

**本节小结：** 一个完整抓取候选不是单个空间点，也不只是一个 $SE(3)$ 位姿，而是一组相互约束的执行参数。抓取点决定夹爪到哪里，接近方向决定从哪条路径进入，姿态匹配决定手指如何对齐，开合宽度决定能否包住目标，安全偏移决定接近过程是否留有缓冲。任何一个要素定义不清，都会把看似合理的几何候选变成真机上的碰撞、夹偏或闭合失败。只有这些要素共同成立，并且经过坐标转换和可达性校验，抓取候选才会变成可规划、可接近、可闭合的末端目标。

### 5.3 典型抓取场景的位姿生成逻辑：顶部垂直接近 vs 侧面姿态匹配

桌面操作中最常见的两类构型是顶部抓取（top grasp）与侧向抓取（side grasp）。二者的区别主要体现在接近方向、姿态约束和环境碰撞条件上。

在桌面场景里，系统通常会先尝试最简单的顶部抓取：从上方下来，夹住物体，再向上抬起。如果目标较高、上方被遮挡、物体靠近货架或墙面，顶部路径就可能不可行，此时才需要考虑侧向抓取。这个决策顺序本身也是一种工程取舍：先用约束更少、风险更低的构型；当环境不允许时，再使用对姿态精度要求更高的构型。

#### 5.3.1 桌面顶部抓取：垂直接近范式

| 构型 | 接近方向 | 姿态约束 | 适合对象 | 主要风险 |
|---|---|---|---|---|
| 顶部抓取 | 沿桌面法线向下 | 夹爪开合方向通常与物体长轴对齐 | 盒体、书本、手机、低矮工件 | 上方空间不足、薄物体难夹 |
| 侧向抓取 | 沿物体侧面法线或水平方向 | 夹爪开合平面需贴合目标侧面 | 杯、瓶、细高物体、货架物体 | 易撞桌面 / 隔板，姿态误差放大 |

顶部抓取的优势是结构简单、碰撞风险较低，通常只需准确估计目标平面位置、顶部高度和开合方向。对于规则块状物体，抓取点可取目标点云在水平面的几何中心，接近方向取桌面法线的反方向，预抓取位姿位于目标上方。它对物体绕竖直轴的旋转误差相对不敏感，因此常被用作观测退化时的保守降级策略。

#### 5.3.2 侧面抓取：水平接近与姿态匹配

侧向抓取更依赖姿态估计和局部几何。夹爪需要从目标侧面进入，接近方向与侧面法线相关，开合方向要与可夹持区域的主方向匹配。它的优势是能处理细高物体、货架物体和上方空间受限场景；风险在于姿态误差会被夹爪长度和接近距离放大。若姿态误差为 $\theta$，指尖处的横向偏移近似为：

$$
\Delta x \approx L \tan \theta
$$

其中 $L$ 是夹爪指尖到 TCP 或接触区域的有效距离。以 $L=0.3\,\text{m}$、$\theta=5^{\circ}$ 为例，横向偏移约为 $26\,\text{mm}$，足以导致侧向抓取从“夹持”变成“顶撞”。因此，侧向抓取通常需要更可靠的点云质量、位姿精化和碰撞检查。

#### 5.3.3 预抓取位姿与安全接近路径设计

执行时，抓取动作通常拆为三段：`pre-grasp → grasp → retreat / lift`。这种分段并非形式化流程，而是为了将长距离运动、低速接触和撤离验证分开处理。

| 阶段 | 顶部抓取 | 侧向抓取 |
|---|---|---|
| Pre-grasp | 位于目标上方，夹爪张开 | 位于目标侧面外侧，夹爪张开 |
| Grasp | 沿竖直方向下降并闭合 | 沿水平方向进入并闭合 |
| Retreat / lift | 垂直抬升，验证负载 | 先沿接近反方向退出，再按可行方向抬升 |

这三段动作也对应不同的误差容忍度。到达 pre-grasp 时允许较大的路径规划余量，因为夹爪尚未接触物体；从 pre-grasp 到 grasp 的最后一段运动必须低速、短距离、方向明确，因为此时深度误差和姿态误差会直接转化为碰撞或夹空；retreat / lift 阶段则用于验证抓取是否成功，并让物体离开桌面或狭窄空间。MoveIt 等规划框架中的 `pre_grasp_approach`、`post_grasp_retreat`、`grasp_pose` 等字段，本质上就是对这三段动作的结构化描述。

**本节小结：** 顶部抓取适合开阔桌面和规则低矮物体，它的优点是约束简单、姿态要求较低、失败风险相对可控；侧向抓取适合细高物体、侧面接触和空间受限场景，但对物体姿态估计、夹爪对齐和避碰规划要求更高。两种抓取范式不是谁替代谁，而是对应不同几何条件和任务目标的策略选择。无论采用哪种构型，都应通过 `pre-grasp → grasp → retreat` 将接近、接触和撤离分开处理。这个三段式结构，是把视觉误差、标定误差和运动误差限制在可控范围内的基本工程手段。

### 5.4 坐标系转换链路：从相机坐标系到机器人基座坐标系

视觉模块通常输出相机坐标系下的点、点云或位姿；运动控制模块需要机器人基座坐标系下的夹爪目标。因此，抓取位姿生成必须显式经过坐标变换链路，并清楚区分 Eye-to-Hand 与 Eye-in-Hand 两种拓扑。

这是从“算得出来”到“机器人动得对”的关键一步。视觉算法说“目标在相机前方 0.6 米、右侧 0.1 米”，机械臂控制器并不能直接使用这句话；它需要知道这个目标在机器人基座坐标系下的位置和姿态。手眼标定的作用，就是把相机看到的空间和机器人能运动的空间对齐。如果这一步错了，前面的检测、分割、点云和位姿都可能看起来正确，但机械臂一执行就会整体偏到另一边。

#### 5.4.1 完整的坐标转换依赖关系

从像素到执行目标，一条典型链路包含以下变换：

| 变换项 | 来源 | 用途 |
|---|---|---|
| $K$ | 相机内参标定 | 像素与深度到相机三维点的恢复 |
| $\,{}^{E}T_{C}$ | Eye-in-Hand 手眼标定 | 相机系到末端系变换 |
| $\,{}^{B}T_{C}$ | Eye-to-Hand 手眼标定 | 相机系到基座系变换 |
| $\,{}^{B}T_{E}$ | 机器人正运动学 | 末端系到基座系变换 |
| $\,{}^{E}T_{TCP}$ | 工具标定 | 法兰 / 末端到夹爪 TCP 的固定偏置 |

坐标变换错误常见于两个层面：一是矩阵方向写反，例如把 $\,{}^{B}T_{C}$ 当成 $\,{}^{C}T_{B}$ 使用；二是忽略 TCP 偏置，导致机械臂法兰到位但夹爪中心未到位。真机部署中，应将每个变换矩阵的“从哪个坐标系到哪个坐标系”写入变量名或文档，避免只用 `T`、`R`、`t` 这类模糊命名。

一个实用的写法是始终使用“左上标表示目标坐标系，右下标表示源坐标系”的约定：$\,{}^{B}T_{C}$ 表示把相机系中的点变换到基座系，$\,{}^{E}T_{C}$ 表示把相机系中的点变换到末端系。若要把点 $\mathbf{p}_{C}$ 变到基座系，应写作 $\mathbf{p}_{B} = {}^{B}T_{C}\mathbf{p}_{C}$。这种记号看似繁琐，但能显著减少矩阵连乘方向错误。

#### 5.4.2 眼在手上（Eye-in-Hand）与眼在手外（Eye-to-Hand）的物理拓扑差异

Eye-to-Hand 中，相机固定在工作空间外，待求外参通常为 $\,{}^{B}T_{C}$。相机观测到的抓取位姿可直接通过固定外参映射到基座系：

$$
{}^{B}T_{G} = {}^{B}T_{C} \, {}^{C}T_{G}
$$

![图6.13 Eye-to-Hand 拓扑：相机固定于工作空间外，标定目标通常随机械臂末端运动，目标是求解相机到机器人基座的固定变换](../../assets/figures/lecture06/图6.13.jpg){width=75%}

图 6.13 对应的是“眼在手外”。相机像一个固定观察员，从工作空间外持续看着桌面和机械臂。它的优势是视野稳定、容易观察全局，适合桌面分拣、上下料和多个目标的排序选择；缺点是目标可能被机械臂本体遮挡，且相机距离目标较远时，深度噪声和标定误差会更明显。

Eye-in-Hand 中，相机安装在末端并随机械臂运动，待求外参通常为 $\,{}^{E}T_{C}$。运行时必须结合当前末端位姿：

$$
{}^{B}T_{G} = {}^{B}T_{E} \, {}^{E}T_{C} \, {}^{C}T_{G}
$$

![图6.14 Eye-in-Hand 拓扑：相机刚性安装在末端执行器附近，运行时需结合机器人正运动学与手眼外参完成坐标转换](../../assets/figures/lecture06/图6.14.jpg){width=75%}

图 6.14 对应的是“眼在手上”。相机随着夹爪运动，机器人可以把相机移动到目标附近做近距离复检，因此适合精细装配、局部对位和遮挡较多的场景。代价是采集图像需要机械臂先移动到合适位置，循环时间更长；相机安装在末端还会带来负载、布线和碰撞规避问题。

| 拓扑 | 固定对象 | 运动对象 | 待求外参 | 运行时变换形式 |
|---|---|---|---|---|
| Eye-to-Hand | 相机固定于工作区外 | 标定板或目标随机械臂运动 | $\,{}^{B}T_{C}$ | $\,{}^{B}T_{G} = {}^{B}T_{C} {}^{C}T_{G}$ |
| Eye-in-Hand | 相机固定于末端 | 相机随机械臂运动 | $\,{}^{E}T_{C}$ | $\,{}^{B}T_{G} = {}^{B}T_{E} {}^{E}T_{C} {}^{C}T_{G}$ |

#### 5.4.3 手眼标定的数学本质：求解 $AX=XB$ 方程

手眼标定的目标，是基于多组机器人运动与相机观测求解一个固定外参矩阵 $X$：

$$
AX = XB
$$

| 符号 | 含义 |
|---|---|
| $A$ | 机器人侧相邻两次采样之间的相对运动 |
| $B$ | 相机侧相邻两次观测之间的相对运动 |
| $X$ | 待求的固定手眼外参 |

该方程依赖的是相对运动关系，而非单次绝对位姿。采样过程是否覆盖足够的平移和旋转激励、标定板观测是否稳定、矩阵方向是否统一，往往比具体调用哪个求解接口更重要。若采样姿态变化过小，或所有位姿近似共面，求得的 $X$ 可能数值上收敛但物理上不可用。

OpenCV 的 `calibrateHandEye()` 提供了 Tsai-Lenz、Park-Martin、Horaud、Andreff、Daniilidis 等多种求解方法 [8]。工程上不应把“换求解器”作为第一反应：如果样本激励不足、机器人位姿方向写反、`T_cam_board` 来自错误 marker 尺寸，那么不同方法只是在同一批错误数据上给出不同数值。更可靠的流程是先检查输入矩阵方向和样本分布，再比较不同求解器的一致性。

采样时应避免只在一个小区域内平移机械臂，也不要让相机始终以几乎相同的角度观察标定板。更可靠的做法是覆盖工作空间内多个位置，并让末端姿态产生足够的 roll、pitch、yaw 变化。标定完成后，不应只检查算法返回的均方误差，还应做点位复现：选择相机视野中的一个已知点，经外参变换到机器人基座系，再让机械臂移动到该点附近观察是否吻合。这个验证步骤往往比单看矩阵数值更能发现方向、单位和 TCP 错误。

#### 5.4.4 眼在手上实操和代码入口

Eye-in-Hand 的物理关系可以这样理解：相机固定在末端执行器上，机械臂每运动到一个新姿态，相机也随之改变观察角度；若标定板在世界中保持相对静止，那么每一组样本都应满足同一条坐标链：

$$
{}^{B}T_{\text{board}} = {}^{B}T_{E}\,{}^{E}T_{C}\,{}^{C}T_{\text{board}}
$$

其中 $\,{}^{E}T_{C}$ 就是要求解的 `T_end_camera`。对应代码位于 [Hand-eye calibration 目录](../../code/lecture06/Hand-eye%20calibration/)：教学 demo 默认使用合成数据，从 `T_base_end` 和 `T_cam_board` 生成一组可复现实验样本；真实机器人实验时，则把这两个 JSON 换成实采数据。完整流程与第 3.4.4 节的点云 demo 类似，都是先准备输入，再一键运行脚本，最后查看输出报告。

#### 5.4.5 眼在手外实操和代码入口

Eye-to-Hand 的核心是求解 $\,{}^{B}T_{C}$ / `T_base_camera`，即固定相机到机器人基座的外参。和 Eye-in-Hand 相比，Eye-to-Hand 的相机不再随机械臂运动，运动的是末端上的标定板或被末端夹持的刚性目标。因此，它的闭环关系更适合写成：

$$
{}^{B}T_{E}\,{}^{E}T_{\text{board}} = {}^{B}T_{C}\,{}^{C}T_{\text{board}}
$$

这里 $\,{}^{E}T_{\text{board}}$ 在采样过程中保持固定，要求解的是 $\,{}^{B}T_C$。两种拓扑可以使用同一批输入格式：机器人侧记录 `T_base_end`，相机侧记录 `T_cam_board`；区别在于构造 $AX=XB$ 相对运动时，Eye-to-Hand 需要对机器人侧运动做方向改写。代码入口仍位于 [Hand-eye calibration 目录](../../code/lecture06/Hand-eye%20calibration/)，但一键命令需要把 `--topology` 切换为 `eye_to_hand`。

Eye-to-Hand 的验证重点不是“标定板在基座系中不动”，而是“标定板在末端坐标系中不动”。因此 `validate_hand_eye.py` 读取 `eye_to_hand.json` 后，会根据其中的 `topology` 字段自动选择验证链路，反推出每个样本的 `T_end_board`，再统计它们相对于平均参考变换的平移和旋转残差。真实标定时，可用 `pipeline_hand_eye_demo.py --topology eye_to_hand --demo-dir 你的数据目录 --skip-generate` 直接复用实采 `robot_poses.json` 和 `camera_poses.json`。若残差呈现随末端位置变化而系统性增大，通常应优先检查相机外参方向、机器人基座坐标定义和相机内参；若只有少数样本异常，则更可能是某几张图的 marker 检测、机器人姿态记录或样本配对出现问题。

#### 5.4.6 真机部署中的标定误差排查

| 误差来源 | 典型表现 | 优先检查项 |
|---|---|---|
| 相机内参偏差 | 点云尺度异常、边缘畸变明显 | $f_x,f_y,c_x,c_y$、畸变模型 |
| 深度尺度错误 | Z 向整体放大或缩小 | `depth_scale`、单位换算 |
| 手眼旋转误差 | 距离越远偏差越大 | 姿态激励是否充分、矩阵方向是否统一 |
| 机器人位姿解析错误 | 标定矩阵数值正常但复现失败 | 欧拉角顺序、四元数顺序、角度单位 |
| TCP 偏置遗漏 | 法兰到位但夹爪中心不对 | $\,{}^{E}T_{TCP}$、工具坐标设定 |

旋转误差的任务影响应按具体坐标链路分析。若某个模型点或接触点相对旋转中心的距离为 $r$，小角度误差为 $\theta$，该点的位移量级约为 $r\theta$；这里的 $r$ 是点到相关旋转中心的几何杠杆臂，而不是物体到机器人基座的距离。因此，手眼标定验证不能只看平移残差，还必须检查旋转残差、点位复现误差以及抓取接触点处的实际偏差。

**本节小结：** 坐标系转换是视觉结果进入机器人控制系统的最后一道几何关口。Eye-in-Hand 与 Eye-to-Hand 的输入数据形式看起来相似，都是机器人位姿配相机观测，但固定对象、运动对象、外参含义和验证链路完全不同。工程实现中最容易出错的不是公式本身，而是矩阵方向、乘法顺序、TCP 偏置和“谁相对谁运动”的拓扑理解。只要这些关系写反，前端感知再准确，也会在执行阶段表现为稳定而危险的系统性偏差。因此，手眼标定结果必须通过点位复现、姿态复现和抓取前的坐标链路检查共同验证。

### 5.5 可达性校验：由几何可行到机械可行

即使 $\,{}^{B}T_{G}$ 已经计算完成，也不能直接下发执行。几何上合理的抓取目标不一定满足机械臂的工作空间、关节限位、逆运动学和碰撞约束。抓取候选需要经过从粗到细的可达性筛选。

这一节要强调的是：抓取位姿“算出来”不等于“机械臂能做到”。有些目标点在相机看来很合理，但超出了机械臂工作空间；有些位置能够到达，但要求夹爪以一个机械臂无法实现的姿态进入；还有些位姿本身可达，但从当前位置过去的路径会撞到桌面或旁边物体。因此，抓取候选必须先经过可达性校验，再进入运动规划和执行。

| 检查项 | 目的 | 失败时的典型处理 |
|---|---|---|
| 工作空间判断 | 判断目标位置是否在机械臂可达范围内 | 丢弃候选或更换目标点 |
| IK 可解性 | 判断是否存在满足目标姿态的关节解 | 更换抓取方向、放宽姿态或调整 pre-grasp |
| 关节限位 | 防止接近奇异位形或超出机构范围 | 选择另一组 IK 解或重新排序候选 |
| 碰撞检查 | 避免与桌面、环境、本体和邻物碰撞 | 修改接近方向、提高过渡点、增加安全偏移 |
| 夹爪行程 | 判断局部尺寸是否落在夹爪开口范围内 | 更换抓取部位或放弃抓取 |
| 路径连续性 | 确保 pre-grasp → grasp → retreat 可顺序执行 | 分段规划或插入中间位姿 |

可达性校验应按顺序执行：先剔除明显超出工作空间的候选，再求解 IK，最后做碰撞和路径检查。这样可以减少规划器负担，也便于定位失败原因。对教学系统而言，建议将每个候选的失败原因显式记录为 `workspace_fail`、`ik_fail`、`collision_fail` 或 `gripper_fail`，避免调试时只看到笼统的 planning failed。

在多候选抓取中，可达性校验还承担排序作用。系统可以先生成多个抓取候选，再按照抓取质量、接近路径长度、IK 解裕量、碰撞距离和夹爪开口余量进行打分。最终被执行的候选，不一定是视觉评分最高的候选，而是综合几何稳定性和机械可行性后最可靠的候选。这样的排序机制能显著降低单一位姿估计误差对最终抓取的影响。

**本节小结：** 可达性校验把“几何上合理”的抓取候选进一步筛成“机械上可执行”的目标。工作空间判断、IK、关节限位、碰撞检测和夹爪行程检查应按由粗到细的顺序执行，这样既减少规划器负担，也便于定位失败原因。可达性失败并不一定说明位姿估计错误，也可能来自机械臂构型、障碍物布局、TCP 定义或夹爪行程不足。真实系统中，记录 `workspace_fail`、`ik_fail`、`collision_fail`、`width_fail` 等失败标签，往往比只看到一句 planning failed 更有调试价值，也能指导后续候选排序和策略降级。

### 5.6 观测退化下的策略降级

真实场景中，6D 位姿估计可能因遮挡、反光、透明材质、低纹理或点云过稀而失效。此时系统不应继续使用低置信度姿态结果，而应根据当前可用观测信息切换到更低信息需求的策略。

降级策略可以理解为机器人系统的保守执行模式。当完整 6D 位姿可靠时，应优先使用姿态匹配抓取；但如果只剩下一个稳定的 3D 中心点，就不应构造缺乏依据的旋转姿态并直接执行。更稳妥的做法，是承认当前信息不足，退回到对姿态要求较低的顶部抓取，或者重新观测。对真实机器人来说，拒绝一次低置信度抓取通常比错误执行一次更安全。

| 当前可用信息 | 建议策略 | 适用条件 | 主要限制 |
|---|---|---|---|
| 6D pose 可靠 | 姿态匹配抓取 | 已知物体、点云完整、配准误差低 | 依赖姿态置信度与标定精度 |
| 3D 中心可靠 | 顶部垂直接近 | 桌面开阔、目标低矮、姿态不关键 | 不适合细长、偏心或易滚动物体 |
| 仅 bbox / mask 可靠 | 重新观测、近距离复检或再分割 | 深度质量不足、遮挡较重 | 需要额外时间和运动 |
| 多次复检仍失败 | 放弃执行或请求人工确认 | 安全风险高、目标不可达 | 任务中断，但避免错误执行 |

降级策略的核心，是把“精确但不可靠”的高维估计，替换为“粗糙但可验证”的低维控制目标。例如，当物体姿态不可信但目标点云中心稳定时，可以退回到基于 3D 中心的顶部抓取：接近方向固定为桌面法线方向，夹爪姿态取默认水平姿态，开合宽度由点云包围盒估计，随后仍执行可达性和碰撞检查。

触发降级的常见条件包括：位姿置信度低于阈值、配准残差过大、位姿在连续帧间跳变、有效深度像素比例过低、IK 或碰撞检查连续失败。降级不是为了保证高成功率，而是为了避免系统在感知不充分时输出看似精确、实则危险的动作。

降级策略也应当分层，而不是只有“执行 / 不执行”两种状态。若只是旋转不可靠，可以保留 3D 中心并使用顶部抓取；若深度点云也不可靠，可以移动腕部相机或改变视角重新采集；若多次重感知仍失败，则应放弃该目标或请求人工确认。对于面向真实硬件的系统，这种保守决策是安全设计的一部分。

**本节小结：** 抓取位姿生成是从物体状态表征到机器人动作表征的转换层。它不仅要从物体位姿推导夹爪的抓取点、接近方向与开合宽度，还要通过手眼标定和 TCP 修正完成坐标转换，并经过 IK、碰撞、夹爪行程与策略降级机制筛选。当 6D 位姿可靠时，系统可以使用姿态匹配抓取；当姿态信息不稳定时，则应退回到中心点、顶部抓取或重感知等更保守策略。到这一步，视觉输出才真正被翻译成真实机器人可以尝试执行的抓取目标，也才进入运动规划和执行闭环的责任范围。

## 6 感知失败分析与鲁棒性优化

在实验室理想环境下，6D 位姿估计算法往往能在标准数据集上达到很高的精度指标，但部署到真实物理场景后，遮挡堆叠、材质反光、标定误差、环境光照扰动等因素都会导致感知失效，直接拉低实际抓取成功率。感知失败并非单一环节的问题，而是贯穿从图像采集、坐标变换到位姿输出的完整链路。

本章系统梳理真实场景中典型感知失败的场景与底层成因，量化不同类型误差对抓取结果的影响程度，并从视觉输入层、位姿计算层、系统机制层三个维度给出可落地的优化方案，最终形成一套标准化的真机调试流程，帮助开发者将算法从 “实验室可用” 推进到 “工业级稳定”。

## 6\.1 典型感知失败场景与成因

感知失败按照产生的链路环节可分为三大类：视觉类失败发生在数据输入前端，源于传感器与环境的不匹配；几何类失败发生在 2D\-3D 转换与坐标变换环节，源于标定误差与坐标系定义问题；位姿类失败发生在输出端，源于算法本身的歧义性与运动学约束脱节。

### 6\.1\.1 视觉类失败：遮挡、反光、低纹理与光照剧变



视觉类失败是最常见的前端失效模式，直接导致后续所有几何计算的输入质量下降，是真实场景中抓取失败的首要诱因。

#### 1\. 遮挡与堆叠

- 现象：目标物体被其他物体遮挡 30% 以上，或处于多层堆叠状态，仅部分表面可见；点云呈现大面积残缺，仅能观测到物体顶面或局部侧面。

- 成因：料箱拣选、桌面杂乱堆放等场景中，物体相互遮挡，完整几何特征不可见；堆叠状态下下层物体的边缘与轮廓被上层物体覆盖。

- 影响机制：点云不完整导致 ICP 配准缺少足够的几何约束，算法易收敛到错误的局部最优解，表现为位姿漂移、旋转角错误，甚至完全求解失败。通常遮挡比例超过 50% 时，单视角位姿估计的准确率会下降到 30% 以下。

#### 2\. 反光与透明材质

- 现象：金属零件、玻璃容器、光亮塑料包装等物体表面出现大面积高光，深度图对应区域出现空洞、飞点（距离值远大于真实值）或随机噪声；RGB 图像对应区域过曝，丢失纹理细节。

- 成因：主动光深度相机的红外光线被镜面反射或穿透，无法按正常路径返回传感器：结构光相机因散斑无法正常成像形成空洞，ToF 相机因多次反射导致飞行时间计算错误产生飞点。

- 影响：目标点云残缺不全，配准算法失去有效对应点，位姿估计结果严重偏离真值；极端情况下目标点云有效点数不足 10%，位姿求解完全失效。

#### 3\. 低纹理 / 无纹理物体

- 现象：纯色陶瓷、哑光塑料、光滑金属等物体表面缺少明显纹理特征，基于 RGB 特征的检测与位姿算法输出结果不稳定。

- 成因：基于特征点匹配的算法无法提取足够多的稳定关键点，模板匹配也缺少区分度，几何上多个姿态的观测特征高度相似。

- 影响：位姿估计出现旋转歧义，姿态结果随机跳动，重复定位精度大幅下降；连续多帧输出的旋转角度波动可达 ±20°，无法用于稳定抓取。

#### 4\. 光照剧变

- 现象：强光直射、逆光、强阴影导致 RGB 图像过曝或过暗，目标与背景对比度急剧下降，目标检测器出现大面积漏检或误检。

- 成因：环境光照超出传感器动态范围，图像特征分布与训练数据产生显著差异，深度学习模型的特征提取能力退化。

- 影响：目标检测漏检、误检，实例分割轮廓偏移，后续所有环节连锁失效，属于前端输入级的整体失效。

### 6\.1\.2 几何类失败：深度空洞、外参偏差与坐标系错误



几何类失败的本质是 “空间换算出错”—— 即使视觉检测完全正确，二维到三维的映射或坐标系转换出现偏差，最终输出的位姿也会偏离真实位置。这类误差通常具有系统性，隐蔽性强。

#### 1\. 深度缺失与点云空洞

- 现象：目标物体的点云存在大面积空缺，尤其是边缘、大角度斜面和高反光区域；物体边缘出现拖尾、飞点等噪声。

- 成因：物体表面法线与相机光轴夹角过大（通常超过 60°）时，深度回波信号信噪比急剧下降；黑色吸光材质、透明材质会导致深度无返回值；传感器本身的测量盲区也会产生边缘空洞。

- 影响：点云无法完整描述物体形状，ICP 配准易陷入局部最优，位姿的平移与旋转均出现系统性偏差；空洞集中在物体一侧时，会导致位姿向点云完整的一侧偏移。

#### 2\. 手眼外参偏差

- 现象：所有抓取结果都呈现固定方向、固定大小的系统性偏移，偏差量不随物体位置改变而改变方向，仅随距离线性放大。

- 成因：手眼标定样本分布不均、标定板精度不足、相机安装发生松动或碰撞，导致手眼变换矩阵存在固定的平移与旋转误差。

- 影响：这是最隐蔽的系统性误差 —— 单看位姿估计本身结果稳定、重复性好，但转换到机器人坐标系后全部偏位；若不做标定验证，很容易误判为位姿估计算法精度不足。

#### 3\. 坐标系方向定义错误

- 现象：抓取位姿出现镜像翻转、坐标轴方向颠倒，物体姿态完全相反，或出现量级级的位置偏差。

- 成因：不同算法库的坐标系约定不一致，例如 OpenCV 相机系（Z 轴朝前、Y 轴朝下）与 OpenGL 相机系（Z 轴朝后、Y 轴朝上）的镜像差异；变换矩阵乘法顺序错误（左乘 / 右乘混淆）；空间单位不统一（毫米 / 米混用）导致 1000 倍的量级偏差。

- 影响：位姿结果完全不可用，直接导致撞机或抓空，属于必须优先排除的基础错误，也是新手部署时最常踩的坑。

### 6\.1\.3 位姿类失败：位姿跳变、方向翻转与目标不可达



- 。

位姿类失败发生在输出环节，算法本身给出了数值结果，但结果不稳定、存在歧义或不可被执行系统直接使用。

#### 1\. 位姿跳变

- 现象：连续采集的多帧静态图像中，估计出的位姿没有平滑变化，而是出现无规律的突变跳动，平移跳变量可达厘米级，旋转跳变可达数十度。

- 成因：单帧点云噪声大、特征不稳定，ICP 算法每次收敛到不同的局部最优解；低纹理物体缺少足够的几何约束，解空间存在多个局部极小值。

- 影响：机械臂末端跟随位姿剧烈抖动，无法平稳接近物体，甚至在运动过程中碰撞环境；连续抓取的一致性极差，成功率波动剧烈。

#### 2\. 方向翻转（对称歧义）

- 现象：旋转对称物体（如圆柱体、正立方体、螺栓）的位姿出现 180° 或 90° 的随机翻转，平移分量正确但朝向完全错误，多次重复测量结果随机跳变。

- 成因：物体本身存在旋转对称性，几何上多个姿态对应的点云观测完全等价，算法无法区分，会随机输出一个合法解。

- 影响：夹爪开合方向与物体长轴错位，无法形成有效夹持，抓取成功率骤降；对于需要精确朝向的装配任务，方向翻转会直接导致任务失败。

#### 3\. 目标不可达

- 现象：位姿估计本身数值正确，但生成的抓取位姿超出机械臂工作范围，或接近路径存在碰撞，运动规划器直接报错无解。

- 成因：位姿估计模块未考虑机械臂运动学约束，抓取点选在工作空间边缘；接近方向被障碍物或工作台阻挡；夹爪姿态超出腕部关节限位。

- 影响：感知输出的位姿无法被执行，感知与规划环节脱节，看似正确的感知结果实际没有工程价值。

### 本节小结

三类失败分别对应感知链路的不同阶段：视觉类失败是 “输入坏了”，发生在最前端；几何类失败是 “换算错了”，发生在坐标变换中间环节；位姿类失败是 “输出不稳 / 不可用”，发生在最终结果端。真机排查时可按 “前端输入→几何转换→输出结果” 的顺序逐级定位，能快速锁定问题根源，避免盲目调参。

## 6\.2 感知误差对抓取成功率的影响量化

不同类型的感知误差对抓取结果的破坏程度并不相同。量化误差与成功率的对应关系，有助于设定合理的精度指标、判断误差来源，以及评估优化效果。

### 6\.2\.1 平移误差：从毫米级偏差到厘米级失效

平移误差指估计出的物体质心位置与真实位置的欧氏距离偏差，是最直观的误差形式，主要影响夹爪与物体的横向对准。

对于两指平行夹爪，平移容错量与夹爪开口宽度、物体宽度直接相关，近似满足：

$e_{t,\text{max}} \approx \frac{w_{\text{gripper}} - w_{\text{object}}}{2}$ 

其中$w_{\text{gripper}}$为夹爪开口宽度，$w_{\text{object}}$为物体夹持处的宽度。当物体宽度远小于夹爪开口时，容错空间更大，反之则对平移精度要求极高。

按照误差量级对抓取成功率的影响，可分为四个等级：

1. 1\-3mm 轻微偏差：对平行夹爪抓取几乎无影响，夹持位置略有偏移但仍能形成稳定夹持，成功率接近 100%；仅对高精度装配任务有影响。

2. 3\-5mm 中度偏差：夹持位置偏离最佳受力点，物体受力不均，抓取成功率下降至 70%\-90%；表面光滑的物体易在提升过程中滑落。

3. 5\-10mm 较大偏差：夹爪仅能夹住物体边缘，或部分手指落空，抓取成功率降至 30%\-50%；夹爪接近时易碰倒物体。

4. 10mm 以上（厘米级）严重偏差：夹爪大概率完全错过物体，直接抓空，或撞击物体导致其移位，抓取成功率低于 20%，基本失效。

平移误差的主要来源是点云提取偏差、深度噪声与标定误差，它是抓取系统最基础的精度指标。

### 6\.2\.2 旋转误差：角度偏差的空间放大效应

旋转误差指估计姿态与真实姿态的角度差，其最核心的特点是误差会随操作距离被空间放大 —— 离旋转中心越远，同样的角度偏差造成的末端位置偏移越大。这一特性使得旋转误差对长臂展机器人的影响远大于桌面机械臂。

### 图 6\-3 旋转误差空间放大效应示意图

![image\.png](../../assets/figures/lecture06/image%206_3.png)

旋转误差的放大效应满足几何关系：

$\Delta d = L \cdot \tan\theta$ 

其中：

- $\Delta d$为末端位置偏移量；

- L为末端到旋转中心的距离（臂展长度）；

- $\theta$为旋转误差角度（弧度制）。

小角度下（$\theta < 5^\circ$），$\tan\theta \approx \theta$，偏移量与角度近似成正比。例如在 1 米臂展处，1° 的旋转误差会带来约 17\.5mm 的位置偏移；5° 的旋转误差则会带来约 87mm 的偏移，足以让夹爪完全错过物体。

按照误差量级对抓取成功率的影响，可分为四个等级：

1. 2° 以内：平行夹爪可完全容忍，夹持面仍能有效接触物体，抓取稳定性不受明显影响。

2. 2°\-5°：夹爪与物体的接触面积减小，摩擦力下降，抓取成功率降至 60%\-80%；提升物体时易倾斜滑落。

3. 5°\-15°：夹爪以侧面接触物体，无法形成有效夹持面，抓取力大幅衰减，成功率通常低于 30%。

4. 15° 以上：夹爪端面直接撞向物体侧面，无法形成夹持动作，抓取基本失败，甚至可能损坏物体或夹爪。

正因旋转误差存在空间放大效应，位姿估计的旋转精度往往比平移精度更重要，也是真机调试的重点优化对象。

### 6\.2\.3 深度误差：接近方向的致命影响

深度误差是沿夹爪接近方向的平移误差，它比平面内的平移误差更致命 —— 夹爪在接近方向上几乎没有容错空间，偏差直接决定 “抓不到” 还是 “撞上去”。

深度误差的特殊性在于：夹爪沿接近方向运动时，在接触物体前通常没有力觉反馈，属于开环运动，深度偏差会直接导致夹爪停止位置错误。对于吸盘式末端，深度误差的容忍度更低，通常要求 ±2mm 以内，否则无法形成有效密封负压。

按照误差量级对抓取成功率的影响，可分为四个等级：

1. 1\-2mm 轻微偏差：无明显影响，夹爪闭合后仍能稳定夹持。

2. 3\-5mm 中度偏差：夹持深度不足，物体仅被夹住前端一小部分，搬运过程中易脱落；或夹爪深入过多，顶推物体导致移位。

3. 5\-10mm 较大偏差：要么夹爪没够到物体、完全抓空，要么夹爪撞击物体表面，将物体推走。

4. 10mm 以上 严重偏差：几乎 100% 出现抓空或撞物，抓取完全失败，甚至存在撞坏传感器或工作台的风险。

### 本节小结

三类误差对抓取的影响各有特点：平移误差影响横向对准，误差与成功率近似线性下降；旋转误差存在空间放大效应，长臂展场景下危害远大于平移误差；深度误差沿接近方向作用，容错空间最小，最为致命。其中标定误差带来的是系统性偏差，决定了整个系统的精度上限；单帧位姿的随机误差决定了单次抓取的波动范围。

## 6\.3 三类优化方向

针对上述失败场景与误差来源，可从视觉输入层、位姿计算层、系统机制层三个维度分层优化，实现从 “单次准确” 到 “长期稳定” 的鲁棒性提升。三者并非替代关系，而是层层递进、互为补充。

### 6\.3\.1 视觉层面：光照、反光、透明物体的处理



视觉层面的优化目标是提升输入数据质量，从源头减少噪声与缺失，是所有优化的基础。前端输入质量提升带来的收益，远大于后端算法的调优。

#### 1\. 光照环境标准化

- 采用漫射环形补光方案，光源与相机光轴呈 30°\-45° 斜射，避免点光源垂直正射，减少物体表面高光与硬阴影；

- 针对高反光金属零件，搭配同轴光源与偏振镜头，通过偏振片过滤镜面反射光，保留漫反射光，大幅提升深度成像质量；

- 封闭工作空间，隔绝环境光干扰，保证光照条件长期稳定，避免检测分割精度随昼夜、天气波动。

#### 2\. 多模态数据互补

- 融合 RGB、深度、红外三个通道的信息，单一模态失效时其他模态兜底；例如反光物体 RGB 过曝，但红外灰度通道仍能提供有效轮廓，可用于辅助目标定位；

- 针对透明玻璃、塑料等普通深度相机无法测量的物体，补充线激光模组或红外结构光传感器，替代普通 RGB\-D 相机，获取稳定的深度数据；

- 多通道数据做空间对齐与时间同步，保证不同模态的像素级对应。

#### 3\. 图像与深度后处理

- 对实例分割掩膜做形态学开运算（先腐蚀后膨胀）与边缘平滑处理，减少边缘锯齿，降低点云边缘噪声，避免背景像素混入目标点云；

- 对深度图做空洞补全：小范围空洞采用双边滤波保留边缘的同时填充，大面积空洞可使用轻量级深度补全网络修复，提升点云完整性；

- 增加边缘深度滤波，剔除物体边缘的飞点与拖尾噪声，通过统计滤波去除距离均值过远的离群点。

### 6\.3\.2 位姿层面：多帧融合与时序平滑



位姿层面的优化目标是抑制单帧波动、提升绝对精度，让输出的位姿既准又稳，是提升抓取一致性的核心手段。

### 图 6\-6 两阶段粗到精位姿优化流程图

![image\.png](../../assets/figures/lecture06/image%206_6.png)

#### 1\. 时序滤波平滑

- 引入卡尔曼滤波或滑动窗口平均，对连续多帧的位姿结果做时序滤波：平移分量采用线性卡尔曼滤波，旋转分量采用四元数球面线性插值（SLERP），抑制单帧跳变，输出平稳的位姿序列；

- 设置位姿变化阈值，单帧平移变化超过 10mm、旋转变化超过 5° 时判定为异常帧，丢弃该帧并沿用历史平滑结果，避免机械臂跟随异常位姿抖动；

- 对于静态场景，可采用多帧点云累加融合的方式，提升点云密度与完整性，再进行单次位姿求解。

#### 2\. 粗到精的两阶段位姿精修

- 第一阶段粗估计：用深度学习网络输出粗位姿，提供较好的初始值，兼顾泛化性与速度；要求初始平移误差小于物体直径的 20%，旋转误差小于 30°，保证后续 ICP 不陷入局部最优。

- 第二阶段精配准：用点到平面 ICP 做几何精配准，在粗位姿基础上迭代优化，提升位姿绝对精度；点到平面 ICP 的收敛速度比传统点到点 ICP 快 3\-5 倍，且对噪声更鲁棒。

- 这是当前工业界的主流方案，兼顾了深度学习的泛化性与几何方法的高精度，性价比最高。

#### 3\. 多视角融合

- 针对遮挡严重的场景，控制机械臂带动腕部相机移动到 2\-3 个不同角度观测物体，或部署多台固定相机从不同视角采集；

- 融合多视角的位姿估计结果，采用加权平均策略，权重由各视角的点云有效率、配准残差共同决定，配准残差越小、点云越完整的视角权重越高；

- 多视角融合可大幅降低遮挡带来的误差，使严重遮挡场景下的位姿准确率提升 40% 以上。

### 6\.3\.3 系统层面：失败检测与重感知机制



系统层面的优化目标是建立容错兜底机制，即使感知出错，也能避免无效抓取，通过重试与闭环迭代提升整体成功率。这是成本最低、见效最快的优化手段。

#### 1\. 前置失败检测

抓取执行前设置三重校验门槛，任一不达标则判定为感知失败，不执行抓取，避免无效动作与碰撞风险：

- 点云有效率校验：目标点云的有效点数占完整模型点数的比例低于阈值（通常 \< 40%），判定为点云质量不足；

- 位姿置信度校验：ICP 配准的均方根误差（RMSE）大于 2mm，或重投影误差大于 3 像素，判定为位姿不可信；

- 可达性校验：通过运动学逆解验证抓取位姿与预抓取位姿是否存在有效解，且接近路径无碰撞，判定为不可执行。

#### 2\. 重感知重试机制

- 单次感知失败后，系统自动调整策略重新采集，采用分级升级策略：第一次失败仅重新采集单帧计算；第二次失败调整相机曝光、增益与滤波参数；第三次失败控制机械臂移动到侧方视角进行多视角重试；

- 通常设置 2\-3 次重试机会，可在不增加硬件成本的前提下，将整体抓取成功率提升 10%\-20%；

- 设置最大重试次数上限，避免无限循环导致系统卡死。

#### 3\. 失败样本闭环回流

- 自动记录所有失败场景的原始数据（RGB、深度图、位姿结果、失败类型、机器人状态），形成结构化失败样本库；

- 定期将样本标注后用于模型微调或参数优化，形成 “部署 \- 失败 \- 优化” 的闭环迭代机制；典型情况下每月迭代一次，可使场景内成功率持续提升 5%\-10%；

- 这是系统长期稳定性提升的核心机制，也是工业部署与实验室演示的核心区别。

### 本节小结

三个层面的优化各有侧重：视觉层面是 “治本”，提升输入质量，从源头减少错误；位姿层面是 “求精”，提升输出精度与平滑度，让结果更可靠；系统层面是 “兜底”，建立容错与重试机制，保证极端情况下仍能正常工作。三者结合，才能实现从实验室精度到真机鲁棒性的跨越。

## 6\.4 真机部署中的感知调试流程

真机调试切忌一上来就跑全链路抓取，否则出现失败时无法定位是哪个环节出了问题。正确的调试路径遵循先基础后上层、先单步后全链路的原则，逐级验证、逐级排查，可大幅提升调试效率。

### 6\.4\.1 基础校验：标定与坐标系正确性验证



标定与坐标系是所有感知的基础，基础错了，上层算法再准也没用。调试第一步必须先排除系统性误差，这一步跳过后患无穷。

#### 1\. 校验内容

- 相机内参：确认相机内参标定的重投影误差小于 0\.5 像素，畸变校正正确，深度与 RGB 图像的像素对齐误差小于 1 像素；

- 手眼外参：确认手眼标定矩阵的平移与旋转精度，排除固定方向的系统性偏移；

- TCP 工具标定：确认夹爪工具中心点标定准确，无偏心偏差，TCP 误差应小于 0\.5mm；

- 坐标系约定：确认像素坐标系、相机坐标系、机器人基座坐标系的轴方向与单位统一，排除镜像、翻转与量级错误。

#### 2\. 验证方法

固定高精度棋盘格标定板，控制机械臂移动到 5\-8 个覆盖工作空间的不同位姿，分别对比 “视觉计算的标定板位姿” 与 “机器人正运动学计算的位姿”。

- 合格标准：全工作空间内平移误差 RMSE≤2mm，旋转误差 RMSE≤1°。

#### 3\. 常见问题排查

- 固定方向的系统性偏移：优先检查手眼标定与 TCP 标定；

- 镜像 / 翻转错误：优先检查坐标系方向约定与变换矩阵乘法顺序；

- 误差随深度线性变化：优先检查相机内参标定精度；

- 误差随位置变化大：优先检查标定样本是否覆盖了完整工作空间。

### 6\.4\.2 单步验证：检测分割效果与静态位姿精度测试



基础校验通过后，逐个验证每个感知模块的输出质量，确保单模块性能达标，再进行全链路联调。

#### 1\. 检测分割验证

- 固定目标物体，连续采集 20 帧 RGB 图像，统计目标检测的召回率与准确率，工业场景要求召回率≥99\.5%，无漏检、无误检；

- 对比实例分割掩膜与物体真实轮廓，要求边缘平均误差小于 2 像素，无大面积空洞或溢出；

- 改变光照角度、背景复杂度、遮挡程度，验证检测分割的鲁棒性，找出最易失效的边界场景。

#### 2\. 静态位姿精度验证

- 使用标准立方体、标定球等已知尺寸的高精度物体（尺寸精度优于 ±0\.01mm）作为真值基准；

- 连续采集 30 帧数据，对比感知输出的位姿与真值，分别统计平移误差与旋转误差的均值、标准差、最大值；

- 合格参考标准：桌面抓取场景平移误差 RMSE≤3mm，旋转误差 RMSE≤2°；精密装配场景需相应提高要求。

#### 3\. 点云质量验证

- 可视化目标点云，观察完整性、边缘平滑度与噪声水平；

- 调整滤波参数（体素降采样尺寸、统计滤波阈值），在保留几何细节与去除噪声之间找到平衡点；

- 验证不同材质、不同角度下的点云有效率，评估点云质量的边界。

### 6\.4\.3 全链路验证：动态抓取评测与迭代优化

单模块全部达标后，再打通完整抓取链路，进行成功率评测与问题迭代。

#### 1\. 固定场景基准测试

- 同一物体、同一摆放位置与姿态，重复执行 10\-20 次完整抓取，统计基准成功率；

- 对每一次失败进行归因分类：检测失败、分割失败、位姿失败、标定误差、运动规划失败、执行失败；

- 绘制失败原因帕累托图，找到占比最高的失败原因，针对性优先优化，遵循 80/20 法则。

#### 2\. 泛化场景压力测试

- 改变物体的摆放角度、位置、堆叠状态，调整光照条件，测试不同工况下的抓取成功率；

- 评估系统的鲁棒性边界，找出最容易失效的场景，作为后续优化重点；

- 记录每个工况的成功率，形成系统的性能指标手册。

#### 3\. 闭环迭代优化

- 针对占比最高的失败类型，对应优化对应模块：反光失败多就优化补光方案，位姿跳变就加时序滤波，标定不准就重新标定；

- 每轮优化后重新测试成功率，验证优化效果，避免无效调参；

- 持续积累失败样本，定期迭代模型与参数，逐步逼近目标成功率。

### 本节小结

真机感知调试的核心逻辑是 “逐级验证、逐级排查”：先搞定标定与坐标系这个基础，排除系统性误差；再逐个验证检测、分割、位姿等单模块性能；最后做全链路的成功率评测与迭代优化。遵循这个流程，可以避免盲目调参，高效定位并解决问题，快速将系统从 “能跑” 优化到 “稳定好用”。

## 7 位姿估计抓取实战实验与作业解析

前面几节分别讲了检测、分割、深度反投影、点云清洗、6D 位姿、抓取候选和手眼标定。本节把这些内容组织成一次完整实验。实验的目标不是让所有同学都在同一套硬件上完成抓取，而是让每个同学都能交付一条可复现、可检查、可归因的链路：

```text
RGB-D 输入
  -> 目标 mask

```

因此，本节的作业评价重点不是“是否刚好抓起来一次”，而是学生能否讲清楚每个中间量从哪里来、单位是什么、坐标系是什么、失败时应该检查哪一层。有 SO101 真机的同学可以继续做低速执行验证；没有硬件的同学也可以用 Open3D、合成手眼数据和可视化报告完成同等核心能力训练。

### 7.1 有硬件版与无硬件仿真版实验流程

建议把本讲实验分成四个层级。课堂最低要求是 A；想训练交互式感知的同学可以做 B；有 SO101 或等价机械臂的同学可以做 C；希望衔接后续仿真和强化学习内容的同学可以做 D。

| 层级 | 实验版本 | 是否需要硬件 | 核心目标 | 主要证据 |
|---|---|---|---|---|
| A | 基础离线版 | 否 | 跑通 RGB-D + mask 到 clean point cloud，再跑通手眼标定示例 | 终端日志、`.pcd`、阶段截图、summary JSON |
| B | 交互分割版 | 否 | 用交互式 prompt 或 SAM 接口生成 mask，再接入同一条点云流水线 | RGB、prompt、mask overlay、点云输出 |
| C | SO101 真机版 | 是 | 用真实相机和机器人位姿完成手眼转换，并做低速抓取验证 | 标定数据、基座系目标、规划截图、执行记录 |
| D | 仿真扩展版 | 否 | 把抓取候选导入 ManiSkill 或其他仿真环境做可达性 / 碰撞验证 | 仿真场景、候选位姿、成功 / 失败判据 |

这四个版本共享同一条主线：前端感知只负责产生目标区域，点云模块负责把目标区域变成三维几何，位姿或抓取模块负责定义 TCP 应到达的位置和方向，手眼标定负责把相机系结果转换到机器人可执行的坐标系。

#### 7.1.1 有硬件版（SO101）：真机全流程操作步骤

有硬件版不要一开始就追求全自动抓取成功率。更稳妥的做法是先证明数据可信、坐标可信、目标可信，再让机械臂低速执行。推荐按下面顺序完成。

**第一步：采集前检查。** 固定相机安装方式，明确是 Eye-in-Hand 还是 Eye-to-Hand；确认 RGB 与深度图已经对齐；确认相机内参中的 `fx`、`fy`、`cx`、`cy` 与图像分辨率匹配；确认深度单位。如果深度图以毫米保存，`depth_scale` 通常取 `1000.0`；如果相机 SDK 已经输出米，则不能再按毫米缩放。

**第二步：准备目标前景。** 初期可以用人工 mask 或数据集 mask 跑通流程；真机扩展时，可以由 YOLO 给出 bbox，再由 SAM / SAM2 或交互式分割工具输出 mask。无论前端模型如何变化，传给点云流水线的文件都应整理成同一套约定：

```text
rgb.png
depth.png
mask.png
intrinsics.json
```

这个约定很重要。它把“用什么模型分割”与“后端如何做三维几何”解耦，使后续代码不必关心 mask 是人工画的、数据集给的，还是模型预测的。

**第三步：运行点云流水线。** 在 `code/lecture06/Visual_Perception/` 目录下运行：

```bash
python pipeline_from_syllabus.py --demo-dir data/rgbd_object_demo --no-vis
```

脚本会一次性完成掩膜筛选、反投影、直通滤波、统计滤波、体素降采样和点云导出。真机实验中，先检查 `syllabus_masked_depth.png` 是否只保留目标，再检查 `syllabus_target_clean.pcd` 的空间范围是否符合桌面物体的真实尺寸。若一个杯子的点云宽度显示成几米，通常是深度尺度或相机内参错了；若点云只剩零散碎片，通常是 mask 或滤波参数过激。

**第四步：完成手眼标定。** 若相机固定在末端，运行 Eye-in-Hand 链路；若相机固定在工作空间外，运行 Eye-to-Hand 链路：

```bash
cd "code/lecture06/Hand-eye calibration"
python pipeline_hand_eye_demo.py --topology eye_in_hand
python pipeline_hand_eye_demo.py --topology eye_to_hand
```

真实数据接入时，把实采 `robot_poses.json` 和 `camera_poses.json` 放入自己的数据目录，再使用：

```bash
python pipeline_hand_eye_demo.py --topology eye_in_hand --demo-dir 你的数据目录 --skip-generate
```

或：

```bash
python pipeline_hand_eye_demo.py --topology eye_to_hand --demo-dir 你的数据目录 --skip-generate
```

真实数据接入时，重点检查三件事：机器人位姿是否与相机观测一一对应，旋转矩阵或四元数的方向是否使用一致，标定板或目标的坐标系定义是否前后一致。手眼标定结果不是一个孤立矩阵，而是后续所有抓取目标转换的基础。

**第五步：构造抓取候选。** 基础版可以从目标点云中计算包围盒、主轴、顶部中心点或局部平面中心，构造一个保守的顶部抓取候选。进阶版可以接入 GraspNet / 6-DoF GraspNet 类方法生成多个 grasp candidates，再由 IK、碰撞检测和夹爪开口范围筛选 [11]。

**第六步：低速执行前验证。** 不建议第一次就把视觉输出直接交给机械臂执行。应先把候选抓取点转换到机器人基座系，在 RViz / MoveIt 或厂商示教界面中显示目标位姿，确认接近方向、单位、TCP 偏置和安全高度无误后，再低速执行：

```text
pre-grasp -> approach -> close gripper -> lift -> retreat
```

以下情况应禁止直接执行：目标点云空间范围明显异常；手眼标定残差没有记录；TCP 坐标系方向无法解释；抓取候选没有 pre-grasp 安全位姿；规划路径穿过桌面、相机支架或机器人本体。

**本节小结：** 有硬件实验要按“相机数据可信 → 点云可信 → 手眼可信 → 候选抓取可信 → 低速执行”的顺序推进。最危险的做法是直接把视觉输出交给机械臂执行，因为一旦坐标方向、深度尺度或 TCP 偏置写错，前端结果越稳定，后端偏差反而越具有迷惑性。

#### 7.1.2 无硬件仿真版：Open3D 与 ManiSkill 离线实验

无硬件版的目标是完成同样的数据闭环，只是不驱动真实机械臂。基础要求使用 Open3D 完成点云生成、滤波、截图和 `.pcd` 导出；进阶要求可以把干净目标点云和抓取候选导入 ManiSkill 或其他仿真环境进行可视化验证。

基础流程如下：

1. 从 University of Washington RGB-D Object Dataset 下载一组 RGB-D 数据，例如 `https://rgbd-dataset.cs.washington.edu/dataset/rgbd-dataset_full/coffee_mug_1.tar`，按代码目录 README 的说明整理为 `data/rgbd_object_demo/`。作业中应记录下载源和整理命令，不应依赖某台电脑上已有的本地数据。
2. 执行 `pipeline_from_syllabus.py`，得到 `syllabus_target_clean.pcd`、阶段截图和 `syllabus_pipeline_summary.json`。
3. 在 Open3D 中查看目标点云，检查点数、XYZ 范围、体素降采样前后变化是否合理。
4. 使用 `pipeline_hand_eye_demo.py` 跑通 Eye-in-Hand 或 Eye-to-Hand 合成数据，理解 `T_end_camera` 与 `T_base_camera` 的区别。
5. 编写一段简化抓取候选生成说明：例如“顶部抓取候选取点云包围盒中心上方，接近方向沿负 Z，夹爪开口取包围盒短边加安全余量”。

离线版的报告要重点检查以下输出：

| 输出文件或结果 | 说明 | 应检查的问题 |
|---|---|---|
| `syllabus_masked_depth.png` | mask 作用后的深度图 | 是否只保留目标区域，是否混入桌面或遮挡物 |
| `syllabus_target_raw.pcd` | 反投影后的原始目标点云 | 深度尺度是否正确，点云是否在相机前方 |
| `syllabus_target_passthrough.pcd` | 直通滤波后点云 | Z 范围是否误删目标 |
| `syllabus_target_statistical.pcd` | 统计滤波后点云 | 离群点是否减少，主体结构是否保留 |
| `syllabus_target_clean.pcd` | 体素降采样后的最终点云 | 点数是否适中，几何轮廓是否仍可辨认 |
| `syllabus_pipeline_summary.json` | 流水线统计摘要 | 点数变化、XYZ 范围、参数是否可复现 |

进阶仿真版可以把第 5 步生成的候选转成仿真环境中的末端目标位姿。此时 ManiSkill 的角色不是替代感知算法，而是验证候选动作在一个物理环境中是否可达、是否碰撞、是否能完成 grasp / lift。作业中只要说明坐标系映射、动作接口和成功判据即可，不要求所有同学都完成完整仿真控制器。

**本节小结：** 无硬件版不是“弱化版”，而是把真机风险替换成可观察的离线证据。只要能保存输入数据、点云中间结果、手眼标定报告、抓取候选定义和失败分析，就已经覆盖了位姿驱动抓取最核心的工程链路。

### 7.2 核心代码逐层解析：从检测分割到抓取生成

参考第 10 讲 `3.3 代码解析：LeRobot 源码逐层拆解` 的写法，本节不只给命令，而是沿数据流拆解代码。入口脚本负责串流程，数据加载层负责统一格式，算法函数负责单步处理，输出层负责保存可复现证据。读代码时要始终追问三个问题：这一层输入是什么，输出是什么，失败时看哪个中间文件。

#### 7.2.1 检测分割模块：YOLO 检测与 SAM 分割的调用逻辑

当前仓库没有内置 YOLO 权重，也没有绑定具体 SAM2 predictor；它提供的是可替换的分割接口。真实系统中，YOLO 的作用是从 RGB 图中找出目标候选，SAM / SAM2 的作用是把 bbox、点击点或文本提示转成像素级 mask。接口关系可以抽象为：

```python
# 伪代码：真实 YOLO 后端输出 bbox
bbox_xyxy = detector.detect(rgb, text_or_class="coffee_mug")

# SAM / SAM2 或当前 fallback 接口把 bbox 转成 mask
segmentation = segmenter.segment(rgb, box_xyxy=bbox_xyxy)
mask = segmentation.mask
```

对应到仓库代码，交互式入口是 [`interactive_depth_pipeline.py`](../../code/lecture06/Visual_Perception/interactive_depth_pipeline.py)。它做了三层封装：

1. `create_depth_source()`：统一 file、usb、network 三种输入源，使后续代码只面对 RGB-D 帧。
2. `InteractiveMaskSelector`：用点击点或框选区域生成 prompt，降低课堂实验对检测模型权重的依赖。
3. `Sam2Segmenter.segment()`：把 prompt 转成二值 mask。当前实现包含 fallback 逻辑，点提示生成圆形 mask，框提示生成矩形 mask；安装真实 SAM2 后，可以在同一类中补齐 predictor 调用。

这一层的关键不是模型名字，而是输出契约：后续点云模块只需要一个与深度图同尺寸的二值 `mask`。因此，只要 YOLO、Grounding DINO、SAM、人工点击或数据集标注最终能产出同样格式的 mask，就可以接入同一条点云流水线。

调试这一层时，不要只看模型置信度。更可靠的检查是：mask 尺寸是否与深度图一致，前景像素比例是否合理，mask overlay 是否漏掉目标关键部位，是否把桌面、遮挡物或邻近物体一起选进来。前端 mask 的错误会直接变成点云污染，后端滤波通常无法完全补救。

#### 7.2.2 点云处理模块：滤波预处理与目标点云提取

点云主入口是 [`pipeline_from_syllabus.py`](../../code/lecture06/Visual_Perception/pipeline_from_syllabus.py)。它对应课堂 5 步法：

1. `load_depth()` / `load_mask()` / `load_intrinsics()`：加载深度图、mask 和相机内参，并检查尺寸、字段和深度尺度。
2. `step1_mask_filtering()`：执行 `depth × mask`，把非目标像素置零，保存 `syllabus_masked_depth.png`。
3. `step2_backprojection()`：用 Open3D `create_from_depth_image()` 根据内参反投影为相机坐标系下的目标点云。
4. `step3_passthrough()`：用 numpy 布尔切片按 Z 范围做直通滤波，去掉工作空间外点。
5. `step4_denoise_and_downsample()`：先做统计离群点滤波，再做体素降采样。
6. `step5_export()`：导出 `syllabus_target_clean.pcd`，并记录点数和 XYZ 范围。

可以把这个脚本理解为第 6 讲的“最小可复现几何核心”。它的各层输入输出可以整理如下：

| 阶段 | 输入 | 输出 | 主要检查 |
|---|---|---|---|
| 加载数据 | RGB、Depth、mask、intrinsics | numpy 数组与相机参数 | 尺寸一致、深度单位正确 |
| 掩膜筛选 | `depth`、`mask` | masked depth | 前景是否只覆盖目标 |
| 反投影 | masked depth、内参 | camera-frame point cloud | 点云是否在相机前方，尺度是否合理 |
| 直通滤波 | raw point cloud | Z 裁剪后的点云 | 是否去掉工作空间外点 |
| 统计滤波 | 裁剪后点云 | 去飞点点云 | 是否保留主体结构 |
| 体素降采样 | 去飞点点云 | clean point cloud | 点数是否降低，轮廓是否仍可辨认 |
| 导出记录 | clean point cloud | `.pcd`、截图、summary JSON | 是否能支撑报告复现 |

如果某次结果不对，排查顺序应是：先看 `syllabus_masked_depth.png` 是否只保留目标，再看原始点云尺度是否合理，再看直通滤波有没有误删目标，最后检查统计滤波和体素降采样是否过强。不要一开始就调最后的抓取候选参数，因为前面任何一步出错，后面的候选都会建立在错误几何上。

#### 7.2.3 位姿生成模块：6D 位姿解算与抓取候选生成

本仓库当前没有强行绑定某个 6D 位姿网络，因为不同方法输入条件差异很大：ICP 需要 CAD 和初值，SAM-6D 需要 RGB-D、内参和 CAD，FoundationPose 需要 CAD 或少量 RGB-D 参考图像，直接抓取检测则可能跳过 object pose。课程基础作业可以使用一个几何近似版本理解数据流：

```python
pcd = o3d.io.read_point_cloud("data/rgbd_object_demo/output/syllabus_target_clean.pcd")
obb = pcd.get_oriented_bounding_box()
center = obb.center
R_obj = obb.R

# 简化 object pose：用 OBB 中心和主轴构造候选物体坐标系
T_cam_object = np.eye(4)
T_cam_object[:3, :3] = R_obj
T_cam_object[:3, 3] = center
```

这个 OBB 结果不能等价于严肃的 6D object pose benchmark。它没有 CAD 语义约束，主轴方向可能存在正负号翻转，对圆柱、盒体、对称物体也可能给出多个等价姿态。但它足以说明“点云几何如何变成一个局部坐标系”。随后可以定义保守顶部抓取候选：

```python
T_object_grasp = np.eye(4)
T_object_grasp[:3, 3] = [0.0, 0.0, z_offset]
T_cam_grasp = T_cam_object @ T_object_grasp
```

抓取候选建议不要只保存一个 4×4 矩阵，而应至少包含以下字段：

```json
{
  "grasp_pose": "4x4 homogeneous matrix",
  "frame_id": "camera or base",
  "approach": "unit vector",
  "width": "gripper opening in meters",
  "pre_grasp_distance": "offset before closing",
  "score": "heuristic or model confidence",
  "checks": ["workspace", "ik", "collision", "width_limit"]
}
```

如果是 Eye-to-Hand，相机固定在外部，抓取目标转换为：

$$
{}^{B}T_G = {}^{B}T_C \, {}^{C}T_O \, {}^{O}T_G
$$

如果是 Eye-in-Hand，相机固定在末端，转换链路通常写成：

$$
{}^{B}T_G = {}^{B}T_E \, {}^{E}T_C \, {}^{C}T_O \, {}^{O}T_G
$$

其中 $\,{}^{C}T_O$ 是感知模块输出的相机系物体位姿，$\,{}^{O}T_G$ 是在物体坐标系中定义的抓取模板，$\,{}^{B}T_C$ 或 $\,{}^{E}T_C$ 来自手眼标定，$\,{}^{B}T_G$ 才是提交给运动规划器的抓取目标。由此可见，6D 位姿不是链路终点，而是连接视觉几何与抓取动作的中间状态。

**本节小结：** 代码解析要沿数据流读，而不是按文件名背功能。检测分割层输出 mask，点云层输出 clean point cloud，位姿层输出 object frame 或 grasp candidates，手眼层负责把相机系结果变到机器人基座系。每一层都必须留下可检查的中间文件，否则全链路失败时很难定位责任环节。

### 7.3 可视化输出规范：多维度结果的 Open3D 展示

位姿估计和抓取实验不能只交终端日志。机器人系统的错误常常来自坐标方向、尺度和遮挡，这些问题必须靠图像、点云和坐标轴可视化发现。

#### 7.3.1 前端感知结果可视化：边界框与实例掩膜

前端结果至少应包含三张图：原始 RGB、bbox 或交互提示位置、mask overlay。mask overlay 应使用半透明颜色叠加在 RGB 上，让读者能看出是否混入桌面、邻物或背景。若使用 YOLO / Grounding DINO，还应保存类别、置信度、bbox 坐标和阈值；若使用人工 mask 或数据集 mask，也要说明来源。

#### 7.3.2 几何结果可视化：点云与物体 6D 位姿

几何结果至少应包含 raw point cloud、passthrough point cloud、clean point cloud 三个阶段。Open3D 可视化时建议统一坐标轴颜色：X 红、Y 绿、Z 蓝；若绘制物体坐标系或 OBB，应在图注中说明它是 CAD / ICP / OBB / 学习模型中的哪一种来源。仅凭一张最终点云截图不足以说明流程正确，必须同时报告点数变化、XYZ 范围和滤波参数。

#### 7.3.3 抓取结果可视化：夹爪模型与接近路径

抓取结果可视化应至少画出三个元素：`grasp_pose` 的 TCP 坐标系、pre-grasp 到 grasp 的接近线段、夹爪开口方向。若没有真实夹爪网格，可以用两条平行线段表示手指，用一条箭头表示接近方向。图中应标注该抓取候选是否已经过 IK、碰撞和夹爪行程检查；如果只是几何候选，应明确写为“未执行候选”，避免读者误以为已经能直接发给机器人。

建议报告中的可视化材料按下面方式组织：

| 可视化 | 证明什么 | 常见问题 |
|---|---|---|
| RGB + mask overlay | 前端目标是否选对 | mask 漏分、过分割、选中桌面 |
| masked depth | 深度是否只保留目标 | 深度空洞、单位错误、边缘噪声 |
| 点云阶段对比 | 滤波是否合理 | 点云过稀、主体被删、离群点残留 |
| 物体坐标系 / OBB | 几何位姿是否可解释 | 轴方向翻转、对称歧义、坐标轴画反 |
| 抓取候选与接近路径 | TCP 是否能接近目标 | 接近方向穿桌、开口不足、pre-grasp 太近 |
| 手眼坐标链路图 | 相机系结果如何到基座系 | 矩阵顺序错、左右乘混淆、单位不一致 |

**本节小结：** 可视化不是装饰，而是机器人感知实验的证据链。前端看 mask 是否选对目标，几何看点云是否干净和尺度是否合理，抓取看 TCP、接近方向和开口是否符合物理直觉。没有这些可视化，单独报告“成功 / 失败”很难形成可复现的技术结论。

## 8 本讲小结

### 8.1 两条技术主线回顾

#### 8.1.1 模块化感知路线：工程落地的主流范式

模块化路线把抓取问题拆成检测、分割、深度反投影、点云滤波、位姿估计、抓取候选生成、手眼转换和运动规划。它的优势是每一步都有明确输入输出，便于保存中间结果、调试误差和做安全检查。它尤其适合教学实验、工业部署、已知物体和需要严格复现的任务。

但模块化路线也有成本：链路长、接口多、标定要求高，任何一步的坐标方向或单位错误都会传导到后端。因此，模块化不是“简单路线”，而是一种把复杂系统拆成可验证环节的工程方法。

#### 8.1.2 端到端感知路线：前沿发展的重要方向

端到端路线试图从图像、点云或机器人状态直接预测 grasp pose、grasp candidates 或动作分布。它减少了显式中间接口，适合开放场景、复杂形状和大规模数据驱动策略学习。直接 6-DoF 抓取检测、点云抓取候选网络、VLA / 模仿学习策略都属于这条思想的不同形态。

它的挑战是数据成本高、失败归因困难、安全边界不易证明。真实机器人系统常采用混合架构：前端利用大模型或学习方法提高泛化能力，后端仍保留点云几何、手眼标定、IK、碰撞检测和失败检测等硬约束。

**本节小结：** 模块化路线和端到端路线不是非此即彼。前者提供可解释、可调试、可验证的工程骨架；后者提供更强的泛化和动作生成能力。理解二者的边界，才能在真实系统中做出稳妥组合。

### 8.2 感知 - 位姿 - 抓取的完整链路梳理

#### 8.2.1 从像素输入到抓取指令的全链路映射

本讲从 RGB-D 输入出发，依次完成了以下映射：

```text
RGB-D + intrinsics
  -> bbox / mask
  -> target depth
  -> target point cloud
  -> object pose 或几何候选坐标系
  -> grasp candidate
  -> base-frame grasp target
  -> IK / collision / execution check
```

每个箭头都对应一个可能出错的工程环节：mask 会影响点云纯净度，深度尺度会影响三维尺寸，点云滤波会影响几何结构，位姿估计会影响夹爪姿态，手眼标定会影响基座系目标，运动规划会决定候选是否真的可执行。

#### 8.2.2 机器人感知的核心目标：生成可执行操作指令

机器人感知的最终目标不是在图像上画框，也不是单独输出一个漂亮的 6D 位姿矩阵，而是为机器人生成可执行、可验证、可回退的操作目标。这个目标可以是显式抓取候选，也可以是策略动作，但必须接受坐标、碰撞、可达性、安全和任务成功标准的检验。

**本节小结：** 本讲的主线可以概括为“像素证据进入三维，三维几何进入位姿，位姿和任务约束进入抓取候选，抓取候选再进入机器人控制系统”。掌握这条链路后，读者就能把一次抓取失败拆解为可定位的问题，而不是笼统归因于“模型不准”。

### 8.3 通向下一讲：从感知结果到抓取动作执行

#### 8.3.1 本讲的能力边界与遗留问题

本讲解决的是“目标在哪里、如何摆放、夹爪候选应如何表达”。它还没有完整展开运动规划、抓取执行状态机、接触检测、力控闭环和失败恢复策略。也就是说，本讲把视觉结果推进到了机器人可以消费的候选目标，但候选目标能否安全执行，还需要下一讲继续处理。

遗留问题包括：如何从多个抓取候选中排序，如何做 IK 和碰撞检测，如何设计 pre-grasp / grasp / lift 状态机，如何在接触失败时重试，如何把一次失败记录成可训练数据。

#### 8.3.2 第 7 讲核心内容预告

下一讲将从“候选抓取”进入“动作执行”：重点讨论末端执行器、抓取技能、运动规划、接近路径、夹爪控制、状态机和执行反馈。第 6 讲输出的 `grasp candidate` 会成为第 7 讲的输入，后者负责把它变成真实机器人上的动作序列。

**本节小结：** 第 6 讲把视觉世界和机器人控制世界接起来，但只走到了“可执行目标”的门口。第 7 讲继续回答：目标给定以后，机械臂怎样安全接近、闭合、抬升、检测失败并恢复。两讲合起来，才构成从“看见目标”到“完成抓取”的完整操作闭环。
