## 20.1 VLA 为什么还不够

从 VLA 承接进入：

```text
VLA 已经让机器人学会：看图像、听指令、输出动作。
但真实机器人还缺一件事：
它不一定知道“这个动作执行之后，世界会怎样变化”。
```

用抓杯子或推方块作为引入：

- 夹爪向前移动，可能抓住杯子，也可能把杯子推倒。
- 推方块时，方块可能直线滑动，也可能旋转、卡住、碰到障碍物。
- 当前图像只告诉机器人“现在是什么样”，世界模型关心“接下来会怎样”。

本节核心问题：

> 机器人能否在执行动作之前，先在内部想象未来，再决定如何行动？

本节小结：

```text
VLA 解决“现在该做什么”。
世界模型关心“动作会如何改变世界”。
世界动作模型进一步把“未来想象”和“动作生成”结合起来。
```

## 20.2 什么是具身机器人里的世界模型

直觉定义：

> 具身世界模型是机器人从视觉、动作和交互数据中学到的内部模型，用来理解物理世界如何随动作和时间变化。

重点讲三层能力：

1. **预测物理变化**
   物体会移动、旋转、滑动、碰撞、被遮挡。

2. **理解动作后果**
   同一个动作可能让任务更接近成功，也可能导致失败。

3. **服务机器人控制**
   世界模型不是为了生成漂亮视频，而是为了帮助机器人选择、修正或生成动作。

可以给一个宽松表达：

```text
当前观测 + 动作 / 目标 -> 未来变化 / 动作后果
```

但要明确：

> 这只是基础世界模型的表达。面向具身机器人时，更重要的是模型能否把未来预测转化为动作能力。

## 20.3 VLA、AC-WM、WAM、仿真器的区别

| 类型 | 主要回答的问题 | 输入 | 输出 | 典型作用 |
|---|---|---|---|---|
| VLA | 现在该做什么？ | 图像 + 指令 + 本体状态 | 动作 | 直接生成控制指令 |
| AC-WM | 如果执行这个动作，世界会怎样？ | 当前观测 + 给定动作 | 未来观测 / 状态 | 预测动作后果 |
| WAM | 为完成任务，未来应如何变化，我该怎么动？ | 当前观测 + 语言目标 | 未来变化 + 动作序列 | 想象未来并生成动作 |
| 仿真器 | 按人写规则模拟物理 | 物理参数 + 动作 | 下一状态 | 人工构建环境 |

本节重点：

- AC-WM 是世界模型的基础形态。
- WAM 是面向具身机器人控制的进一步发展。
- 仿真器是人写物理规则，世界模型是从数据中学世界动态。
- 视频生成模型提供动态先验，但不等于机器人世界模型。

## 20.4 从 AC-WM 到 WAM：为什么世界模型要走向动作模型

先讲 AC-WM：

```text
当前观测 + 给定动作 -> 预测未来观测 / 状态
```

它的价值：

- 让机器人评估动作后果。
- 支持 imagination rollout。
- 可以在内部模拟几步未来变化。

它的局限：

- 动作通常已经给定。
- 它更像预测器，不一定直接告诉机器人该怎么动。
- 多步预测会漂移。
- 接触、摩擦、遮挡、物体交互会放大误差。

引出 WAM：

```text
当前观测 + 语言目标 -> 未来变化想象 + 动作生成
```

WAM 的关键变化：

- 不只是预测动作后果。
- 而是把未来世界变化和动作序列联合建模。
- 它试图让机器人从“反应式执行”走向“预测式行动”。

本节收束句：

> AC-WM 像学出来的预测器，WAM 更像面向机器人控制的想象-动作模型。

## 20.5 读懂 WAM 前需要的 8 个必备知识点

这一节只讲“读懂 WAM 所需的最小理论”，不展开基础线代和概率。

### 20.5.1 ViT 与视觉 token：图像如何变成模型能处理的序列

核心问题：

> 模型不是直接“看图片”，而是把图片变成一串 token。

讲法：

- ViT 把图像切成 patch。
- 每个 patch 变成一个视觉 token。
- 视觉 token 可以和语言 token、动作 token 放在同一个序列里处理。

服务后文：

- 解释 VLA 为什么能把图像和语言放在一起。
- 为后面“多模态 token”和 MoT 铺路。

### 20.5.2 VAE / Video Tokenizer：为什么视频要先压缩

核心问题：

> 视频太大，不能直接把每个像素都拿来建模。

讲法：

- VAE encoder 把图像或视频压缩到 latent space。
- VAE decoder 再把 latent 还原成图像或视频。
- 对视频模型来说，VAE / tokenizer 是视觉压缩器。

可以用 Wan 系列视频模型作例子：

- Wan 这类视频生成模型依赖高质量视频 VAE。
- 视频 VAE 决定了模型看到的“世界压缩表示”质量。
- 如果 tokenizer 压缩时丢掉运动、接触、细节，后面的世界模型再大也难补回来。

服务后文：

- Dreamer/RSSM 的 latent state。
- 视频 diffusion 的 latent video generation。
- WAM 中未来视觉预测为什么常在 latent space 中完成。

### 20.5.3 多模态 token：图像、语言、动作、本体状态如何统一

核心问题：

> 机器人不是只处理图像，还要同时处理语言、动作和自身状态。

讲法：

```text
图像 -> vision token
语言 -> text token
动作 -> action token
本体状态 -> state token
未来视频 -> future visual token
```

服务后文：

- VLA：视觉 + 语言 -> 动作。
- WAM：当前观测 + 未来视觉 + 动作序列联合建模。
- Motus：统一不同任务模式。

### 20.5.4 动作表示：continuous action、action token、latent action

核心问题：

> 机器人动作可以是连续数值，也可以被离散化或隐空间化。

讲三类：

| 动作表示 | 例子 | 适合讲什么 |
|---|---|---|
| continuous action | 关节角、末端位姿增量 | 传统控制 / VLA 输出 |
| action token | 把动作离散成 token | 接入 Transformer / MoT |
| latent action | 从视频变化中学到隐动作 | Motus / 世界动作模型 |

服务后文：

- DreamZero / LingBot-VA 的动作建模。
- Motus 的 latent action。
- Fast-WAM 为什么要快速输出可执行动作。

### 20.5.5 视频生成模型：从单帧理解到动态世界建模

核心问题：

> 图像模型理解“现在是什么”，视频模型学习“接下来怎么变”。

讲法：

- 单帧图像看不到动态。
- 视频包含运动、遮挡、接触、物体变化。
- 视频生成模型学习的是时空变化规律。

例子：

```text
单帧图像：杯子在桌上。
视频序列：夹爪靠近杯子，杯子被推动、倾斜、滑动、掉落。
```

服务后文：

- 为什么 WAM 借鉴 video generation。
- 为什么视频生成模型能提供 world prior。
- 为什么“会生成视频”仍不等于“会控制机器人”。

### 20.5.6 Diffusion / Flow Matching：为什么未来和动作可以生成

核心问题：

> 未来不是唯一答案，动作也不是唯一答案，所以需要生成式建模。

讲法：

- Diffusion：加噪 - 去噪。
- Flow Matching：学习从简单分布到目标分布的连续变换。
- 它们都可以生成视频、动作或轨迹。

服务后文：

- DreamZero 的 video-action generation。
- Fast-WAM 中 video co-training 的意义。
- 和第 10 讲 Diffusion Policy / Flow Matching 呼应。

### 20.5.7 RSSM / Latent Dynamics：为什么要在内部状态里想象未来

核心问题：

> 世界模型通常不直接在像素上想象，而是在 latent state 里滚动未来。

讲法：

- Encoder 把 observation 编码成 latent state。
- Dynamics model 在 latent state 中预测下一步。
- Decoder / prediction head 再预测图像、reward、continuation 等。

服务后文：

- Dreamer/RSSM Demo。
- 一步预测、多步 rollout、误差累积。
- 让学生理解“想象”不是玄学，而是模型内部状态递推。

### 20.5.8 MoT / 多专家架构：为什么一个模型里需要不同专家

核心问题：

> 图像理解、视频生成、动作生成、世界预测不是同一种能力。

讲法：

- 视觉专家处理图像/视频。
- 语言专家理解指令。
- 动作专家生成控制。
- 世界模型专家预测未来。
- 路由机制决定什么时候调用哪个专家。

服务后文：

- LingBot-VA 的 MoT。
- Motus 的 Mixture-of-Transformer。
- 解释为什么统一模型不是简单把所有东西拼起来。

本节收束：

```text
ViT / tokenizer 把图像和视频变成 token 或 latent；
多模态建模把图像、语言、状态、动作放进同一个系统；
Diffusion / Flow Matching 负责生成未来视频或动作序列；
RSSM / latent dynamics 负责在内部状态中预测未来；
MoT 让不同专家分别处理理解、生成、动作和世界建模。

这些工具加在一起，才让“机器人先想象，再行动”变成一个可训练的模型系统。
```

## 20.6 基础路线：Dreamer / RSSM 如何让模型学会“想象”

这一节承接 repo 原来的 DreamerV3 / RSSM Demo。

讲解顺序：

1. **为什么不直接预测像素**
   图像维度高、细节多、噪声大，直接预测每个像素很难。

2. **什么是 latent state**
   模型把观测压缩成内部状态，在这个内部空间里预测未来。

3. **RSSM 的核心模块**
   - Encoder：把 observation 编码成 latent state。
   - Recurrent dynamics：根据历史和动作更新 latent state。
   - Prediction heads：预测未来观测、reward、continuation 等。
   - Imagination rollout：在模型内部向前滚动。

4. **Dreamer 的教学价值**
   它让学生看到：世界模型如何学到动态规律，并在内部想象未来。

提醒：

> Dreamer/RSSM 是理解世界模型的好入口，但它不是具身 WAM 的全部。

## 20.7 五个代表工作：从世界模型到世界动作模型

这一节不要写成论文综述，而写成“技术路线地图”。每个工作只讲四件事：

```text
它要解决什么问题？
它的核心做法是什么？
它代表哪条路线？
它给具身机器人带来什么启发？
```

### 20.7.1 Dreamer / RSSM：世界模型的基础入口

定位：

> 先让学生理解“模型如何在潜在空间里想象未来”。

讲法：

- RSSM 把观测编码成 latent state。
- 模型在 latent space 中预测未来。
- Dreamer 用 imagination rollout 来学习策略。
- 它适合做本讲基础 Demo，但不是 WAM 的全部。

一句话：

> Dreamer 教我们：世界模型可以不直接预测像素，而是在内部状态里滚动未来。

### 20.7.2 DreamZero：WAM 作为 Zero-shot Policy

定位：

> WAM 不只是预测未来，而是联合建模未来世界状态和动作。

可讲点：

- 建在 pretrained video diffusion backbone 上。
- 用视频作为世界演化的密集表示。
- 联合建模 video 和 action。
- 强调 zero-shot generalization、跨任务、跨环境、跨 embodiment 迁移。
- 真实机器人闭环控制可作为亮点案例讨论。

一句话：

> DreamZero 把视频生成模型从“看起来会预测未来”，推进到“能和动作一起服务机器人控制”。

### 20.7.3 LingBot-VA：因果世界建模与闭环纠偏

定位：

> WAM 不能只靠开环幻想，必须在执行中接收真实观测反馈。

可讲点：

- 同时学习 frame prediction 和 policy execution。
- 使用 shared latent space、MoT 架构、closed-loop rollout、asynchronous inference。
- 把视觉动态、动作 token、真实反馈放到同一个控制过程里。

一句话：

> LingBot-VA 代表“边想象、边观察、边修正”的闭环 WAM 路线。

### 20.7.4 Fast-WAM：训练时学世界，推理时快速行动

定位：

> 回答真实机器人最关心的问题：推理时显式生成未来视频会不会太慢？

可讲点：

- 质疑“测试时一定要显式未来想象”。
- 保留 video co-training，但推理时跳过 future prediction。
- 强调低延迟动作生成。
- 用它讲“世界模型的价值可能主要来自训练阶段学到的世界表征，而不一定来自推理时生成未来视频”。

一句话：

> Fast-WAM 提醒我们：机器人需要的不是慢慢幻想，而是把世界动态知识压进快速动作生成里。

### 20.7.5 Motus：统一潜在动作世界模型

定位：

> 代表“统一架构”路线，把理解、世界建模、视频生成、动作生成放进一个系统。

可讲点：

- 用 Mixture-of-Transformer 整合理解、视频生成、动作等 expert。
- 用统一调度方式在 world model、VLA、inverse dynamics、video generation、video-action joint prediction 等模式之间切换。
- 用 latent action 表示连接视频变化和机器人动作。

一句话：

> Motus 代表一个更大的方向：未来的机器人模型可能不再区分 VLA、世界模型、视频生成、逆动力学，而是在统一潜在动作空间里切换能力。

## 20.8 Demo / 复现教学：从真机记录到 Fast-WAM

### 20.8.1 有硬件版 Demo：SO101 / xLeRobot 一步预测对比

目标：

> 让学生看到真实机器人执行动作后，物体状态与模型预测之间的偏差。

硬件平台：

- SO101：桌面抓取或推块任务。
- xLeRobot：移动操作任务，可记录 base + arm 联合动作。

流程：

```text
记录短 episode
-> 保存 observation、action、next observation
-> 用一步预测模型预测 next state
-> 对比 predicted 与 actual
-> 标注接触、遮挡、滑动等失败样本
```

课堂重点不是追求预测精度，而是让学生理解：世界模型的价值来自“预测误差能被看见、分析并回流到数据飞轮”。

### 20.8.2 无硬件版基础 Demo：简化 RSSM / Dreamer 风格世界模型

目标：

> 让学生看到 predicted 与 actual 的差异，理解一步预测、多步 rollout 和误差累积。

流程：

```text
加载 toy env / ManiSkill 简化任务
-> 收集 observation-action 序列
-> 训练或加载简化 RSSM / small world model
-> 可视化 predicted vs actual observation
-> 展示一步预测和多步 rollout
```

学生需要观察：

- 一步预测是否接近真实结果。
- 多步 rollout 从第几步开始明显漂移。
- 哪些情况更容易预测失败：接触、遮挡、快速运动、物体滑动。

### 20.8.3 进阶复现：Fast-WAM 最小复现

目标：

> 复现 Fast-WAM 的核心思想：训练时利用视频动态学习世界表征，推理时快速输出动作，而不是每一步都显式生成未来视频。

建议拆成四步。

第一步：准备数据

使用课程提供的小规模机器人视频-动作数据，或从公开数据集中抽取短序列：

```text
observation_t
action_t
observation_t+1 ... observation_t+k
```

第二步：训练阶段，加入未来预测辅助任务

模型不仅预测动作，还学习一个视频/未来特征预测任务：

```text
当前观测 + 指令 -> 动作
当前观测 + 动作历史 -> 未来视觉特征
```

重点不是追求高画质视频，而是让模型学到“动作会改变世界”。

第三步：推理阶段，关闭显式未来生成

推理时只保留快速动作输出路径：

```text
当前观测 + 指令 -> 动作
```

同时解释：

> 世界动态知识已经在训练中进入模型参数，不一定要在每次推理时慢慢生成未来视频。

第四步：对比实验

| 方法 | 是否训练未来预测 | 推理时是否生成未来 | 观察重点 |
|---|---|---|---|
| 普通 VLA baseline | 否 | 否 | 快，但缺少世界动态监督 |
| Imagine-then-act | 是 | 是 | 更显式，但慢 |
| Fast-WAM style | 是 | 否 | 训练学世界，推理快 |

学生观察：

- 推理延迟。
- 动作稳定性。
- rollout 成功/失败片段。
- 是否出现“预测未来很好看但动作不准”的情况。

### 20.8.4 实验步骤与作业交付

实验步骤：

1. 运行 `code/lecture20/` 中的一步预测 mock，理解 `state + action -> next state`。
2. 画出 VLA、AC-WM、WAM、仿真器的输入输出对比图。
3. 选择一个抓取或推块 episode，标注当前观测、动作、真实下一状态和模型预测下一状态。
4. 找出至少 2 类预测失败样本，例如接触、遮挡、滑动、长程漂移或实时性不足。
5. 说明这些失败样本如何进入“采集 -> 训练 -> 部署 -> 评测 -> 失败回流”的数据飞轮。

作业交付：

1. 一张世界模型 vs VLA vs WAM 对比图。
2. 一张数据飞轮闭环图。
3. 一段仿真或真机预测对比截图 / 短视频。
4. 一份预测失败复盘，说明失败现象、可能原因和下一轮数据补充方案。

## 20.9 常见误区与复盘

### 常见误区

- 世界模型就是视频生成。
- 能生成未来画面，就一定能控制机器人。
- VLA 和 WAM 只是名字不同。
- Dreamer 就代表全部具身世界模型。
- 预测越长越好。
- 只看未来画面逼不逼真，不看是否帮助动作生成。
- 忽略实时性：机器人不能慢慢想完再动。

### 复盘问题

1. 这个模型是否显式建模未来？
2. 它是否输出动作？
3. 它预测的未来是否服务控制？
4. 它是否能用真实观测纠偏？
5. 它在接触、遮挡、滑动任务中会不会失效？
6. 它的推理速度能否满足机器人控制频率？

## 20.10 本讲小结

三层总结：

1. **世界模型的基础**
   机器人学习世界如何随动作变化。

2. **世界动作模型的关键**
   不只预测未来，还要把未来想象转化为动作。

3. **具身机器人中的真正难点**
   未来预测必须面对接触、遮挡、摩擦、长程误差和实时控制。

收束句：

> VLA 让机器人学会“看见后行动”，世界动作模型希望机器人进一步学会“想象后行动”。对具身智能来说，世界模型真正重要的地方，不是生成一段漂亮的视频，而是帮助机器人理解：动作会如何改变现实世界。
