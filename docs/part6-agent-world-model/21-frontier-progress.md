## 21.1 本讲目标

前面二十讲已经把具身智能的主要部件拆开讲过：机器人本体、感知、控制、仿真、操作、数据、模仿学习、强化学习、Agent 和世界模型。到了最后一讲，我们以具身智能最新的变化作为本讲的主要内容。

第一个变化是，世界模型不再只是强化学习教材里的一个内部预测器，而是在向大规模、通用、可交互的世界动作模型发展。过去世界模型通常围绕一个环境、一个任务、一个状态空间训练；现在视频生成模型、机器人数据和人类视频开始汇合，模型第一次有机会在很大的经验分布上学习“动作之后世界会怎样变化”。

第二个变化是，LLM/VLM Agent 的能力正在从任务规划向动作领域渗透。最早的机器人 Agent 只是把“去厨房拿水”拆成若干 Skill；现在它开始指定目标部位、接近方向、空间约束、动作参数，甚至生成新的 Skill、状态机和控制程序。这里的重点并不是让语言模型直接接管电机，而是动作接口本身正在变得越来越语义化。

第三个变化是，仿真与强化学习的关系正在改变。仿真过去常常是一个人工搭好的训练场，强化学习在里面把一个策略练熟。现在更前沿的想法，是让模型自动生成任务、场景、奖励和课程，让仿真持续制造新的交互经验，再把高价值失败和恢复轨迹送回训练系统。仿真开始从“环境”变成“经验工厂”。

第四个变化是，第一人称人类数据正在尝试成为机器人学习的统一数据入口。人类每天都在开门、整理、烹饪、维修和使用工具，这些经验远比机器人数据丰富。第一人称视频在观察视角上接近机器人，但人手、机器人夹爪、关节动作和力觉并不相同。因此，这条路线真正要解决的不是“把视频全部转成关节角”，而是怎样在观察、几何、交互和动作之间建立分层桥梁。

这四条线并不是四个互斥的模型方案。WAM 关心未来，Agent 关心任务组织，Simulation × RL 关心交互和试错，第一人称数据关心经验从哪里来。它们目前仍然各自发展，很多工作也只解决其中一小段。这里不急着把它们强行收束成一个统一架构，而是分别谈谈这些方向为什么值得关注，以及我觉得它们接下来可能往哪里走。

## 21.2 方向一：WAM Scaling——世界模型正在走向基础设施

### 21.2.1 老问题为什么突然有了新解法

世界模型不是新概念。早期的 World Models、PlaNet、Dreamer 一类工作，已经在学习一个内部动态模型：把观测压缩成潜在状态，在潜在空间里预测未来，再用想象出来的轨迹训练策略。DreamerV3 进一步证明，同一套世界模型方法可以覆盖大量不同任务。[1]

这些工作很重要，但它们长期有一个明显特征：世界模型通常是围绕一个环境或一组相近环境训练的。输入状态、动作形式、视觉分布和任务结构都相对固定。模型学到的是一个任务族中的动态，而不是开放世界里的通用交互经验。

近几年真正改变局面的，是视频生成模型的规模上升。视频天然包含时间、运动、遮挡和物体状态变化；当视频模型开始拥有较强的时空生成能力后，研究者很自然地会问：能不能把动作也放进去，让视频模型不只是“续写画面”，而是“响应动作”？

这就是世界动作模型（World Action Model，WAM）重新受到关注的原因。它不再只满足于：

```text
当前状态 + 动作 → 下一状态
```

而是试图在更大规模的数据上学习：

```text
历史观测 + 动作 / 目标 / 本体条件
                ↓
未来视觉、对象变化、接触结果、任务进度与后续动作
```

DreamZero 是这条路线里很有代表性的工作。它基于预训练视频扩散骨干，联合建模未来视频与机器人动作，并把一个 14B 级视频模型优化到约 7 Hz 的真机闭环控制。论文还报告了来自其他机器人和人类的视频，对未见任务有明显帮助。[2]

DreamDojo 则把数据规模继续推高：使用约 4.4 万小时第一人称人类视频预训练世界模型，再通过连续潜在动作和少量目标机器人数据把模型接到真实控制上。作者还给出蒸馏后的实时版本，使交互式生成达到约 10 FPS。[3]

我觉得这两项工作的意义不只在于某个成功率数字。更值得注意的是，世界模型第一次开始呈现“基础模型化”的迹象：它不再完全依赖单个机器人、单个任务和单个实验室的数据，而是试图从大规模人类与机器人视频中学习一种更一般的交互先验。

换句话说，过去世界模型更像机器人内部的一个小型预测模块；现在的 WAM 更像是在争夺“机器人世界基础模型”这个位置。

### 21.2.2 Scale 的不只是参数，而是世界经验

谈到 WAM Scaling，最容易把注意力放在模型参数量上。参数当然重要，但对机器人来说，真正稀缺的往往不是网络容量，而是动作与后果相互对应的世界经验。

一段普通视频能告诉模型，杯子从桌面移动到了水槽；但它未必告诉模型，杯子是被右手抓走、被左手推走，还是镜头切换后出现在另一个位置。视频模型可以学到“接下来可能出现什么”，控制模型还需要学到“什么动作会导致什么结果”。这中间多了一个可控性问题。

所以 WAM 的规模，至少同时发生在几个方向。

#### 1. 视频规模

更多视频带来更多对象、场景、运动和交互方式。它扩大的是模型对世界变化的覆盖。人类第一人称视频尤其有价值，因为手、工具和目标物体通常处于画面中心，任务过程也相对完整。

#### 2. 动作规模

机器人动作标签仍然远少于视频。真实关节动作最准确，但跨机器人难以统一；末端轨迹更通用，却会丢失冗余自由度和接触细节；人类手腕与手指轨迹容易采集，但与夹爪动作存在本体差异；潜在动作可以吸收无标签视频，却不一定天然对应可执行控制。

DreamDojo 使用连续潜在动作，就是在尝试绕开“每段视频都必须有机器人动作标签”这个瓶颈。[3] 这种做法的想象空间很大：先在海量视频里学习变化模式，再用少量机器人数据把潜在动作锚定到真实动作空间。

#### 3. 时间规模

一步预测适合局部控制，长视频适合长程想象。但预测越长，误差也越容易累积。未来很可能不会简单追求“越长越好”，而是形成多个时间尺度：

```text
几十毫秒：接触和局部运动
几百毫秒：一段动作块的后果
几秒：抓取、打开、放置等阶段结果
更长时间：任务级状态与场景变化
```

不同时间尺度也可能由不同模型或不同 latent 表示负责。

#### 4. 本体规模

机械臂、灵巧手、移动操作机器人和人形机器人的动作空间完全不同。WAM 如果只记住某个关节向量，很难跨本体扩展。OSCAR 使用 2D 运动骨架作为机器人手臂和人手之间的统一条件表示，就是一种很有意思的尝试。[4]

更长远地看，跨本体世界模型可能不会直接统一所有关节，而是统一一些更接近任务的量：对象运动、末端轨迹、接触关系、身体关键点、支撑关系和功能部位。

#### 5. 交互模态规模

视觉是最容易规模化的模态，但视觉并不完整。夹爪看起来闭合，不代表真的夹稳；物体暂时没动，不代表没有受力；柔性物体的状态也很难只靠一帧 RGB 判断。力、触觉、本体状态、深度和音频迟早会进入 WAM，只是这些模态的同步、标定和数据规模目前远不如视频成熟。

因此，我更愿意把 WAM Scaling 理解成：模型在扩大“可观察、可干预、可迁移的世界经验”，而不只是扩大网络。

### 21.2.3视频未来与潜在未来，两条路线正在并行

现在谈 WAM，常常会把它理解成“先生成一段未来视频，再根据视频决定动作”。这种路线很直观：机器人可以在内部看见几种候选动作的结果，选择更接近目标的一种。DreamZero 就具有很强的这一色彩。[2]

显式视频未来有几个明显优势。

首先，它保留的信息多。对象是否被遮挡、抽屉是否打开、杯子是否倾倒，都可以在视觉空间中表达。其次，它适合人观察和分析，研究者能直接看到模型“想象”了什么。最后，大规模视频预训练可以直接提供初始化，不需要从头学习一个机器人专用状态空间。

但像素空间也很昂贵。机器人控制真正关心的，往往只是对象位置、接触、运动趋势和任务进度；视频模型却还要生成纹理、背景、光照和大量与动作无关的细节。生成得越精细，推理成本越高。

因此另一条路线，是让未来只存在于 latent 中。Being-H0.7 在感知和动作之间加入可学习 latent query：训练时用未来观测分支监督这些 latent，部署时删除未来分支，只从当前上下文推断未来相关的内部状态，不再生成未来画面。[5]

它背后的想法可以概括成：

```text
训练时看见未来，部署时记住未来带来的结构。
```

这类路线让我觉得，未来的 WAM 不一定都长成“每一步都放一段内部视频”。更可能出现三种形态并存：

1. 显式想象型：在困难状态下生成候选未来，适合规划、分析和高风险决策；
2. 潜在预测型：把未来压缩成动作相关 latent，适合高频执行；
3. 训练辅助型：未来预测只在训练阶段使用，部署时保留一条轻量动作路径。

显式未来和潜在未来并不是谁取代谁。它们更像不同计算预算下的两种使用方式。熟悉任务可能直接依赖 latent；遇到遮挡、长程转折或不确定状态时，再调用更昂贵的显式想象。

### 21.2.4 当世界模型开始承担“模拟器”的角色

WAM 的另一个变化，是它不一定直接负责控制机器人。它也可以成为训练和评估系统中的模拟器。

传统物理仿真依赖资产、碰撞体、质量、摩擦和控制接口。它对已建模变量很精确，但新场景和新对象的制作成本高。视频世界模型正好相反：它可以从数据中吸收大量外观和交互先验，却可能在接触、几何一致性和动作跟随上出错。

DreamDojo 把世界模型用于实时遥操作、策略评估和模型规划。[3] OSCAR 则尝试用统一骨架条件的世界模型评估不同机器人策略，并报告虚拟评估与真机评估之间存在较强相关性。[4]

这类工作的潜在影响很大。机器人训练中最昂贵的部分之一，不是反向传播，而是让策略和世界发生足够多的交互。如果世界模型能够生成“足够可靠”的交互结果，它就可能承担几种基础设施角色：

- 在真实执行前快速筛掉明显不合理的动作；
- 为策略提供大量短时 imagined rollout；
- 在没有完整物理资产时近似新场景；
- 评估不同策略在新对象、新外观和新视角下的表现；
- 把真实视频转换成可继续交互的训练环境。

这里最关键的词不是“逼真”，而是“可控”。一个视频模型可以生成非常漂亮的抽屉打开画面，但如果不同拉力、方向和抓取位置都得到差不多的结果，它就不能承担控制模拟器。世界模型真正进入机器人训练系统，依赖的是动作跟随、对象持续性、接触一致性和误差可控，而不只是视觉质量。

WoVR 进一步把世界模型作为强化学习后训练环境，同时专门限制长时 rollout 的幻觉和策略对模型漏洞的利用。[6] 这说明一个新的研究主题正在形成：不是假设世界模型已经足够真实，而是研究怎样在不完美世界模型中安全地学习。

### 21.2.5接下来可能往哪里走

第一，控制导向的短时未来会比长视频更早成熟。机器人每次不一定要想象十几秒，很多时候只要知道接下来 0.5 秒是否形成接触、物体会向哪边移动，就足以改善动作。

第二，对象和交互关系会逐渐进入核心表示。纯像素视频很难稳定维护“这是同一个杯子”“抽屉已经打开 12 cm”“夹爪正在接触把手”。对象级状态、接触图和功能部位可能会和视频 latent 共存。

第三，世界模型会越来越多地与物理引擎混合。物理引擎负责关节、碰撞和硬约束，学习模型负责外观、未建模对象和复杂交互先验。两者的边界会根据任务不断移动，而不是长期二选一。

第四，多模态世界模型会把视觉之外的信号带进来。力、触觉和声音不一定拥有互联网规模的数据，但在接触任务中信息密度极高。未来可能出现“视频负责大范围世界知识，触觉和力觉负责局部校正”的结构。

第五，世界模型可能先成为训练基础设施，再成为部署主干。在训练中生成数据、筛选动作、构造奖励和评估策略，比在每个控制周期都显式生成视频更容易落地。等模型速度、可靠性和多模态数据进一步成熟后，它才可能更深地进入在线控制。

## 21.3 方向二：Agentic Action——Agent 正在进入动作接口

### 21.3.1 从调用 API 到调用身体

数字世界里的 Agent 已经很容易理解：模型调用搜索、浏览器、代码解释器和数据库，通过一轮轮观察与行动完成任务。具身 Agent 的循环其实没有本质变化，只是工具的另一端变成了机器人身体。

```text
数字 Agent：search() / read_file() / run_code()
具身 Agent：navigate() / observe() / grasp() / open_drawer()
```

真正变化的是，数字工具失败通常只是返回一个报错；物理动作失败会改变环境，甚至造成不可逆后果。因此，机器人 Agent 从一开始就必须同时面对可执行性、反馈、时序和安全。

SayCan 是这一方向很早也很清晰的工作。语言模型负责判断“做什么在语义上合理”，技能价值函数负责判断“当前机器人能不能做”，两者相乘后选择下一步 Skill。[7] 它把一个重要原则讲得很透：语言知识不能直接等于物理可行性，必须由机器人自身能力进行落地。

Inner Monologue 随后把成功检测、场景描述和人类反馈重新喂给语言模型，让计划从一次性生成变成闭环修正。[8] 这一步看似只是增加反馈，实际上决定了 Agent 能不能在真实世界里持续工作。

之后，动作接口开始继续下沉。Code as Policies 让语言模型生成调用感知与控制 API 的程序，程序中可以包含循环、条件、几何计算和第三方库。[9] VoxPoser 则让 LLM/VLM 生成 3D 价值图，把“远离障碍”“从把手左侧接近”“保持杯口向上”等语言约束投影到空间，再由规划器合成轨迹。[10]

把这些工作连起来看，会发现 Agent 并不是突然从文本规划跳到电机控制，而是在一步一步缩短语言与动作之间的距离：

```text
自然语言任务
→ Skill 序列
→ 带反馈的 Skill 序列
→ 可执行程序
→ 空间约束与轨迹目标
→ 新 Skill 与动作接口
```

### 21.3.2 Action 的粒度正在变细

过去说“机器人 Agent 负责高层规划”，高层通常意味着一句话一个动作：去厨房、找到杯子、抓起来、送到桌上。现在高层和低层之间出现了越来越多的中间层。

一个 Agent 可能只选择 `grasp_cup`，也可能进一步给出：

- 抓哪个杯子；
- 抓杯身还是杯把；
- 从哪一侧接近；
- 哪些区域不能碰；
- 夹爪大约张开多宽；
- 抓取后先抬多高；
- 什么时候重新观察；
- 什么现象表示抓取失败。

再往下一层，模型还可以生成一段状态机、运动约束或控制程序。此时“动作”已经不再只是一个固定 Skill 名称，而是一种带语义、空间和时间结构的中间表示。

我更倾向于把机器人动作看成四个尺度：

```text
任务意图：把杯子放进抽屉
    ↓
技能与空间子目标：抓杯身、沿把手法向拉开抽屉
    ↓
局部轨迹与动作块：未来一段末端轨迹、夹爪开合与接触阶段
    ↓
伺服控制：关节位置、速度、力矩和安全联锁
```

LLM/VLM Agent 正在从第一层向第二层、部分第三层移动。第四层仍然更适合确定性控制器、全身控制器和驱动器固件。不是因为语言模型永远不能输出高频动作，而是底层控制需要稳定周期、有限延迟、硬约束和故障时的确定行为。

因此，“Agent 能力覆盖 action”更准确的理解是：语义推理开始进入动作表示和动作组织，而不是语言模型取代所有控制层。

### 21.3.3 真正重要的不是计划，而是闭环反馈

很多机器人 Agent 展示都把重点放在计划上：模型能把一个长任务拆成十几个步骤，看起来很聪明。但真实执行里，最容易失效的往往不是第一份计划，而是计划与现实之间的偏差。

例如 Agent 计划：

```text
找到抽屉把手 → 抓住把手 → 向外拉 → 把杯子放入
```

实际可能发生：

- 相机看到了把手，但把手位姿估计偏了；
- 夹爪闭合了，却只夹到边缘；
- 拉动方向与滑轨方向不一致；
- 抽屉打开后遮住了杯子；
- 杯子在抓取时滑落；
- 用户中途把杯子移到了另一边。

Agent 如果只保存最初的计划，就会继续执行一条已经过期的动作链。真正的具身能力来自持续更新：环境现在是什么状态，上一步产生了什么后果，原计划的哪些前提已经不成立。

PLanAR 把对象谓词、动作前提、动作效果和符号计划组合成一个 planning-language interface。每个动作执行后，系统根据机载观测检查预期效果是否真的发生，再更新状态或重新规划。[11] 这个工作值得关注的地方，不是重新回到传统符号规划，而是给 VLM 提供了一个介于自然语言和底层动作之间的、可验证的中间层。

机器人 Agent 的闭环也不适合让大模型持续高频轮询。更自然的做法是事件触发：

```text
Skill 正常执行
    ↓
只有在完成、超时、无进展、环境显著变化、风险上升时
    ↓
重新调用 Agent 观察和推理
```

这样可以把不同时间尺度分开。控制器持续处理毫秒级反馈，局部策略处理几十到几百毫秒的动作，Agent 只在任务状态发生变化时介入。

随着任务变长，Agent 的记忆也会从“聊天上下文”变成真正的空间和任务记忆：对象最后出现在哪里，哪个抽屉已经打开，某个 Skill 在这个机器人上通常为什么失败，哪些信息已经过期。ABot-AgentOS 就把运行时、技能隔离、多阶段验证和多模态图记忆作为一个独立 Agent OS 层来处理。[12]

这类系统说明，长程机器人能力不一定只来自更大的主模型。运行时如何保存状态、隔离上下文、返回证据和恢复失败，可能同样决定最终表现。

### 21.3.4 Skill 可能成为机器人时代的“工具协议”

数字 Agent 的能力很大程度上取决于工具。工具如果只有名字，没有明确参数、权限和返回值，Agent 很快就会失控。机器人 Skill 也是一样。

一个成熟的 Skill 不应只写成：

```text
open_drawer(drawer)
```

它还需要表达：

```text
前提：把手可见、目标在工作空间、机器人无故障
参数：目标开度、最大速度、最大力、接近方向
执行：抓取、拉动、阶段检查
结果：抽屉位姿、任务进度、接触证据、失败原因
边界：超时、无进展、力超限、人员进入工作区
```

当 Skill 被写成这种形式时，它就不只是一个函数，而是一份动作契约。Agent 可以根据契约组合能力，系统也可以在执行前检查参数，在执行后验证结果。

这可能会成为具身 Agent 很重要的一层基础设施：不同机器人拥有不同底层控制，但可以暴露相似的语义 Skill；同一个 Agent 根据本体能力选择不同实现；新 Skill 可以由模型生成，再在仿真和验证器中测试后进入能力库。

VASO 把这种思路继续推向形式化验证。它把 Skill 表示成同时面向规划器和模型检查器的语义契约，验证失败时，把反例轨迹转成文本反馈更新 Skill，而不直接修改基础模型权重。[13]

我觉得这类方向会越来越重要。模型生成 Skill 的成本会快速下降，但“怎样相信一个 Skill”不会自动变简单。机器人越通用，能力库越大，越需要清楚的前提、效果、安全规范和版本管理。

从这个角度看，未来机器人软件栈里可能出现一层类似今天 API、MCP 或操作系统系统调用的东西：

```text
自然语言目标
→ Agent 选择 / 生成 Skill
→ Skill 契约约束可执行空间
→ 控制器完成实时动作
→ Evidence 返回 Agent 与记忆
```

Skill 将成为模型推理和物理执行之间的共同语言。

### 21.3.5 Agent 能力继续下沉后，系统会变成什么样

我不太认为未来会是“一个超大模型直接接管整台机器人”，至少在相当长时间内不会。更可能出现的是一个层次化系统：

- 大模型负责理解开放目标、生成子目标和解释反馈；
- 空间模型负责对象、部位、可达性和几何约束；
- 专用策略负责局部动作和接触技能；
- 控制器负责稳定、实时和安全；
- Harness 或 Agent OS 负责权限、记忆、日志、验证和恢复。

变化在于，这些边界不会像传统流水线那样完全由工程师手写。Agent 会参与生成中间表示、组装能力、修改 Skill、选择模型和调用世界预测。系统仍然分层，但层与层之间的内容会越来越多由模型动态产生。

还有几个方向值得持续观察。

第一，Agent 会从调用 Skill 走向维护 Skill。它不仅使用已有能力，还会根据失败轨迹修正参数、重写状态机、生成测试和更新文档。

第二，空间记忆会成为动作能力的一部分。Agent 不再只记住语言事实，还要维护对象位置、可通行区域、容器状态、交互历史和不确定性。

第三，多机器人与多 Agent 协同会让动作接口进一步抽象。高层 Agent 可能不关心具体由哪台机器人执行，而是根据能力、位置和负载分配任务。

第四，模型路由会比单模型更实际。简单状态由小模型或规则处理，复杂语义调用大模型，接触任务调用专用策略，长期计划调用带记忆的 Agent。机器人系统会更像一个异构计算系统，而不是一个统一频率的神经网络。

第五，安全与验证会成为 Agent 能力扩展的前提，而不是后补模块。动作越开放，越不能依赖模型自述“我认为安全”。硬限制、权限、形式规则和独立验证器会长期存在。

## 21.4 方向三：Simulation × RL——仿真正在成为经验工厂

### 21.4.1 从固定训练场到自动生成世界

过去做机器人强化学习，通常先由研究者搭好一个环境：机器人、物体、初始状态、奖励函数和终止条件都写死，然后开几千个并行环境训练策略。这个模式对行走、抓取和固定技能非常有效，但它的规模上限很明显：环境和任务仍然靠人设计。

近几年生成式模型开始进入仿真工程，重点并不是让场景更漂亮，而是让任务、场景、奖励和训练监督能够自动扩张。

GenSim 让 LLM 生成机器人仿真任务和代码，在已有基准上把任务数量扩展了约十倍，并用生成任务训练多任务策略。[14] RoboGen 更进一步，让系统自己提出任务、生成场景、选择学习方法并产生训练监督，形成“提出—生成—学习”的循环。[15]

Eureka 则集中解决奖励设计。它让代码大模型生成和迭代奖励函数，在 29 个开源强化学习环境、10 种机器人形态上进行实验，论文报告其生成奖励在多数任务上超过人工奖励。[16]

SimWorld Studio 把这种自动化推进到可运行 3D 世界：编码 Agent 在 Unreal Engine 5 中生成带物理、任务和 Gym 接口的环境，并根据学习器当前能力继续生成更难的课程。[17]

把这些工作放在一起看，仿真的角色正在发生变化：

```text
过去：人搭环境 → 策略训练
现在：模型生成环境 / 奖励 / 课程 → 策略训练 → 失败反馈 → 继续生成
```

也就是说，仿真不再只是一个静态容器，而是在变成可以持续生产经验的系统。

### 21.4.2 RL 的位置正在从“从零学技能”转向“后训练”

强化学习最经典的形态，是从随机策略开始，通过大量试错学会走路、抓取或游戏。但对越来越大的机器人模型来说，从零开始并不划算。模型已经可以通过人类示范、机器人轨迹和视频预训练获得相当强的先验，RL 更适合做后训练。

模仿学习告诉模型“人通常怎么做”，强化学习回答的是“在这个身体、这个环境和这个目标下，什么动作真的有效”。两者的差别在接触和恢复任务里尤其明显。

例如一条示范只展示成功抓取，模型很难知道夹偏一点会怎样；RL 可以反复经历滑落、碰撞和重新抓取，把成功边界逐渐摸出来。一条示范通常没有恢复动作，而 RL 会主动进入偏离状态，学习怎样回来。

因此，未来的 RL 可能更多承担几种角色：

- 在模仿策略上提高精度和鲁棒性；
- 学习失败恢复和长尾状态；
- 让高层 Agent 学会选择更有效的 Skill 顺序；
- 优化观察时机、动作速度和接触参数；
- 根据世界模型或仿真 rollout 做大规模后训练；
- 把交互经验再蒸馏回更快、更稳定的执行模型。

WoVR 就体现了“世界模型 + RL 后训练”的思路。它不假设学习世界模型完全可靠，而是通过关键帧初始化 rollout 和世界模型—策略协同演化，控制想象误差对策略优化的污染。[6]

这个方向让我觉得，机器人模型的训练流程会越来越像语言模型的“预训练—监督训练—强化后训练”，但物理世界中的奖励、环境和安全比文本任务复杂得多。机器人 RL 的核心竞争力未必只在 PPO、SAC 或 GRPO 的公式，而在于谁能构造足够丰富、可靠、可重复的交互环境。

### 21.4.3 Real2Sim、Sim2Real 和数据回流开始连成一条线

传统 Sim2Real 常常从仿真出发：在仿真里训练策略，再通过域随机化、系统辨识和少量真机数据迁移。现在另一条线越来越重要：先从真实世界恢复可编辑的场景、对象和任务，再进入仿真。

这使流程从单向迁移变成循环：

```text
真实场景 / 视频 / 机器人日志
          ↓ Real2Sim
可编辑场景、对象资产、初始状态和任务条件
          ↓ 仿真与 RL
大量成功、失败、扰动和恢复轨迹
          ↓ Sim2Real
真机部署与少量在线校准
          ↓
新的失败和边界状态再次回流
```

Real2Sim 的价值不只是视觉复刻。对机器人训练真正有用的场景，需要对象可分离、碰撞体正确、关节可动、尺度可靠、材质和动力学能够调整。一个看起来很像真实房间的 3D 场景，如果抽屉不能打开、杯子没有碰撞体，就不能成为交互环境。

反过来，Sim2Real 也不再只是把一个最终策略搬到真机。仿真数据可以参与预训练，真机少量失败可以用于系统辨识，真实视频可以修正渲染和对象分布，人在环纠正可以形成新的高价值样本。

因此，我更看好“闭环数据引擎”而不是一次性迁移：

```text
真实数据定义问题
→ 仿真放大问题
→ RL 搜索解决办法
→ 真机验证
→ 失败再定义下一轮问题
```

这条链路中，最有价值的数据往往不是完全随机的失败，而是接近成功、原因可解释、具有恢复可能的失败。比如抓住后滑落、插入时卡住、目标被遮挡后重新观察。这些状态离决策边界最近，对模型改进也最直接。

### 21.4.4 世界模型与物理仿真并不是二选一

谈到学习世界模型，有时会出现一种说法：未来视频模型会取代 MuJoCo、Isaac Sim 或其他物理引擎。我觉得这种二选一的判断太早。

物理引擎擅长的是已知结构：关节、刚体、碰撞、质量、摩擦、约束和可重复状态。它的优点是状态清楚、动作严格、结果可解释。缺点是资产制作和复杂现实建模昂贵。

学习世界模型擅长的是数据覆盖：真实外观、长尾对象、人类交互和难以手工建模的变化。它的优点是可以从大量视频中吸收经验。缺点是可能幻觉、动作跟随不精确、内部状态不透明。

更实际的路线是混合：

```text
物理引擎负责：机器人本体、碰撞、硬约束、基础动力学
学习模型负责：视觉观测、复杂对象行为、材质变化、未建模交互先验
真实数据负责：校准两者的偏差
```

在某些任务里，学习模型只生成相机画面，物理状态仍由引擎推进；在另一些任务里，学习模型预测对象运动，物理引擎保证机器人关节和安全；还有一些任务会把短时世界模型 rollout 夹在真实观测之间，避免长时间自由生成。

这个混合方向很可能比“完全神经模拟器”更早产生工程价值。它允许系统保留物理引擎的确定性，同时借助世界模型扩展外观和交互分布。

### 21.4.5 交互数据也许比更大的模型更稀缺

互联网给语言模型提供了海量文本，视频平台给视觉模型提供了海量图像和视频，但机器人真正需要的“动作—后果”数据仍然非常少。观察视频容易，干预世界很贵。

这也是仿真与 RL 重要的根本原因：它们能够主动生成交互，而不是被动等待数据。一个模型看到一万次“杯子被拿起”，仍然可能不知道从不同方向推杯子会怎样；仿真可以固定同一初始状态，尝试不同动作、摩擦和抓取点，得到反事实经验。

这种反事实数据对“模型理解”很关键。这里的理解不是一个抽象哲学概念，而是模型内部是否建立了动作、状态变化和长期结果之间的关系。监督学习通常只看到一条正确轨迹，RL 和仿真可以让模型看到：

```text
同一个状态
+ 不同动作
+ 不同物理参数
= 不同后果
```

当模型需要在这些后果中选择时，它才被迫关心可控因果，而不仅是视觉相关性。

因此，未来具身智能的 Scaling 也许会越来越强调“交互规模”：一次训练包含多少动作尝试、多少失败边界、多少物理干预和多少恢复过程。模型规模仍然重要，但没有足够交互，参数很容易只是记住更大的相关性表。

### 21.4.6 真机 RL 仍然离不开人的最后一公里

无论仿真多强，真实机器人仍然存在一些很难完整建模的东西：机械间隙、线缆、磨损、柔性材料、工件公差、相机延迟、环境光和人的临时干扰。

HIL-SERL 把示范、人类纠正、视觉奖励和高效离策略强化学习组合在一起，在动态操作、精密装配和双臂任务中进行真机训练。论文报告，多项任务可在约 1 到 2.5 小时内达到接近满成功率的表现。[18]

这类工作给我的感觉是，真机 RL 的“人”不会很快消失，但人的角色会变化。人不再逐帧遥操作全部数据，而是在少数关键状态介入：

- 在危险探索前停止；
- 在策略即将失败时纠正；
- 处理自动复位覆盖不了的情况；
- 给奖励模型难以判断的边界状态标注；
- 选择哪些失败值得继续训练。

如果仿真和预训练已经提供大部分能力，真机 RL 可能越来越像校准和精修，而不是从零学习。人的时间也会从“持续示范”转向“高价值干预”。

## 21.5 方向四：第一人称数据——把人类经验接入机器人

### 21.5.1 第一人称真正统一的是观察过程

机器人数据规模化一直有一个现实问题：每采一小时数据，都需要机器人、场地、操作员和复位。人类活动则随时随地发生。只要佩戴头部相机，人们在厨房、工厂、仓库和日常生活中的操作都可以被记录。

Ego4D 已经把第一人称视频扩展到 3,670 小时，覆盖大量日常场景和活动。[19] Ego-Exo4D 又加入同步第一、第三人称视角、相机位姿、眼动、IMU 和 3D 信息，开始把“看到什么”和“身体怎样完成技能”联系起来。[20]

这些数据集最初主要服务视频理解，但它们为机器人学习提供了一个重要启发：第一人称视角不是普通视频的另一个摄像机角度，而是一种与行动者身体绑定的观察过程。

人在操作时会主动移动头部，手和工具会进入画面，遮挡会随身体变化，视野会围绕任务目标组织。机器人头部相机、腕部相机和移动相机也有类似特点。

因此，第一人称数据能够较自然地统一几种信息：

- 任务发生的视觉上下文；
- 手、工具与对象的相对关系；
- 操作前后的对象状态变化；
- 任务阶段和时间顺序；
- 为保持目标可见而产生的视角动作；
- 人类在开放场景中实际选择的交互方式。

它统一的首先是“从行动者视角观察和经历任务”，而不是某一台机器人的控制命令。

### 21.5.2 统一观察不等于统一动作

第一人称数据最容易被过度乐观地表述成“人类视频就是机器人数据”。实际上，两者中间仍有很大的 embodiment gap。

人手有多指、柔性皮肤和复杂触觉；二指夹爪的接触方式完全不同。人类可以用腕、肘、肩和身体补偿，机械臂可能受工作空间限制。人类头部相机和机器人腕部相机也不在同一位置。视频通常没有关节角、力、夹持宽度和精确时间同步。

所以第一人称数据真正的技术问题，是怎样把一段人类经验拆成不同层次的监督：

```text
视觉和语义：场景、对象、任务步骤
几何：手、对象、相机的 3D 运动
交互：接近、接触、抓持、释放、对象状态变化
动作：机器人可执行的末端轨迹、关节动作或潜在动作
结果：任务进度、成功、失败和恢复
```

不同数据不必拥有全部字段。一段普通人类视频可以只提供视觉与任务阶段；带 3D 手追踪的视频可以提供几何与交互；使用专门采集设备的数据可以进一步提供接近机器人动作的控制标签；真实机器人数据则负责把这些中间表示锚定到具体本体。

这也是我理解“统一数据模态”的方式：统一的是数据结构和任务语义，而不是强迫所有来源输出同一套关节向量。

### 21.5.3 从手部轨迹到伪动作

最直接的人到机器人桥接，是把人手运动恢复出来，再映射到机器人。

典型流程是：

```text
第一人称视频
→ 相机运动估计
→ 手腕 / 手指 / 物体 3D 位姿
→ 手—物相对运动
→ 机器人末端伪动作
→ 少量机器人数据校准
```

EgoMimic 使用 Project Aria 眼镜采集第一人称视频和 3D 手部追踪，并让人类数据与机器人数据共同训练统一策略。论文报告，增加人手数据呈现出较好的扩展趋势。[21]

VITRA 则对无标注的日常第一人称视频做自动化手部活动分析，生成原子动作片段、语言描述、逐帧 3D 手运动和相机运动，并构建约 100 万 episode、2,600 万帧的预训练数据。[22]

这条路线的好处是动作含义明确：人手向右移动 5 cm，可以转换成机器人末端的相对位移。它也容易与现有模仿学习数据格式结合。

但误差会逐层累积。相机位姿错一点，3D 手轨迹就会漂；手被物体遮挡，关键点会跳；人类握住杯子的姿态也不一定适合二指夹爪。更麻烦的是，动作通常不是唯一的：同一个物体变化可能由多种手部运动造成，同一条人手轨迹也可能有多种机器人实现。

因此伪动作不应被当成与真实机器人动作等价的真值。更合理的做法，是给它保留来源、置信度和本体信息，在训练中与真实动作使用不同权重。

### 21.5.4 从显式动作到 3D Flow、实体关系和潜在动作

当直接重定向太困难时，可以退一步，不再追求“人手关节到机器人关节”的一一对应，而是学习更通用的中间表示。

### 实体关系

HumanEgo 把示范提升为实体级手—物交互表示，让模型关注手、对象和任务关系，而不是人手外观本身。作者报告，每个任务约 30 分钟人类视频即可在四项真机任务上取得较高成功率，并跨机器人、相机和环境迁移。[23]

这类表示更接近任务本质。机器人不一定需要复制人手每个关节，只需要知道手从哪里接近、与对象哪个部位接触、对象随后如何移动。

### 3D Flow

EgoAVFlow 使用共享 3D flow 表示对象和相机在空间中的运动，同时预测机器人动作、未来 3D flow 和相机轨迹。[24] 3D flow 的好处是它比关节更跨本体，又比纯语义更接近运动。

例如“把杯子移到左侧”可以表示成对象点云或关键区域向左的三维位移场；不同机器人可以用各自的控制器实现同一个 flow 目标。

### 潜在动作

DreamDojo 使用连续潜在动作，让没有显式动作标签的视频也能参与世界模型预训练。[3] 潜在动作不要求我们预先定义“人类动作究竟对应机器人哪个关节”，而是先从视频变化中学习一组可控因素，再用少量机器人数据解码。

潜在动作的吸引力在于可扩展性，风险在于可解释性和可控性。一个 latent 可能同时混合相机运动、手部运动和对象变化；如果没有足够机器人数据约束，模型可能学到的是视频变化因子，而不是可以执行的动作因子。

这三条路线并不冲突。未来很可能是分层组合：

```text
语义与实体关系负责“做什么”
3D 轨迹 / flow 负责“世界怎样变化”
伪动作负责“机器人末端大致怎样动”
真实机器人动作负责“具体本体怎样执行”
潜在动作负责吸收无标签视频中的剩余变化
```

### 21.5.5 主动视角可能是第一人称数据最被低估的部分

谈第一人称视频时，人们通常先关注手部动作，但头部相机的运动同样重要。人类不是被动记录场景，而是在主动看。

拿一个杯子时，人会先转头找到杯子；手靠近后，视线可能转向抓取点；杯子被遮挡时，人会微调头部；放置时，又会看向目标区域。这些视角变化本身就是任务策略的一部分。

机器人如果只学习手部轨迹，却使用固定相机，可能很快进入看不见目标的状态。反过来，如果机械照搬人类头部轨迹，也可能因为机器人身体结构不同而产生无效动作。

EgoAVFlow 的做法很有代表性：它不直接模仿人类相机轨迹，而是根据预测运动和场景几何构造可见性奖励，在测试时优化机器人视角。[24]

这个思路说明，第一人称数据带来的不只是操作示范，还包含“什么时候应该看哪里”的先验。对移动操作、人形机器人和带云台相机的系统来说，主动视觉可能会成为与手臂动作同等重要的策略分支。

未来的动作空间可能不再只是机械臂 action，而是：

```text
身体动作 + 相机动作 + 观察时机
```

机器人不仅要学会做，还要学会让自己持续看得见。

### 21.5.6 数据平台会成为这个方向的核心基础设施

第一人称数据看起来比机器人数据容易采，但真正做到规模化并不简单。不同相机有不同内参、帧率和畸变；采集者身高、习惯和动作速度不同；隐私信息频繁出现；任务边界和语言描述也很难统一。

EgoVerse 的意义就在于把第一人称数据从单个实验室的数据集推进到协作平台。当前版本包含 1,362 小时、约 8 万个 episode，覆盖 1,965 个任务、240 个场景和 2,087 名示范者，并统一采集、处理、格式与跨实验室实验协议。[25]

这类平台真正需要长期维护的，不只是视频文件，还包括：

- 相机内参与时间戳；
- 相机、手、对象和场景坐标信息；
- 任务、子步骤和对象语义；
- 追踪置信度与遮挡标记；
- 数据来源和采集设备；
- 隐私脱敏与授权信息；
- 与机器人数据的映射方式；
- 可重复的数据划分和版本管理。

数据质量会直接决定动作桥接是否有效。手追踪不稳定的片段仍可以用于视觉预训练，但不适合当精确动作标签；任务描述模糊的片段可以学习世界动态，却不一定适合语言条件训练。未来的数据平台很可能会对同一段视频提供多层监督和不同可信度，而不是简单地把它归为“可用”或“不可用”。

在这个方向上，数据工程本身就是模型能力的一部分。谁能持续把海量视频转换成结构化、带置信度、可跨本体使用的 episode，谁就更可能获得稳定的 Scaling。

### 21.5.7 最终可能形成分层数据混合

第一人称人类视频不会取代机器人数据，仿真数据也不会取代真实数据。它们更像不同价格和不同信息密度的数据层。

```text
大规模普通第一人称视频
提供：场景、对象、任务过程、视觉动态

带 3D 手追踪 / 相机位姿的人类数据
提供：手—物几何、交互阶段、伪动作

UMI / 专用采集设备数据
提供：更接近机器人接口的末端轨迹和夹爪状态

仿真数据
提供：完整状态、接触、反事实动作和奖励真值

真实机器人数据
提供：本体动作、真实动力学、传感器与执行误差

真机 RL 与人工干预数据
提供：失败边界、恢复和高价值纠正
```

UMI 就是介于人类视频和机器人遥操作之间的一层：人手持带相机的夹爪在真实环境中示范，数据天然更接近机器人末端接口，同时仍保持便携和低成本。[26]

这类分层数据混合可能是更现实的路线。最便宜的数据负责覆盖世界，较贵的数据负责补充几何和动作，最贵的真机交互负责校准和验证。不同数据不需要完全同质，只需要在共享任务、对象和后果表示上建立联系。

从这个角度看，第一人称数据的长期价值可能不只是“增加一些机器人训练样本”，而是让机器人学习第一次拥有接近互联网规模的人类行为经验。真正决定这条路线能走多远的，是我们能否把这些经验从“可观看的视频”转换成“可行动的结构”。
