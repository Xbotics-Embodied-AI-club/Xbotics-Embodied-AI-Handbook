# 第 4 讲：传感器与感知基础

## 本讲学习目标

学完本讲后，学生应能够：
1. 理解机器人为什么需要传感器，以及不同传感器分别获取什么信息；
2. 根据任务需求选择合适传感器，并理解传感器参数对任务效果的影响；
3. 理解传感器数据如何进入机器人系统，并转化为目标位置、目标姿态、障碍物、接触状态等任务信息；
4. 掌握 RGB-D 相机反投影和 camera 到 base 坐标转换的基本流程；
5. 理解标定、坐标系、TF、多传感器对齐和感知误差对机器人真实执行效果的影响。

## 4.1 本讲主线：从“看到”到“能执行”

### 4.1.1 为什么需要传感器？

- 机器人需要获取外部环境信息；
- 机器人需要获取自身状态信息；
- 机器人需要根据环境变化调整动作；
- 传感器是机器人感知、决策和控制的输入来源。

### 4.1.2 传感器信息如何获取？

- 视觉传感器获取图像、深度和点云；
- 激光雷达获取距离和环境结构；
- 编码器获取关节角度、速度和轮速；
- IMU 获取加速度、角速度和姿态变化；
- 力觉 / 触觉传感器获取接触信息；
- 麦克风获取语音和声音事件。

### 4.1.3 传感器信息如何使用？

- 从原始数据中提取任务相关信息；
- 将传感器数据转换为空间信息；
- 将不同传感器数据统一到机器人坐标系；
- 将感知结果提供给规划和控制模块；
- 形成机器人可执行的目标位置、目标姿态或动作指令。

### 4.1.4 本讲整体逻辑

```text
传感器采集数据
↓
理解数据含义
↓
提取任务信息
↓
坐标转换与标定
↓
生成可执行目标
↓
规划与控制执行
```

## 4.2 机器人常用传感器：特点、参数与任务选型

- RGB 相机；
- RGB-D 相机 / 深度相机；
- 双目相机。

主要特点：
- RGB 相机适合识别、检测、分割；
- RGB-D 相机适合三维定位、点云生成和近距离抓取；
- 双目相机适合通过视差估计深度，常用于导航和三维重建。

- 视场角；
- 深度范围；

- RGB-depth 对齐；

### 4.2.2 测距与导航传感器

- 2D 激光雷达；
- 3D 激光雷达。

关键参数：

### 4.2.4 接触传感器

- 触觉传感器。

主要特点：

## 4.3 传感器数据如何进入机器人系统？

### 4.3.1 从物理世界到数据流

```text

↓
传感器采样
↓
驱动程序
↓
机器人中间件消息
↓
感知算法处理
↓
任务相关信息
↓
规划与控制模块
```

### 4.3.2 常见数据形式

- RGB 图像；
- 深度图；
- 点云；
- LaserScan；
- JointState；
- IMU；
- Force / Torque；
- Audio；
- TF。

### 4.3.3 原始数据为什么不能直接控制机器人？

- RGB 图像只有像素，没有真实距离；
- 深度图需要结合相机内参才能变成三维点；
- 点云通常还在相机或雷达坐标系下；
- 传感器数据可能存在噪声、延迟、缺失和单位错误；
- 控制器通常需要目标位姿、速度、力等结构化信息。

## 4.5 多传感器数据对齐与融合

### 4.5.1 为什么需要多传感器融合？

- 单一传感器存在信息缺失；
- 不同传感器可以相互补充；
- 复杂任务通常需要同时使用视觉、力觉、本体状态和环境感知信息。

### 4.5.2 时间对齐

- 不同传感器采样频率不同；
- 图像、IMU、LiDAR、编码器数据需要基于时间戳对齐；
- 时间不同步会导致感知和控制使用的不是同一时刻的信息。

### 4.5.3 空间对齐

- 每个传感器都有自己的坐标系；
- 相机、雷达、IMU、机械臂、夹爪的数据需要转换到统一坐标系；
- 空间对齐依赖外参和 TF。

### 4.5.4 语义对齐

- RGB 表示颜色和纹理；
- depth 表示距离；
- LiDAR 表示点云；
- force 表示力；
- tactile 表示接触状态；
- 多传感器融合需要明确不同数据在任务中的作用。

## 4.6 相机原理与坐标转换

### 4.6.1 为什么重点讲相机？

- 相机是机器人最常用的感知传感器之一；
- 视觉任务通常从图像开始；
- 图像中的像素点不能直接作为机器人目标点；
- 需要通过深度、内参、外参和坐标转换得到空间位置。

### 4.6.2 图像坐标系

- 像素点表示为 [u, v]；
- u 表示横向像素坐标；
- v 表示纵向像素坐标；
- 图像坐标原点通常在左上角。

### 4.6.3 相机内参

- fx：x 方向焦距；
- fy：y 方向焦距；
- cx：主点 x 坐标；
- cy：主点 y 坐标；
- 畸变参数。

相机内参矩阵：
K = [ fx   0   cx
0   fy   cy
0    0    1 ]

### 4.6.4 深度 Z

- 深度用于恢复像素点对应的三维位置；
- depth 单位可能是米或毫米；
- depth = 0 或 NaN 通常表示无效深度；
- RGB 和 depth 需要确认是否对齐；
- 透明、反光、黑色物体容易导致深度异常。

### 4.6.5 RGB-D 反投影

输入：
像素点：[u, v]
深度：Z
相机内参：fx, fy, cx, cy
输出：
相机坐标系下的三维点：[X, Y, Z]
核心公式：
X = (u - cx) * Z / fx
Y = (v - cy) * Z / fy
Z = depth

### 4.6.6 从 camera 坐标系到 base 坐标系

- 反投影得到的是 point_camera；
- 机器人规划和控制通常需要 point_base；
- 需要使用相机到机器人 base 的外参。

坐标转换关系：
point_base = T_base_camera · point_camera

### 4.6.7 从三维点到可执行目标

完整链路：
pixel [u, v]
↓ depth + intrinsics
point_camera [X, Y, Z]
↓ T_base_camera
point_base [x, y, z]
↓ grasp pose generation
target_pose_base [x, y, z, qx, qy, qz, qw]
↓ motion planning
robot execution

## 4.7 感知误差与任务失败

### 4.7.1 图像层误差

- 图像模糊；
- 曝光异常；
- 光照变化；
- 目标遮挡；
- 检测框不准；
- mask 分割不准。

### 4.7.2 深度层误差

- depth 噪声；
- depth 单位错误；
- depth 空洞；
- RGB-depth 未对齐；
- 特殊材质导致深度异常。

### 4.7.3 坐标转换层误差

- 内参错误；
- 外参错误；
- 外参方向写反；
- 坐标轴方向理解错误；
- 齐次矩阵乘法顺序错误。

### 4.7.4 系统层误差

- 时间戳不同步；
- TF 树断裂；
- frame 名称不一致；
- 传感器安装松动；
- 目标点不可达；
- 夹爪姿态不合理；
- 运动规划碰撞。

### 4.7.5 误差传递链路

```text
图像检测误差
↓
深度读取误差
↓
三维反投影误差
↓
相机到 base 坐标转换误差
↓
目标位姿误差
↓
运动规划偏差
↓
抓偏、抓空、碰撞或损坏物体
```

## 4.8 标定：让传感器和真实空间对齐

### 4.8.1 什么是标定？

- 建立传感器数据与真实物理空间之间的关系；
- 建立不同坐标系之间的转换关系；
- 让感知结果能够被机器人规划和控制模块正确使用。

### 4.8.2 相机内参标定

主要得到：
- fx；
- fy；
- cx；
- cy；
- 畸变参数。

解决问题：
- 相机如何成像；
- 图像点如何反投影到三维空间；
- 三维点如何投影到图像平面。

### 4.8.3 相机外参标定

主要得到：
- T_base_camera；
- 或 T_camera_base。

解决问题：
- 相机相对于机器人 base 在哪里；
- 相机坐标系如何转换到机器人坐标系。

### 4.8.4 手眼标定

- Eye-to-hand：相机固定在外部；
- Eye-in-hand：相机安装在机械臂末端。

典型链路：
Eye-to-hand:
base → camera → object

Eye-in-hand:
base → end_effector → camera → object

### 4.8.5 LiDAR 标定

- lidar 到 base 的外参；
- lidar 到 camera 的外参；
- lidar 到 IMU 的外参；
- 多 lidar 之间的外参。

### 4.8.6 IMU 标定

- 加速度计零偏；
- 陀螺仪零偏；
- 噪声参数；
- 安装方向；
- IMU 到 base 的外参；
- 时间同步。

### 4.8.7 力传感器标定

- 零点标定；
- 工具重力补偿；
- 安装坐标系标定；
- 力和力矩方向校正。

### 4.8.8 标定后的工程验证

- 在已知位置放置标定物；
- 计算视觉估计位置；
- 与真实测量位置对比；
- 多个位置重复测试；
- 记录平均误差和最大误差；
- 用真实机器人动作验证目标点是否准确。

## 4.9 坐标系、位姿表示与 ROS2 TF

### 4.9.1 为什么需要坐标系？

- 相机、雷达、IMU、机器人 base、机械臂末端和物体都有自己的坐标系；
- 机器人需要把不同坐标系下的信息统一起来；
- 控制指令通常需要在 base 或 end-effector 坐标系下表达。

### 4.9.2 常见坐标系

> 待补充：该图表内容需从原飞书文档或源素材补齐。

### 4.9.3 位姿表示

- 平移向量；
- 旋转矩阵；
- 欧拉角；
- 四元数；
- 齐次变换矩阵。

### 4.9.4 点、向量和位姿的变换

点的变换：
p_base = T_base_camera · p_camera
位姿的变换：
T_base_object = T_base_camera · T_camera_object

### 4.9.5 ROS2 TF 解决什么问题？

- 描述坐标系之间的关系；
- 查询任意两个 frame 之间的变换；
- 管理静态变换和动态变换；
- 让感知、规划、控制模块使用统一空间表达。

### 4.9.6 TF 树

- parent frame；
- child frame；
- static transform；
- dynamic transform；
- transform broadcaster；
- transform listener；
- TF buffer；
- timestamp。

### 4.9.7 常见 TF 链路

移动机器人：
map → odom → base_link → lidar
机械臂视觉抓取：
base → camera → object
Eye-in-hand 系统：
base → end_effector → camera → object
移动操作机器人：
map → odom → base → arm_base → end_effector → camera → object

### 4.9.8 TF 常见问题

- frame 名称不一致；
- TF 树断裂；
- 外参方向写反；
- static transform 发布错误；
- dynamic transform 时间戳不同步；
- 坐标轴方向理解错误；
- base、base_link、world、map 混用；
- 查询 TF 的时间点不存在；
- camera frame 和 camera optical frame 混淆。

### 4.10.7 常见排错 checklist

1. depth 单位是否正确？
2. u / v 顺序是否正确？
3. RGB 和 depth 是否对齐？
4. 内参是否匹配当前分辨率？
5. depth 是否有效？
