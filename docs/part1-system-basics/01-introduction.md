## 本讲提要

![图 1-1 从“回答问题”到“改变世界”](part1_picture/Lecture1_picture/figure-1-1.png)

*图 1-1 从“回答问题”到“改变世界”*

具身智能讨论的不是“模型能不能回答问题”，而是“一个有身体的智能体能不能在真实世界中可靠地完成任务”。

在数字世界里，AI 往往完成一次性的输入输出：给一段文字，生成一段回答；给一张图片，输出一个类别；给一个提示词，生成一张图。输出结果即使不理想，通常也只是信息层面的错误。

机器人则不同。机器人输出的是动作，动作会改变物体的位置、机器人的姿态以及下一次传感器看到的内容。一次抓偏、一次碰撞、一次路径规划错误，都可能影响后续任务，甚至带来安全风险。

所以，本讲的主线可以概括为：

```text
数字 AI：输入数据 → 模型推理 → 输出结果
具身智能：观察环境 → 决策动作 → 改变环境 → 获得反馈 → 持续修正
```

完成本讲后，读者应能够：

1. 说明具身智能与传统 AI、传统机器人、大模型应用之间的区别；
2. 画出具身智能系统的基本闭环；
3. 初步理解传统 pipeline、模仿学习、强化学习、VLA、世界模型和人形机器人等路线；
4. 解释为什么机器人系统必须关注实时性、安全性、物理约束、失败恢复和数据回流；
5. 完成一个最小机器人闭环 Demo，并能说清楚其中的状态、动作、反馈和数据记录。

## 1.1 本讲导入：为什么 AI 进入物理世界后问题变了？

人工智能在文本、图像、视频和代码任务上取得了显著进展。这些任务的共同点是：输入和输出都可以表示为数字信息，模型主要学习这些信息之间的规律。

然而，一旦 AI 进入物理世界，问题就不再只是“理解”或“生成”。机器人需要看见环境、判断目标、移动身体、接触物体、处理失败，并保证安全。它的每一步动作都会改变世界，世界又会反过来影响下一步感知和决策。

这也是具身智能与普通大模型应用之间最根本的区别。

### 1.1.1 从静态推理到动态交互

普通 AI 更像是在回答一个问题：

```text
输入 → 模型 → 输出
```

机器人更像是在参与一个过程：

```text
观察 → 决策 → 行动 → 环境变化 → 再观察 → 再决策
```

比如，一个视觉模型识别错了杯子，图片本身不会改变；但机器人抓错了杯子，杯子可能被碰倒，桌面状态也会变化。下一次感知面对的已经不是原来的环境。

因此，具身智能必须强调闭环：系统不能只在一开始做一次判断，而要在任务执行过程中不断观察、不断修正。

### 1.1.2 “说得对”与“做得成”的差距

大语言模型可以很好地回答“如何抓杯子”：先定位杯子，再规划路径，打开夹爪，接近杯子，闭合夹爪，抬起物体。

这段回答在语言层面是合理的，但真实机器人还要解决更多问题：

1. 杯子是否真的在相机视野中？
2. 杯子是否透明、反光或被遮挡？
3. 杯子的三维位置如何估计？
4. 相机坐标系如何转换到机器人坐标系？
5. 夹爪从哪个角度接近更稳定？
6. 机械臂路径是否会碰撞桌面或其他物体？
7. 夹爪力度是否合适？
8. 抓取失败后如何判断和重试？
9. 人突然靠近时是否需要停机？

这些问题只有一小部分属于语言理解，更多属于感知、几何、规划、控制、反馈、安全和数据系统。

### 1.1.3 物理世界带来的四类约束

AI 进入物理世界后，会遇到四类新约束。

第一是实时性约束。机器人控制有频率要求，不能无限等待模型推理。比如移动机器人避障、人形机器人平衡、机械臂接触控制，都要求系统在很短时间内完成感知和反应。

第二是安全性约束。机器人有电机、关节和动能，错误动作可能导致碰撞、损坏物体，甚至伤害人。任何模型输出的动作，都应该经过安全边界检查。

第三是物理可行性约束。机械臂关节不能超过角度范围，夹爪不能穿过物体，底盘不能瞬间移动，人形机器人不能违反平衡条件。模型想得再好，也必须被身体和物理规律允许。

第四是闭环反馈约束。真实环境会变化，物体会滑动，人会走进工作区，目标会被遮挡。因此机器人必须根据最新观察持续调整动作，而不是只执行一条固定轨迹。

### 1.1.4 本节小结

从普通 AI 到具身智能，最大的变化不是模型形式，而是任务形态发生了变化：

| 普通 AI | 具身智能 |
| --- | --- |
| 处理静态或离线数据 | 面对动态物理环境 |
| 输出文本、标签、图像 | 输出动作、轨迹、控制指令 |
| 错误多是信息错误 | 错误可能造成物理后果 |
| 单次推理即可完成很多任务 | 必须持续闭环执行 |
| 数据主要来自互联网 | 数据来自真实机器人交互和仿真 |

本课程后续讨论数据采集、模仿学习、VLA、世界模型和部署，都是围绕这条主线展开：让机器人能够在真实世界中稳定、可靠、可持续地完成任务。

## 1.2 第一张地图：什么是具身智能？

![图 1-2 具身智能体由什么组成](part1_picture/Lecture1_picture/figure-1-2.png)

*图 1-2 具身智能体由什么组成*

理解具身智能，首先要理解“具身”。这里的身体不是简单外壳，而是智能体感知世界、作用世界和获得反馈的基础。

人类理解杯子，不只是因为见过杯子的图片，还因为我们可以伸手去拿，感受它的重量，判断里面是否有水，预测它是否容易倾倒。对机器人而言，物体也不是静态标签，而是可抓取、可推动、可避让、可放置或可使用的对象。

因此，可以这样定义具身智能：

> 具身智能是指智能体依托身体，在真实或仿真的物理环境中，通过感知、理解、规划、行动、反馈和学习，完成开放世界任务的能力。

### 1.2.1 具身智能体的七个组成部分

一个完整的具身智能体通常包括七个组成部分。

| 组成部分 | 作用 | 例子 |
| --- | --- | --- |
| 身体 | 决定能做什么 | 机械臂、移动底盘、人形机器人、灵巧手 |
| 感知 | 决定能看到什么 | RGB 相机、深度相机、力觉、触觉、IMU |
| 状态 | 决定是否知道自己在哪里 | 关节角、末端位姿、夹爪状态、底盘位姿 |
| 任务 | 决定要做什么 | 抓杯子、搬箱子、整理桌面、补货 |
| 策略 | 决定下一步怎么做 | 规划器、模仿学习策略、VLA 策略 |
| 控制 | 决定动作能否稳定执行 | 位置控制、速度控制、力控、全身控制 |
| 数据 | 决定系统能否持续变好 | 示教数据、失败样本、部署日志、标签 |

这张表提醒我们：不要只讨论“大模型”。同一个模型放到不同身体上，动作空间不同；同一个任务换一种传感器，感知质量不同；同一种算法换一批数据，效果也会发生变化。

### 1.2.2 身体不是容器，而是能力边界

身体决定了智能体的能力边界。

机械臂擅长桌面抓取和固定工位操作，但很难自己移动到另一个房间。移动底盘可以导航，但没有机械臂就无法操作物体。人形机器人理论上最适合进入人类环境，但它需要处理平衡、双臂协同和安全问题，复杂度也最高。

因此，具身智能课程不能脱离硬件本体。一个算法是否有效，必须放在具体身体、具体传感器和具体任务中讨论。

### 1.2.3 感知不是“看见”，而是获得可行动信息

机器人感知的目标不是描述画面，而是为行动提供依据。

例如桌面上有一个红色杯子。普通图像理解只要说出“这里有杯子”即可；机器人还需要知道杯子在哪里、离夹爪多远、从哪个方向抓更稳、周围是否有障碍、杯子是否可能滑动。

所以，对机器人来说，有用的感知信息通常包括：

1. 目标类别；
2. 目标位置；
3. 目标姿态；
4. 可抓取区域；
5. 障碍物位置；
6. 接触状态；
7. 是否完成任务。

### 1.2.4 数据让系统形成长期学习能力

如果机器人每次失败都被简单忽略，系统就很难进步。相反，如果失败被记录下来，经过筛选和标注，再用于下一轮训练，那么机器人就有机会逐步提升。

具身智能中的数据通常包括：图像、深度、关节状态、动作、语言指令、任务结果、人工修正和失败原因。这些数据共同构成后续模型训练和评测的基础。

## 1.3 具身智能系统闭环：机器人到底如何完成一个任务？

![图 1-3 机器人任务闭环](part1_picture/Lecture1_picture/figure-1-3.png)

*图 1-3 机器人任务闭环*

为了理解具身智能系统，可以从一个简单任务出发：

> 把桌上的红色杯子放到托盘里。

这个任务对人来说很自然，但对机器人来说，它包含多个连续步骤：理解任务、找到目标、估计位置、选择抓取方式、控制机械臂、检查是否抓住、移动到托盘、放下物体、判断结果。

### 1.3.1 任务输入：从用户意图到机器可执行目标

用户通常用自然语言表达任务，例如“把红色杯子放到托盘里”。机器人需要把这句话转化为更具体的执行目标：目标物是红色杯子，目标区域是托盘，动作是抓取并放置。

对于复杂任务，系统还要生成子目标。例如“整理桌面”可以拆成：识别桌面物体、判断哪些需要整理、逐个抓取、放到对应区域、检查桌面是否清空。

### 1.3.2 环境感知：识别目标和约束

机器人需要通过相机、深度传感器或其他传感器感知环境。它不仅要找到目标物，还要识别托盘、桌面边缘、障碍物以及可能影响抓取的因素。

在真实系统中，感知往往是最容易出问题的环节之一。光照变化、遮挡、反光、透明物体、堆叠场景都会让感知变得困难。

### 1.3.3 状态估计：知道自己和目标在哪里

机器人要行动，必须知道自己在哪里，也要知道目标在哪里。

机械臂需要知道各个关节角度、末端位置、夹爪状态；移动机器人需要知道自己在地图中的位置；人形机器人还需要知道身体姿态、重心和平衡状态。

如果状态估计不准，后面的规划和控制都会受到影响。

### 1.3.4 策略与规划：决定下一步做什么

策略负责决定“下一步做什么”，规划负责把目标转化为可执行路径。

传统 pipeline 往往显式生成抓取点和轨迹；模仿学习可能直接从图像和状态预测动作；VLA 则把视觉、语言和状态结合起来输出动作建议。

真实系统常常采用混合方式：高层模型负责理解任务，传统规划器负责路径可行性，低层控制器负责稳定执行，安全模块负责兜底。

### 1.3.5 控制执行：把决策变成稳定动作

策略输出的“下一步动作”还不能直接等同于电机命令。控制层要把目标位置、速度或轨迹变成机器人可以执行的控制信号。

可以用一句直观的话理解最小控制器：

> 当前位置离目标越远，移动指令越大；越接近目标，移动指令越小。

这就是很多基础控制器的核心思想。后续课程会再展开更完整的控制方法。

### 1.3.6 反馈检测与失败恢复

机器人必须能判断任务是否真的完成。例如：

1. 是否抓住了杯子？
2. 杯子是否掉落？
3. 是否放到了托盘里？
4. 是否发生碰撞？
5. 是否需要重新抓取？

如果系统没有反馈检测，即使模型输出了动作，也无法确认任务结果。反馈检测是机器人从“执行动作”走向“完成任务”的关键。

### 1.3.7 数据记录与模型迭代

每次执行任务都可以产生数据。成功数据告诉我们哪些行为有效，失败数据告诉我们系统在哪些地方不可靠。

一个良好的机器人系统应该记录：任务指令、图像、状态、动作、时间戳、成功失败标签、异常原因和人工修正。它们会成为下一轮模型训练和系统优化的原材料。

## 1.4 技术路线总览：从传统机器人到 VLA 与世界模型

![图 1-4 五条技术路线的关系](part1_picture/Lecture1_picture/figure-1-4.png)

*图 1-4 五条技术路线的关系*

具身智能不是单一技术路线，而是多种路线共同发展的领域。不同路线解决的问题不同，适合的场景也不同。

### 1.4.1 传统机器人 Pipeline

传统机器人系统通常把任务拆成多个模块：感知、定位、规划、控制和安全。每个模块完成相对明确的功能，再通过工程接口连接起来。

以工业抓取为例，流程通常是：相机拍照，检测物体，估计位置，生成抓取姿态，规划机械臂轨迹，控制夹爪执行，最后检测是否成功。

这种方式的优点是可解释、易调试、工程边界清晰，特别适合结构化工业场景。缺点是泛化能力有限，遇到开放物体、复杂遮挡或长时序任务时，系统维护成本较高。

### 1.4.2 模仿学习

模仿学习的核心思想是：让机器人从示教数据中学习行为。

人类先通过遥操作、拖动示教或脚本控制完成任务，系统记录每一时刻的图像、状态和动作。模型训练后，学会在类似场景中输出类似动作。

模仿学习的优点是上手相对直接，适合真实机器人任务。缺点是对数据质量非常敏感。如果训练数据没有覆盖某些情况，机器人在部署时就可能失败。

### 1.4.3 强化学习与仿真训练

强化学习让机器人通过试错学习策略。由于真实机器人试错成本高、风险大，很多强化学习任务会先在仿真中训练，再迁移到真实机器人。

强化学习特别适合运动控制、灵巧手操作、高速动态任务和接触丰富任务。例如四足机器人行走、人形机器人平衡、灵巧手转动物体等。

它的挑战是：需要好的仿真环境、合理的奖励设计、大量算力，以及严格的真机安全验证。

### 1.4.4 VLA：视觉—语言—动作模型

![图 1-5 VLA：视觉、语言与动作的桥梁](part1_picture/Lecture1_picture/figure-1-5.png)

*图 1-5 VLA：视觉、语言与动作的桥梁*

VLA 的目标是把视觉、语言和动作统一到一个模型中。它希望机器人能够“看见场景、听懂指令、输出动作”。

例如，输入是桌面图像、语言指令“把红色积木放进盒子里”和当前机械臂状态；输出是下一段机械臂动作和夹爪动作。

VLA 的价值在于：语言降低了任务定义成本，视觉提供了环境信息，动作输出让模型直接参与控制。它为多任务、多物体、多场景泛化提供了可能。

但 VLA 不能替代整个机器人系统。真实部署仍然需要低层控制器、安全约束、失败检测、数据回流和工程监控。

### 1.4.5 世界模型与 World Action Model

![图 1-6 世界模型：行动前先“预演”](part1_picture/Lecture1_picture/figure-1-6.png)

*图 1-6 世界模型：行动前先“预演”*

世界模型关注的是：机器人能不能在行动前预测未来。

比如机器人有三个候选动作：从左侧抓、从上方抓、先推开障碍再抓。世界模型可以帮助系统估计每种动作可能带来的后果：是否会碰撞，是否会掉落，是否更可能成功。

它的价值不是生成好看的视频，而是帮助机器人理解动作对环境的影响。对于长时序任务和高风险任务，提前预演和比较动作非常重要。

### 1.4.6 路线不是互斥的

真实机器人系统往往是混合架构。可以这样理解：

1. 传统 pipeline 提供可解释和稳定的工程基础；
2. 模仿学习从真实示教中获得操作能力；
3. 强化学习适合在仿真中学习运动和接触技能；
4. VLA 提供语言理解和多任务泛化能力；
5. 世界模型帮助机器人预判未来后果；
6. 安全系统和低层控制器为所有路线提供兜底。

## 1.5 应用场景与课程硬件体系

![图 1-8 应用场景难度阶梯](part1_picture/Lecture1_picture/figure-1-8.png)

*图 1-8 应用场景难度阶梯*

具身智能最终要落到具体任务和具体硬件上。不同场景对系统能力的要求不同，难点也不同。

### 1.5.1 典型应用场景

| 场景 | 典型任务 | 主要难点 |
| --- | --- | --- |
| 桌面抓取 | 抓杯子、积木、工具 | 目标定位、抓取点、夹爪控制 |
| 移动操作 | 移动到桌边并抓取 | 导航与操作协同、坐标统一 |
| 工业分拣 | 多品类识别和抓取 | 成功率、节拍、异常处理 |
| 商超零售 | 货架识别、补货、拣货 | 商品种类多、摆放变化大 |
| 家庭服务 | 整理桌面、倒水、开门 | 环境开放、安全要求高 |
| 实验室自动化 | 移液、试管抓取、样本分拣 | 高精度、小物体、流程追踪 |
| 人形机器人 | 行走、搬箱、双臂操作 | 全身控制、平衡、人机共处 |

从教学角度看，可以按照难度逐步推进：先做桌面操作，再做移动操作，再进入工业和商超场景，最后讨论家庭服务和人形机器人。

### 1.5.2 机器人本体与本课程硬件体系

本课程强调“仿真可跑，真机可落地”。有硬件的学员可以完成真实机器人实验，没有硬件的学员也可以通过仿真环境完成核心 Demo。

机器人本体与技术路线不是同一个分类维度。机械臂、移动机器人和人形机器人描述的是智能运行在什么身体上；传统 pipeline、模仿学习、强化学习、VLA 和世界模型描述的是系统怎样获得或组织能力。同一种技术路线可以部署到不同本体，同一种本体也可以组合多种技术路线。

人形机器人之所以受到关注，是因为门把手、楼梯、桌椅和工具等人类环境本来就按照人的尺度设计。但人形机器人也是最复杂的本体之一，需要同时处理行走与平衡、双臂协同、全身控制、环境感知、任务规划、安全约束和人机共处。它不是简单“把 VLA 装到人形身体上”，而是软硬件系统共同协作的结果。

| 硬件平台 | 定位 | 适合学习内容 |
| --- | --- | --- |
| SO101 教学机械臂 | 入门级桌面操作平台 | 机械臂控制、数据采集、简单抓取 |
| xLeRobot 移动操作套件 | 移动底盘 + 教学机械臂 | 导航与操作结合、移动抓取 |
| Imeta-Y1 科研机械臂 | 更接近工程应用 | 工业分拣、复杂抓取、VLA 部署 |
| Unitree G1 人形机器人 | 前沿人形平台 | 全身控制、人形操作、遥操作数据 |

硬件平台不是简单的教学道具，而是帮助学生理解不同任务复杂度的载体。不同身体形态会带来不同动作空间、控制方式和安全要求。

## 1.6 本讲体验 Demo：从目标到动作

![图 1-9 最小 Demo：目标点控制闭环](part1_picture/Lecture1_picture/figure-1-9.png)

*图 1-9 最小 Demo：目标点控制闭环*

本讲 Demo 不追求复杂算法，而是让学生体验一个最小闭环：输入目标，读取当前状态，计算差距，给出动作，执行并观察反馈。

### 1.6.1 Demo 目标

这个 Demo 要让学生看到：即使只是让机械臂末端接近一个目标点，也已经包含了具身智能系统的基本要素。

最小闭环包括：

```text
目标点 → 当前状态 → 差距判断 → 控制指令 → 机器人动作 → 轨迹记录 → 结果判断
```

其中，“差距判断”可以用非常直观的话解释：当前位置离目标越远，机器人移动得越明显；越接近目标，动作越小，直到停止。

### 1.6.2 有硬件版本

硬件可选 SO101 教学机械臂或 Imeta-Y1 科研机械臂。

任务是给定一个目标末端位置，让机械臂末端移动到目标点附近。系统需要输出当前关节状态、当前末端位置、目标位置、控制指令、执行轨迹和是否到达目标。

学生观察重点包括：

1. 机器人是否接近目标；
2. 是否出现过冲或震荡；
3. 速度是否过快；
4. 目标点是否超出工作空间；
5. 坐标系方向是否理解正确；
6. 停止误差是否可接受。

### 1.6.3 无硬件版本：二维闭环示意

本仓库默认提供的是一个纯 Python 二维 reaching 示例：把二维点看作“被控制的末端位置”，不断计算当前位置与目标点的差距，并以受限步长逐步接近目标。它用于解释闭环思想，不包含机械臂运动学、动力学、碰撞或传感器仿真，因此不应把它描述成完整机械臂仿真。

运行方式：

```bash
cd code/lecture01
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python simulation/minimal_reach.py
```

程序会在 `simulation/outputs/` 下生成 `result.json` 和 `trajectory.png`。读者应检查最终误差、是否到达目标、执行步数和运动轨迹，并修改 `target_eef`、`step_size`、`threshold` 观察系统行为怎样变化。

若希望进一步接近真实机器人，可以在后续实验中把二维点替换为 MuJoCo、ManiSkill、Isaac Lab 或 ROS2 mock robot 中的机械臂，但这些平台不属于本讲默认 Demo 的必要条件。

学生应观察轨迹是否平滑、目标改变后系统如何响应、控制参数变化对运动是否有影响。

### 1.6.4 Demo 复盘问题

完成 Demo 后，可以让学生回答：

1. 输入目标点属于哪个模块？
2. 当前状态从哪里来？
3. 为什么需要比较当前位置和目标位置？
4. 控制器为什么不能让机器人一次性跳到目标？
5. 如果没有反馈，系统如何知道是否完成？
6. 如果记录这次执行数据，后续可以怎样用于训练？

这些问题能帮助学生把一个小实验和整套具身智能系统联系起来。

### 1.7.2 课堂讨论题

建议保留五个核心讨论题：

1. 为什么 ChatGPT 能回答“怎么抓杯子”，但不能直接让机器人稳定抓住杯子？
2. 为什么机器人必须有状态反馈？
3. 为什么仿真中成功的策略到真实机器人上可能失败？
4. 为什么 VLA 很重要，但不能替代所有机器人模块？
5. 如果让机器人完成“整理桌面”，你会如何拆解系统模块？

### 1.7.3 常见误区与复盘

| 常见误区 | 正确认识 |
| --- | --- |
| 具身智能就是大模型控制机器人 | 大模型只负责部分理解和推理，机器人还需要感知、控制、安全和数据系统 |
| 端到端模型一定比传统 pipeline 好 | 真实系统常常是混合架构，不同模块各有价值 |
| 仿真成功就等于真机成功 | 真机存在摩擦、延迟、传感器噪声、接触误差和安全约束 |
| 只要数据多，机器人就一定能学会 | 数据还要覆盖关键场景、失败情况、恢复动作和边界条件 |
| 人形机器人只是换了一个外形 | 人形涉及全身平衡、双臂协同、接触控制和人机共处 |

### 1.8.2 本讲需要记住的五件事

第一，具身智能是 AI 进入物理世界后的系统性问题，不是单个模型问题。

第二，具身智能的核心是闭环。机器人必须不断观察、行动、获得反馈并修正行为。

第三，大模型、VLA 和世界模型很重要，但不能脱离身体、传感器、控制、安全和数据。

第四，真实可落地的系统通常是混合架构：高层理解、策略生成、低层控制、安全约束和数据回流共同工作。

第五，后续课程会从本讲的概念地图继续向工程系统和学习算法展开：

```text
系统架构 → 本体与控制 → 传感器与坐标系 → 仿真与操作
→ 数据采集 → 模仿学习与生成式策略 → VLA → 强化学习
→ Robot Agent 与 VLN → 世界模型 → 综合部署与复盘
```

下一讲将首先回答一个工程问题：这套闭环分别运行在哪些硬件和软件上，模块之间又怎样通信、同步和排错。

### 1.8.3 本讲一句话总结

> 具身智能不是让机器人会说话，而是让机器人能在真实世界中可靠地做事。
