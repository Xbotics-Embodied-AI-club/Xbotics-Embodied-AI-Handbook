# 第 2 讲：机器人系统架构

## 2.1 本讲主线：从“单个模型”到“机器人系统”

### 2.1.1 为什么这一讲很重要？

- 具身智能不是单个模型，而是由多个模块持续通信、持续反馈、持续记录数据的完整系统；
- VLA、世界模型、模仿学习、强化学习等模型通常只是机器人系统中的策略层或智能层；
- 真实机器人任务需要感知、状态读取、策略决策、控制执行和数据记录共同工作；
- 学生需要先理解机器人系统架构，后续学习 VLA、模仿学习和世界模型时，才能知道这些算法如何接入真实机器人。

### 2.1.2 本讲学习目标

学完本讲后，学生应能够：
1. 理解机器人系统为什么需要多个模块协同工作；
2. 理解机器人系统中本体层、控制层、感知层和策略层的关系；
3. 理解 ROS2 中 Node、Topic、Service、Action 和 Launch 的基本作用；
4. 判断 VLA、世界模型、模仿学习、强化学习在机器人系统中的位置；
5. 能够搭建一个最小机器人闭环：读取状态、发布目标、生成动作、执行控制、记录数据。

### 2.1.3 本讲整体逻辑

```text
机器人本体
↓
ROS2 驱动节点
↓
状态读取
↓
感知模块
↓
策略模型
↓
控制器
↓
动作执行
↓
任务反馈
↓
数据记录
```

## 2.2 机器人系统四层结构

### 2.2.1 本体层

包括：
- 机械臂；
- 夹爪；
- 移动底盘；
- 相机；
- 深度相机；
- 电机；
- 编码器；
- IMU；
- 力传感器。

作用：
- 在真实物理世界中执行动作；
- 采集环境信息和自身状态；
- 决定机器人能做什么任务。

### 2.2.2 控制层

包括：
- 关节控制；
- 末端控制；
- 速度控制；
- 夹爪控制；
- 安全限制；
- 控制频率管理；
- 动作平滑与限幅。

作用：
- 把策略层输出的 action 转换成机器人可以执行的控制指令；
- 保证动作安全、稳定、连续；
- 处理关节限位、速度限制、碰撞风险和急停保护。

### 2.2.3 感知层

包括：
- 图像采集；
- 深度采集；
- 点云处理；
- 目标检测；
- 图像分割；
- 状态估计；
- 目标位姿估计；
- 环境感知。

作用：
- 从传感器数据中提取任务相关信息；
- 为策略模型提供观测输入；
- 为控制和规划提供目标、障碍物和状态信息。

### 2.2.4 策略层

包括：
- 任务理解；
- VLA；
- ACT；
- Diffusion Policy；
- 模仿学习策略；
- 强化学习策略；
- 世界模型；
- 高层规划模块。

作用：
- 根据观测、任务指令和当前状态生成动作或目标；
- 决定机器人下一步应该做什么；
- 将语言、视觉和状态信息转化为机器人动作。

## 2.3 ROS2 基础：机器人模块如何通信？

### 2.3.1 ROS2 在机器人系统中的作用

- 将机器人系统拆分成多个可独立运行的节点；
- 让感知、控制、策略、记录等模块通过消息通信；
- 支持连续数据流、短请求和长任务执行；
- 便于调试、可视化、复用和扩展机器人系统。

### 2.3.2 Node

- Node 是 ROS2 中的基本运行单元；
- 一个节点通常负责一个功能模块；
- 常见节点包括相机节点、状态节点、策略节点、控制节点和数据记录节点。

示例：
- camera_node；
- robot_state_node；
- target_publisher；
- policy_node；
- controller_node；
- task_status_node；
- episode_recorder。

### 2.3.3 Topic

适合连续数据流。
常见用途：
- 发布相机图像；
- 发布关节状态；
- 发布目标点；
- 发布动作指令；
- 发布夹爪命令；
- 发布任务状态。

示例：
- /camera/image；
- /joint_states；
- /target_pose；
- /action_command；
- /gripper_command；
- /task_status。

### 2.3.4 Service

适合短请求和立即返回结果的任务。
常见用途：
- 查询机器人状态；
- 切换控制模式；
- 复位系统；
- 开启或关闭夹爪；
- 清空缓存；
- 保存当前配置。

示例：
- /reset_robot；
- /set_mode；
- /get_status；
- /save_episode。

### 2.3.5 Action

适合需要一段时间完成的长任务。
常见用途：
- 移动到目标点；
- 执行抓取；
- 完成一段轨迹；
- 导航到指定位置；
- 执行一个完整任务。

特点：
- 可以持续反馈进度；
- 可以取消任务；
- 可以返回最终执行结果；
- 比 Service 更适合机器人长时间动作。

### 2.3.6 Launch

- 用于统一启动多个节点；
- 用于配置参数、命名空间和启动顺序；
- 适合组织完整机器人系统；
- 可以一键启动硬件驱动、感知、策略、控制和记录模块。

## 2.4 具身智能前沿模型在系统中的位置

### 2.4.1 VLM / 检测 / 分割模型

主要位于感知层。
作用：
- 理解图像内容；
- 识别目标物体；
- 输出 bbox、mask 或目标区域；
- 为后续定位、抓取和策略提供视觉信息。

### 2.4.2 VLA 模型

主要位于策略层。
作用：
- 接收语言指令、图像观测和机器人状态；
- 输出机器人 action、目标位姿或动作序列；
- 连接任务理解和机器人执行。

### 2.4.3 ACT / Diffusion Policy

主要位于策略层。
作用：
- 根据观测生成动作；
- 常用于模仿学习；
- 可以输出单步 action，也可以输出 action chunk；
- 需要接入控制器和安全限制后才能执行。

### 2.4.4 强化学习

可用于策略层，也可用于控制层。
常见用途：
- 四足机器人运动控制；
- 人形机器人平衡和行走；
- 灵巧操作；
- 仿真策略训练；
- 低层控制策略学习。

### 2.4.5 世界模型

主要用于预测、规划和数据生成。
作用：
- 预测未来状态；
- 辅助动作规划；
- 评估不同动作后果；
- 生成或增强训练数据；
- 支持更长时序的任务推理。

### 2.4.6 数据飞轮

贯穿完整系统。
包括：
- 任务执行；
- 数据采集；
- 失败记录；
- 数据清洗；
- 训练样本生成；
- 模型训练；
- 模型部署；
- 任务复盘；
- 再采集和再训练。

## 2.5 机器人系统闭环：从状态读取到数据记录

### 2.5.1 最小机器人闭环

```text
读取状态
↓
发布目标
↓
生成动作
↓
下发控制
↓
执行运动
↓
读取反馈
↓
判断结果
↓
记录 episode
```

### 2.5.2 状态读取

包括：
- 关节位置；
- 关节速度；
- 夹爪状态；
- 相机图像；
- 深度图；
- 目标点；
- 任务状态。

### 2.5.3 动作生成

动作可以来自：
- 手写规则；
- 简单控制策略；
- 模仿学习模型；
- VLA 模型；
- 强化学习策略；
- 世界模型辅助规划。

### 2.5.4 动作执行

执行前需要检查：
- 动作范围；
- 速度限制；
- 关节限位；
- 碰撞风险；
- 控制频率；
- 夹爪状态；
- 急停条件。

### 2.5.5 任务反馈

反馈信息包括：
- 是否到达目标；
- 是否抓取成功；
- 是否发生碰撞；
- 是否超时；
- 是否丢失目标；
- 是否需要重试。

### 2.5.6 Episode 数据记录

一个 episode 通常包括：
- 图像；
- 状态；
- action；
- 目标；
- 时间戳；
- 任务结果；
- 成功 / 失败标签；
- 异常信息。

## 2.6 Demo 设计：基于 ROS2 的 LeRobot / SO101 最小闭环

### 2.6.1 Demo 目标

```text
完成一个基于 ROS2 的最小机器人闭环：
读取 joint_states
↓
发布 target_pose 或 target_joint
↓
policy_node 生成 action_command
↓
controller_node 下发动作
↓
读取反馈状态
↓
判断是否到达目标
↓
保存 episode 数据
```

### 2.6.2 有硬件版 Demo

Demo 名称：
- 基于 ROS2 的 LeRobot / SO101 机械臂状态读取与动作下发闭环。

适合设备：
- SO101；
- LeRobot 兼容机械臂；
- ROS2；
- 相机；
- 夹爪；
- 数据记录模块。

流程：
1. 连接 LeRobot / SO101 机械臂；
2. 启动 ROS2 驱动节点；
3. 读取当前 /joint_states；
4. 发布 /target_pose 或 /target_joint；
5. 控制节点生成 /action_command；
6. 下发机械臂动作；
7. 读取反馈状态；
8. 判断是否到达目标；
9. 记录图像、状态、动作和结果；
10. 保存为 episode_0001。

输入示例：
target_eef = [0.20, 0.05, 0.12]
输出示例：
/joint_states
/target_pose
/action_command
/gripper_command
/task_status
episode_0001

## 2.7 实验步骤

### 2.7.1 环境准备

1. 创建 ROS2 workspace；
2. 创建 LeRobot demo package；
3. 配置依赖和消息类型；
4. 准备硬件或仿真环境。

### 2.7.2 节点编写

1. 编写 robot_state_node，发布关节状态；
2. 编写 target_publisher，发布目标点；
3. 编写 policy_node，生成简单动作指令；
4. 编写 controller_node，下发动作；
5. 编写 task_status_node，判断是否完成；
6. 编写 episode_recorder，记录图像、状态、动作和任务结果。

### 2.7.3 系统调试

1. 使用 ros2 topic list 查看 Topic；
2. 使用 ros2 topic echo 查看消息内容；
3. 使用 rqt_graph 查看节点连接；
4. 修改目标点，观察系统响应；
5. 修改控制参数，观察闭环稳定性；
6. 保存并检查 episode 数据。

## 2.8 作业交付与失败复盘

### 2.8.1 作业交付

学生需要提交：
- ROS2 package 源码；
- rqt_graph 截图；
- Topic / Service / Action 使用说明；
- 一张 LeRobot 机械臂数据流图；
- 一段硬件或仿真闭环运行视频；
- 一个 episode 数据样例；
- 一段说明：VLA、世界模型、控制器分别位于机器人系统的哪个模块。

### 2.8.2 常见失败 checklist

1. Topic 名称是否一致？
2. 消息类型是否匹配？
3. 节点是否全部启动？
4. Topic 是否真的有数据发布？
5. 控制频率是否太低？
6. 状态更新是否滞后？
7. 动作下发后是否有反馈？
8. 目标点坐标系是否正确？
9. 是否只记录动作，没有记录观测和任务结果？
10. 策略输出动作是否经过安全限制？
11. episode 是否包含图像、状态、动作、时间戳和结果？
12. rqt_graph 中节点连接是否符合预期？

### 2.8.3 复盘问题

- 为什么机器人任务需要持续反馈？
- Topic 和 Service 分别适合什么场景？
- 为什么长任务更适合 Action？
- 为什么 LeRobot 数据不能只记录动作？
- 为什么 VLA 需要接入状态、控制和安全模块？
- 为什么失败样本比成功样本更有迭代价值？
