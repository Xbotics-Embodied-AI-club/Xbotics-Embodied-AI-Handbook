# 第一、二讲配图重做设计

## 1. 目标与范围

依据第一、二讲当前正文，重做第一讲全部 9 张配图，并为第二讲新增 5 张配图，共 14 张。旧图只用于核对已有编号，不作为构图或内容限制；用户提供的三张手眼标定图片只作为视觉风格和 A/B/C 模板类型参考。

最终配图服务于书稿阅读，不是宣传海报。每张图只承担一个教学任务：A 类建立直观概念，B 类解释步骤或闭环，C 类拆解原理与系统架构。

## 2. 统一视觉规范

- 最终格式：PNG，sRGB，1920 × 1080，严格 16:9 横版。
- 背景：白色或极浅蓝灰，不使用复杂场景背景。
- 主色：深蓝标题、亮蓝结构线；黄色用于强调；绿色用于反馈或成功；红色只用于风险、异常或执行端。
- 版式：顶部标题和一句副标题，中部主体图，底部一句话结论条；使用蓝色细边框、圆角分区和充足留白。
- 图形：机器人、本体、相机、计算平台等使用统一的半写实三维教学插图；接口、数据和步骤使用简洁图标与箭头。
- 文字：简体中文无衬线字体；标题醒目，正文在书稿页面宽度下可读；不使用大段正文。
- 禁止：品牌标识、水印、装饰性英文、与正文无关的机器人类型、错误关节结构、伪造公式或无意义字符。
- 参考图只用于学习“白底、深蓝标题、黄色强调线、圆角信息框、三维机器人、底部总结条”的视觉语言，不复制其手眼标定内容。

## 3. A/B/C 模板规则

### A 类：示意图

- 用途：概念导入、组成关系、路线对比、场景对比。
- 一张主视觉，最多 5—7 个短标签；不使用连续步骤编号。
- 读者应在 5 秒内说出图片表达的核心概念。

### B 类：流程图

- 用途：任务流程、运行闭环、数据飞轮、实验步骤。
- 使用 1—7 的明确编号、统一方向箭头和清晰的起点/终点。
- 闭环流程必须画出反馈回路，不能伪装成单向流水线。

### C 类：原理解释图

- 用途：软硬件架构、接口原理、通信机制和公式拆解。
- 允许较多文字，但必须分区；同时给出对象、关系、接口或符号说明。
- 信息分成不超过三层，避免把整页正文搬进图片。

## 4. 第一讲图片设计

第一讲以 A 类和 B 类为主，不引入 C 类高密度原理图。最终文件继续使用现有文件名，以避免破坏书稿链接；生成阶段先保存候选图，验收后再替换正式文件。

### 图 1-1：从“回答问题”到“改变世界”

- 类型：A 类示意图。
- 主标题：`从“回答问题”到“改变世界”`
- 副标题：`数字 AI 输出信息，具身智能通过行动改变环境`
- 主体：左侧为数字世界的输入—模型—输出；右侧为机器人观察环境、决策、行动、反馈的闭环场景。
- 结论：`具身智能的关键不是一次回答，而是持续闭环。`

### 图 1-2：具身智能体由什么组成？

- 类型：A 类示意图。
- 主体：中心为具身智能体，周围准确呈现七个组成部分：`身体`、`感知`、`状态`、`任务`、`策略`、`控制`、`数据`。
- 结论：`模型只是系统的一部分，身体、状态、控制和数据同样决定能力。`

### 图 1-3：机器人怎样完成一个任务？

- 类型：B 类流程图。
- 编号步骤：`1 任务输入` → `2 环境感知` → `3 状态估计` → `4 策略与规划` → `5 控制执行` → `6 结果检查` → `7 数据记录`。
- 从结果检查和数据记录画出返回环境感知/下一次任务的反馈箭头。
- 结论：`任务不是一次推理，而是边做、边看、边修正。`

### 图 1-4：五条技术路线如何协作？

- 类型：A 类示意图。
- 五个并列模块：`传统 Pipeline`、`模仿学习`、`强化学习`、`VLA`、`世界模型`。
- 每个模块只保留一条核心说明，底部用混合系统连接五条路线。
- 结论：`路线不是互相替代，真实系统通常组合使用。`

### 图 1-5：VLA 如何连接视觉、语言与动作？

- 类型：A 类示意图。
- 输入：`视觉`、`语言`、`机器人状态`；中间：`多模态融合`；输出：`动作建议`；输出后继续连接`控制与安全`。
- 结论：`VLA 可以生成动作建议，但不能替代底层控制和安全系统。`

### 图 1-6：世界模型如何在行动前预演？

- 类型：A 类示意图。
- 从当前场景分出三种候选动作：左侧抓取、上方抓取、先移开障碍；每个动作连接一个预测结果，再选择更稳妥的动作。
- 结论：`世界模型的价值是比较行动后果，而不是只生成未来画面。`

### 图 1-7：机器人数据飞轮

- 类型：B 类循环流程图。
- 编号步骤：`1 真实执行` → `2 记录数据` → `3 筛选与标注` → `4 模型训练` → `5 评测` → `6 重新部署` → 返回真实执行。
- 单独标出失败样本进入筛选与标注。
- 结论：`成功数据提供能力，失败数据暴露系统边界。`

### 图 1-8：应用场景难度阶梯

- 类型：A 类示意图。
- 从低到高呈现：`桌面抓取`、`移动操作`、`工业/商超`、`家庭服务`、`人形机器人`。
- 难度轴只表达三项随场景上升：开放性、任务时长、安全要求。
- 结论：`场景越开放，系统集成与失败恢复越重要。`

### 图 1-9：二维目标点控制闭环

- 类型：B 类流程图。
- 编号步骤：`1 输入目标点` → `2 读取当前位置` → `3 计算误差` → `4 限制单步移动` → `5 更新当前位置` → `6 判断是否到达` → `7 记录轨迹`。
- 未到达时从步骤 6 返回步骤 2；到达后输出结果。
- 必须明确标注：`二维闭环示意，不是机械臂仿真`。
- 结论：`最小闭环通过最新反馈持续修正下一步动作。`

## 5. 第二讲图片设计

新增目录：`docs/part1-system-basics/part1_picture/Lecture2_picture/`。图片生成并验收后，在第二讲对应小节插入 Markdown 图片链接和图注。

### 图 2-1：机器人系统由哪些硬件组成？

- 类型：A 类示意图。
- 主体：一台六关节机械臂与工作台，使用短引线标出六类硬件：`本体与机构`、`传感器`、`执行器`、`计算平台`、`通信与同步`、`电源与安全`。
- 结论：`机器人硬件不只是机械结构，还包括计算、通信、供电和安全。`
- 插入位置：2.2.1。

### 图 2-2：机器人软硬件系统架构

- 类型：C 类原理解释图，是第二讲核心大图。
- 上层软件：`任务应用`、`规划与策略`、`感知与状态估计`、`数据与运维`。
- 中层软件：`ROS2 / 消息接口`、`控制与安全`、`硬件抽象`。
- 下层硬件：`计算平台`、`传感器`、`执行器`、`机器人本体`、`通信`、`电源与急停`。
- 左侧绿色箭头表示`状态上行`，右侧蓝色箭头表示`指令下行`。
- 右侧接口契约框：`含义`、`维度与顺序`、`单位与坐标系`、`时间戳与频率`、`范围`、`异常行为`。
- 结论：`硬件提供能力，软件组织能力，接口保证两者正确协作。`
- 插入位置：2.2 开头或 2.2.4 之前。

### 图 2-3：状态上行与指令下行

- 类型：B 类流程图。
- 编号下行链路：`1 任务目标` → `2 规划/策略` → `3 控制与安全` → `4 驱动命令` → `5 执行器与本体`。
- 编号上行链路：`6 传感器反馈` → `7 驱动与状态估计` → 返回控制与策略。
- 额外标出三种时间尺度：电机局部闭环、机器人控制闭环、策略闭环，但不填写未经正文验证的具体频率数字。
- 结论：`高层模型可以慢，底层控制与安全不能停。`
- 插入位置：2.2.5。

### 图 2-4：ROS2 如何连接机器人模块？

- 类型：C 类原理解释图。
- 中央用多个 Node 与 Topic 组成机器人数据流；侧边对比：`Topic：持续数据`、`Service：短请求/响应`、`Action：长任务/反馈/取消`；底部说明`Launch：统一启动和配置节点`。
- 强调：`通信连通不等于系统正确`，还需检查消息类型、单位、频率和时间。
- 结论：`ROS2 负责连接模块，系统设计负责定义数据语义。`
- 插入位置：2.3.7 后。

### 图 2-5：六个 ROS2 节点组成最小闭环

- 类型：B 类流程图。
- 节点编号：`1 target_publisher`、`2 robot_state_node`、`3 policy_node`、`4 controller_node`、`5 task_status_node`、`6 episode_recorder`。
- 明确数据关系：目标与状态共同进入策略；策略动作进入控制器；控制器改变 mock/硬件；新状态返回；状态节点是 `/joint_states` 的唯一发布者；记录器接收核心 Topic。
- 结论：`节点可以替换，但清晰的接口契约必须保持稳定。`
- 插入位置：2.6.1 或 2.6.2。

## 6. 生成与文字准确性策略

- 使用内置图像生成工具逐张生成或重做，不能用同一提示词批量复制构图。
- 每张图均使用用户三张参考图作为风格参考，不把它们作为内容或物体参考。
- 提示词必须逐字提供标题、标签和结论；不允许模型自行增加术语。
- 生成结果若出现错别字、乱码、漏字或箭头关系错误，先进行一次针对性图像编辑；若仍不能保证准确，则保留生成的机器人和视觉素材，以确定性排版方式覆盖准确中文文字。
- 正式替换前保留候选文件，不直接覆盖旧图；只有通过内容和视觉检查的版本才进入正式文件名。
