# 第 2 讲全文写作设计

## 目标

依据现有 `docs/part1-system-basics/02-ros2-architecture.md` 大纲，将第二讲扩写为面向 ROS2 零基础到入门读者的完整课程讲义。正文以原理讲解为主，辅以关键代码片段和可复现的实验步骤，不写成完整 API 手册或逐文件工程教程。

完成后的章节应帮助读者：

1. 理解具身智能为什么必须作为完整机器人系统来设计，而不能只关注单个模型；
2. 说清本体层、控制层、感知层和策略层之间的关系；
3. 理解 ROS2 Node、Topic、Service、Action 和 Launch 的作用与适用场景；
4. 判断 VLM、VLA、ACT、Diffusion Policy、强化学习和世界模型在系统中的位置；
5. 理解从状态读取、动作生成、安全检查、执行反馈到 episode 记录的最小闭环；
6. 按实验步骤完成一个无硬件 mock 闭环，并知道如何替换为 SO101 或兼容机械臂驱动。

## 写作原则

- 保留现有 `2.1—2.9` 章节结构和知识范围，不改变课程大纲的教学顺序。
- 与第一讲保持一致，采用图文简明版讲义风格：场景导入、直观解释、流程图、对比表、关键示例和阶段小结相结合。
- 用连续段落解释“为什么”和“如何协作”，避免把大纲中的短条目简单扩成更长的条目列表。
- 第一次出现的 ROS2 术语使用中文解释，并保留标准英文名称和命令形式。
- 代码以 ROS2 Python `rclpy` 为主，只展示理解数据流所需的关键逻辑；片段应语法合理，接口名称前后一致。
- 不虚构图片素材。现有“待补充”占位改为 Markdown 表格或 fenced text 流程图。
- 不声称片段构成可直接部署到真实机械臂的完整控制工程；涉及硬件执行时明确安全边界和适配要求。

## 叙事主线

全章围绕一个统一任务展开：机械臂接收目标关节位置，持续读取当前关节状态，生成动作指令，经过限幅与状态检查后执行，判断是否到达目标，并将观测、动作、时间戳和任务结果记录为一个 episode。

统一数据流为：

```text
target_publisher
        ↓ /target_joint
policy_node ← /joint_states
        ↓ /action_command
controller_node
        ↓ /task_status
episode_recorder
```

这个案例只承担教学作用。无硬件实验使用 mock 状态和控制节点；有硬件时保留上层接口，替换驱动与控制节点。

## 各节内容设计

### 2.1 从单个模型到机器人系统

从“模型可以预测动作，但为什么机器人仍不能稳定完成任务”切入，解释真实任务还依赖传感器、状态、通信、控制、安全、反馈和记录。明确学习目标，并用全章闭环图建立读者的第一张系统地图。

### 2.2 机器人系统四层结构

分别解释本体层、控制层、感知层和策略层的输入、输出、职责与边界。以统一机械臂任务说明数据如何上行、指令如何下行。用 Markdown 表格替换四层总览占位，并强调四层是理解框架，不是所有工程都必须采用的固定进程划分。

### 2.3 ROS2 基础

先解释 ROS2 是机器人软件的通信与组织框架，再介绍 Node、Topic、Service、Action 和 Launch。对 Topic、Service、Action 使用同一组判断维度：通信模式、持续时间、反馈能力、典型场景和本章示例。补充最基本的 ROS2 工作空间、Package 和常用检查命令，但不展开安装教程。

### 2.4 前沿模型在系统中的位置

将 VLM、检测与分割模型放入感知链路，将 VLA、ACT 和 Diffusion Policy 放入策略链路，说明强化学习可以跨策略层和控制层，世界模型承担预测与规划能力，数据飞轮贯穿全系统。强调“模型输出不等于电机命令”，任何策略都必须经过接口适配、控制与安全约束。

### 2.5 最小机器人闭环

按状态读取、目标输入、动作生成、安全检查、动作执行、任务反馈和 episode 记录依次展开。说明时间戳、状态新鲜度、控制频率和成功判定为什么属于系统正确性的一部分。给出 episode 字段表和一条完整的数据记录示例。

### 2.6 Demo 设计

介绍 `target_publisher`、`policy_node`、`controller_node`、`task_status_node` 和 `episode_recorder` 的职责及 Topic 接口。关键代码片段展示：

- 创建 Node、Publisher、Subscriber 和 Timer；
- 读取 `/joint_states`；
- 根据目标误差生成简单动作；
- 对动作限幅并拒绝过期状态；
- 发布 `/task_status`；
- 记录观测、动作、时间戳和结果；
- 使用简化 Launch 片段组织节点。

代码片段应服务于概念解释，不要求拼接成完整 Package。章节明确指出消息类型可能需要根据实际机械臂驱动调整。

### 2.7 实验步骤

实验以无硬件 mock 闭环为默认路径，包括准备工作空间、启动节点、检查节点和 Topic、发布目标、观察状态变化、检查频率、查看节点图和验证 episode。硬件版作为替换路径，说明接入前必须确认坐标、关节顺序、单位、限位、急停和低速测试。

### 2.8 作业与失败复盘

保留源码、`rqt_graph`、数据流图、运行视频和 episode 样例等交付项。将常见失败整理为“现象—可能原因—检查方法”的排查表，覆盖命名、消息类型、无数据、低频、状态过期、动作越界、超时和记录缺失。保留复盘问题，引导读者解释系统设计，而不是只复述命令。

### 2.9 参考资料

保留 LeRobot 相关资源，并补充 ROS2 官方概念与教程入口。链接使用标准 Markdown 格式，名称说明资料用途。

## 异常与安全设计

正文需要明确处理以下情况：

- Topic 名称或消息类型不一致；
- 节点已启动但没有发布数据；
- 状态为空、维度错误或时间戳过旧；
- 策略输出超出关节、速度或控制周期限制；
- 目标长时间未到达；
- 硬件驱动不可用；
- episode 缺少观测、动作、时间戳或任务结果。

对于真实硬件，章节要求先使用 mock 或仿真验证，再进行低速、限幅、有人监护且急停可用的测试。示例代码不绕过厂商驱动和底层安全控制。

## 验收标准

### 内容验收

- `2.1—2.9` 均形成完整讲解，不再是短句式大纲；
- 统一机械臂案例贯穿架构、ROS2、闭环、Demo 和实验；
- 所有原有知识点均被覆盖；
- “待补充”占位全部被有效内容替换；
- 术语、Topic 名称和数据流前后一致；
- 理论、代码、实验和作业难度符合零基础到入门定位。

### Markdown 验收

- 全文只有一个一级标题；
- 标题层级连续且与现有编号一致；
- fenced code block 成对闭合；
- Markdown 表格列数一致；
- 不引入不存在的本地图片链接；
- 参考链接使用标准 Markdown 语法。

### 实验可理解性验收

读者应能根据正文说明使用以下工具判断闭环是否正常：

- `ros2 node list` 检查节点；
- `ros2 topic list`、`ros2 topic echo` 和 `ros2 topic hz` 检查数据与频率；
- `rqt_graph` 检查节点连接；
- 修改目标并观察系统响应；
- 检查 episode 是否包含完整字段和最终结果。
